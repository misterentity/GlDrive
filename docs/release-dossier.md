# Release dossier and operations journal

Open **Explain release** in the dashboard, enter an exact release name and optionally its announce section, then click **Refresh**. The timeline joins retained matched announcements, recent sightings, wishlist verdicts, race queue/history/outcomes, transfer and download outcomes, nuke observations and new operational verdicts. Matching is case-insensitive and uses complete release names or path segments. Missing evidence means **not observed**, never remote absence. Legacy nuke rows without exactness metadata remain approximate.

The predicted panel evaluates a detached copy of current configuration and bounded wishlist claims. It explains global/site/mapping rules, source and destination roles, quality, prior claims and source policy. It never starts a race, downloads, logs in, polls, fetches metadata, saves configuration or reserves a wishlist claim. Conditional results still require source availability, completion, runtime admission and metadata checks. Missing claims or an oversized policy produce unknown results, rather than an approval based on a truncated gate.

Reads run off the UI thread and accept 1–90 days. One request reserves a share for each telemetry stream within a total budget of 64 MiB decompressed input, 250,000 rows, 640 files and five seconds; unused capacity passes to later streams. Rows over 128 KiB are omitted. Downloads, nukes and transfers are read before announcements and wishlist attempts. Up to 500 timeline events are retained, sharing space among sources so noisy telemetry cannot evict local or journal evidence. Local store and prediction work have separate finite bounds. Coverage reports each stream's rows, observed date range and incomplete evidence. Output is redacted again using the existing log and secret redactors; raw IRC text, config values, credentials and local download paths are not included.

Open **Journal** to refresh operational events and grouped incidents. It records remount causes, mount and IRC transitions, health episodes, configuration save attribution, updates and restart requests, agent run outcomes and warning/error alerts. Unchanged states and repeated warnings are coalesced. Announcements, per-site release verdicts, race admissions and ordinary race completions remain outside this operational history. Incident groups include up to ten retained configuration, remount, update or agent changes from the two hours before the first issue; proximity describes correlation, not a proven cause. New configuration change sets copy at most 32 canonical pointer names and 3.5 KiB from the existing save diff, with actor and audit reference. Values are never copied; omitted pointers are explicitly marked partial. Historical pointer changes remain in existing overrides telemetry. An incomplete previous shutdown is reported as an unknown cause, not proof of a crash.

The journal retains up to 90 days, bounded by 10,000 events and 8 MiB of UTF-8 event data. Oldest entries are evicted first. Producer callbacks enqueue bounded facts without disk or credential work; a background worker redacts and batches persistence. Its pending queue holds at most 512 events and evicts oldest on overload. One fixed staging file and one fixed corrupt backup are each bounded to 8 MiB. Torn or malformed rows are skipped and counted while valid neighbors survive. An unreadable file starts empty; a write failure preserves bounded in-memory history and warns once. If the current secret inventory is unavailable, already-redacted stored evidence is retained internally and rewriting waits for recovery. The UI and MCP responses report persistence health, dropped queue entries and partial read coverage. Operational work never depends on journal persistence.

This first version uses bounded scans instead of a persistent offset index. Historical per-site decisions that were never recorded remain unknown. Runtime dead-race/feasibility caches, unmatched raw IRC messages, broad release action menus and deep links are not evaluated or added. Retention limits can shorten the available history during heavy activity. WPF layout and live event delivery require desktop verification; tests use isolated local fixtures.
