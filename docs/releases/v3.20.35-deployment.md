# GL Drive v3.20.35 production review

## Incident and change

The initial audit covered all three retained daily application logs, from November 24 through November 26 at 16:02 UTC. It counted 39,410 entries, 1,018 warnings, zero errors and zero fatals. The Windows Application log contained no matching warning, error or critical event in that interval. The latest historical crash dump was from November 12 UTC and identified fullscreen teardown, addressed in v3.20.23.

A separate v3.20.34 audit ran from its November 26 startup at 06:14 UTC through 16:03 UTC. It contained 12,349 records, 249 warnings, 2,244 completed FXP transfers and 61 completed races. The 249 warning records have the following breakdown.

| Records | Operational finding |
| ---: | --- |
| 208 | Spread jobs reported destination directory filters. Site policy can prevent the requested transfers. |
| 16 | Polls encountered FTP control sessions closed by the server after a 300-second timeout. |
| 16 | Eight FXP transfers reported missing source files, each logged at two layers. |
| 4 | The source relocation handler followed alternate directories. Three switches on one release went from incoming to recent, back to incoming, then to recent again. |
| 4 | Two download lanes retired and their downloads retried. One pool was exhausted and one source file was missing. Both downloads subsequently completed. |
| 1 | Live search returned partial results during an account-wide FTP login hold. |

In v3.20.34, a positive directory probe could select a second visible directory even if the individual file had already moved out of it. The patch requires evidence of the failed file at the alternate path while the original directory remains visible. It also discards a delayed transfer failure if another probe has already switched paths. A scan with no failed filename and a move where the original directory has disappeared retain their existing recovery behavior.

The broader history also includes four races that reached their inactivity deadline, two missing releases, three partial search-index builds and 19 queue entries removed after cleanup exhausted its attempts. The inactivity record alone cannot establish the upstream cause. The earlier entries span several deployed versions. All four distinct downloads with retry warnings across the retained logs subsequently completed.

## Validation and release

The candidate passed locked Release builds of the solution and native harness with zero warnings or errors. All 6,305 regression tests passed with zero skips (6,141 application, 140 Core and 24 MCP). Three new loopback cases cover a missing payload, a present payload inside a nested directory and a late failure from the prior path. The transitive package audit reported no known vulnerable packages. All 64 candidate WPF screenshot views passed the manifest and pixel checks.

Two pre-publication native fixture runs exposed reflective calls using the previous parameter counts. The fixture now passes the observed payload and failed path for transfer-triggered recovery, and explicitly requests a directory-only probe for the fallback scenario. Both failures occurred in the local test harness.

## Outstanding operating conditions

Six configured announce-channel mappings were unavailable and five previously frozen decisions awaited review before rollout. Channel intent and access require the site operator. Remote filters, session timeouts and files in transit can still interrupt transfers. A server that cannot substantiate a file size may delay a relocation while both directories exist. Read-only production checks cover this Windows installation and its configured connections.

## Production observation

From 16:28:02 through 16:33:19 UTC, all eight health samples passed with one stable process. The heartbeat, configured connections and authenticated automation catalog remained available. The final read-only smoke again passed all four FTP roots and three enabled IRC connections. Log retention and coverage checks passed, with zero error or fatal records and zero matching Windows events.

The strict monitor returned a failed overall result because 18 spread jobs failed during the window. Every warning reported a destination directory filter. The FTP trace includes explicit server responses refusing directory creation. One race completed during the window. Connectivity and process checks passed throughout, but the affected jobs require a destination that permits those uploads. This observation did not establish a new production instance of the overlapping-directory move. The loopback and native fixtures provide the direct validation for that case.

Inno Setup warned that elevated installation writes per-user registry entries. Installation under an alternate administrator remains unverified. Detailed test, deployment and monitoring evidence is in the local ignored directory `.release-tools/review-20261126/`.
