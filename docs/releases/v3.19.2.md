# GL Drive v3.19.2

This corrective release addresses the one code fault found in the v3.19.1 production logs and a recurring CI failure.

- **IRC notices and prose are no longer accepted as release names.** A broad custom announce rule on zephyr's `#ent` turned the sitebot notice `AUTONUKE: TV/Nocturne.2026.S01E01.2160p.WEB.H265-CAKES created by altruist is still empty after 1 hour` into a "new release" in section `AUTONUKE` named `TV/Nocturne...`, a path. A `#SYN-SPAM` plot synopsis had earlier become release `Frankenstein,`. Each false match was recorded as sitebot activity and as a section-learning signal for the AI agent, and was offered to auto-race. The shared plausibility check now requires a release to be a single directory name ending in its group tag: no path separator or filename-illegal character, and a final letter, digit, `)` or `]`. Checked against 2,350 distinct real release names from three days of logs and race history, only the two false matches are rejected. The same check guards race pulls, wanted acquisition and the wanted index sweep.
- **Reliable hook test teardown.** The hook timeout test kills a real PowerShell process tree whose working directory is the test's temporary folder. On the CI runner that folder could stay in use for a moment after both hook processes had reported exit, so deleting it failed the run (three CI runs, including two for this release). Teardown now retries the delete for up to ten seconds. The hook runner itself is unchanged: the test's assertions on the timeout outcome, bounded output and the killed child tree all passed in every failing run.

The [deployment report](https://github.com/misterentity/GlDrive/blob/master/docs/releases/v3.19.2-deployment.md) records the log audit, tests, deployment and remaining risks.
