# GL Drive v3.16.0

Feature-gap roadmap, Phase C batch 1 (C1–C5). Codex implemented it, and three independent reviewers plus Claude reviewed it. This release includes v3.15.1 and v3.15.2. Full suite: 4,560 tests (4,487 app, 53 core, 20 MCP), 0 failures.

Two changes are on by default: the wishlist source floor and passive nuke flags on things you own. Everything else is opt-in.

**Review.** The reviewers found 19 issues; all were fixed before release. One affected every user: the new hook settings made the default queue size `64` a redaction token, so every "64" (x264, H264) would have been rewritten out of the nightly agent's and AI Setup's requests. Hooks are now masked in config views but never treated as credentials. Other fixes:
- A malformed hooks block disables only hooks, instead of loading the whole config as defaults.
- An invalid hook no longer blocks unrelated config edits.
- OneDrive-hosted scripts work.
- Hook output is logged with redaction.
- The CAM floor applies to movies only.
- Watchlist imports don't duplicate your manual items.
- A pending SFV repair still fetches other missing files.

## Wishlist source floor and movie release dates

- **CAM, TS and TC releases are no longer grabbed for wishlist movies by default** (`downloads.blockLowQualityWishlistSources`). Common concatenated tags are included. The item stays open, so a proper copy is still picked up later.
  - Unknown sources stay eligible.
  - An item can allow these sources explicitly: the Wishlist checkbox cycles default / allow / block. A custom profile that allows them keeps its choice.
  - TV episode titles, audio/codec tokens and screeners are outside this floor.
  - Checked against 30 days of real announces: of 27,306 distinct releases, no TV or movie release was flagged. The 35 matches were XXX or software titles with "Cam" or "TS" in the name, which never reach the wishlist.
- **Release dates:** select a movie in Wishlist or Upcoming and use **Release dates** (or MCP `wishlist.calendar_refresh`) to see its theatrical, digital and physical dates from TMDB.
  - Lookups happen only when you ask; there's no background timer.
  - Failed or keyless lookups retain saved dates and report unavailable. Successful lookups with no regional dates show unknown; neither blocks a grab.
- The nightly agent's wishlist evidence no longer invents "60 days since a match". Known theatrical windows, future digital dates and title-matched low-source sightings explain why a movie has no qualifying matches yet.

## Nuke watch on things you own (passive, on)

- `nukeWatch.enabled` flags a recently completed download or library import if it's nuked within `watchDays` (default 7).
  - It uses only PreDB results and trusted sitebot facts GlDrive already receives: no new polling, provider requests or FTP commands.
- Queueing a PROPER or same-group REPACK automatically (`autoQueueFixes`) is **off**. When on, it fires only for a recognised quality defect, such as corrupt video, bad IVTC or audio sync, and only for an exact title match. A failed or cancelled fix isn't retried on repeat observations.

## Post-event scripts and webhooks (opt-in)

- Run your own `.exe` or `.ps1` on `download.complete`, `download.failed`, `race.finished`, `wishlist.grab` or `nuke` events.
  - Values arrive as `GLDRIVE_*` environment variables and as JSON on stdin, never in the command line.
  - Commands run one at a time in the background, with a timeout (default 30 s) that kills the whole process tree, and capped captured output.
  - A hook never delays a transfer, race or download completion.
- **Hooks can only be created by editing `appsettings.json` and restarting.** MCP, the nightly agent, timed changes and history restores can't create, enable, change or run them.
- Invalid hooks leave ordinary configuration and lease reverts working. Malformed hook blocks are preserved for correction. Cloud-file scripts are supported; redirects and content-folder paths are refused with reasons. Plain-text output is bounded and secret-redacted in logs.
- HTTPS webhooks use the v3.15 alert router's bounded delivery and redactors (`kind: "webhook"` targets, off by default).

## Self-healing SFV (opt-in)

- `downloads.sfvRepairEnabled` (off) re-fetches files that fail CRC, at most 2 attempts per file per download, while fetching any other missing/incomplete payloads. The count survives restarts and manual Retry.
- A bad file is quarantined inside the download's own staging folder. Files that passed and manifests are never deleted.
- Missing files, read failures and malformed SFVs keep their existing verdicts.
- A folder with a confirmed CRC failure is held back from watch-folder extraction until it verifies.

## Plex Watchlist as the wishlist inbox (opt-in)

- `plex.watchlistSyncEnabled` (off; every 30 minutes when on) imports your Plex Watchlist into the wishlist with its IMDb, TMDB and TVDB ids and your default quality.
- It is read-only towards Plex: HTTPS GET only, and it never removes anything locally when an item leaves the Watchlist.
- Items are marked done only on proof of ownership: completed downloads or the library index, with matching identity and quality.
- Existing manual title-only requests suppress duplicate imports. Removing an import locally retains it as inactive so later syncs cannot re-add it.
