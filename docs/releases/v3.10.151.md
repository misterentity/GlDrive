## Root causes and fixes

### 1. Directory cache could store a listing older than the latest change (user-visible)

`ListDirectoryCached` and the stale-while-revalidate background refresh stored
whatever their LIST returned. A LIST that started before a DELE, RNTO or buffered
STOR could finish **after** that operation invalidated the directory. The old
listing was then cached for the full TTL, which brought deleted files back and
kept pre-upload sizes and pre-rename names. Windows probes newly written files in
parallel (Defender/indexer), so the window opens on ordinary use.

The harness log proved the interleaving: a LIST started at 21.349 during a STOR
and completed at 21.416, after the upload's invalidation. The release smoke failed
`File.Exists` after `File.Delete` in 1 of 5 runs before the fix.

**Fix:** `DirectoryCache` stamps every `Invalidate`, `InvalidateParent` and `Clear`
with a monotonically increasing epoch. Callers take `BeginFetch()` before
listing, and `Set(path, items, epoch)` refuses to store a listing for a directory
invalidated after that epoch. The check and the store share `_setLock` with
invalidation. Tracking is capped at 4,096 directories and collapses to one global
stamp when the cap is reached, which can only skip caching for listings still in
flight. Both writers (`GlDriveFileSystem`, `MountService` background refresh)
use the guarded overload.

### 2. Malformed AI proposals were audited as `frozen`

On 2026-10-05 the free `openai/gpt-oss-120b` model returned an all-empty change.
An empty target is the JSON Pointer root, which is an ancestor of every freeze, so
`ChangeApplier` recorded `RejectionReason: "frozen"` and blamed the user's freeze
list for malformed output. Changes with a missing or blank category or target are
now rejected as `malformed` before the freeze check, and the Suggestions list hides
them as it already hid `frozen` rows. No mutation was possible in either version.

### 3. Blank AI brief

`AgentRunResult.BriefMarkdown` defaults to `""`, so the `?? "# (no brief)"` fallback
never ran. The 2026-10-08 brief was an empty file: 121 output tokens and no summary.
`AgentRunner.ComposeBrief` now writes an explicit "model returned no brief" heading.

### Harness

`tools/ReleaseCheck` now writes a Debug Serilog file beside its fixture state, so a
failed step shows what the app did, not only which check failed.
