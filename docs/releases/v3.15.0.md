# GL Drive v3.15.0

Feature-gap roadmap, Phase B batch 3, which completes Phase B. Codex implemented it and Claude reviewed it. Full suite: 4,088 tests (4,015 app, 53 core, 20 MCP), 0 failures.

Everything in this release is passive or opt-in except two nightly-agent checks, which can only reject a proposal and leave your settings unchanged.

## Alert router (opt-in features)

- Every tray notice now goes through one router. With the defaults, notices look and behave exactly as before.
- Turn on `alerts.enabled` for a persistent alert history with acknowledge and snooze. Optional extras:
  - coalescing of repeats (`coalesce`), so a burst of "Race Complete" becomes one summary;
  - mutes by kind or server;
  - quiet hours;
  - a morning digest built locally, with no AI involved.
- **Phone push and email** (`alerts.targets`): ntfy, Pushover, Telegram, Discord webhook, SMTP (TLS required) and an external dead-man heartbeat URL.
  - Every target starts disabled.
  - Messages carry only the severity, the kind and the server's display name. Release names are opt-in per target.
  - Hosts, IPs, account names, channel names and chat never leave the PC, and every message also passes the existing redactors.
  - Target credentials are kept in Windows Credential Manager.
  - Sending runs in the background with bounded retries, so a dead webhook can't slow the app.

## Config history, timed changes and experiments

- Every config save now records who made it: Settings, tray, MCP, an agent run, a restore or a migration. The override telemetry carries that actor, with secrets masked.
- **Version history** (`configHistory.enabled`, off by default; keeps 512 versions) stores numbered, secret-masked versions you can restore through the normal save path. A restore keeps your current control-API token.
- **Timed changes** (`config_lease`): "set this for 2 hours" or "until 07:00". The change reverts even across a restart, but only if you haven't changed that setting again since. The tray's "Pause 24h" now survives a restart.
- **Experiments** (`config_experiment`): a labelled change with a hypothesis, before/after race counts from local telemetry, and an explicit Keep or Revert.

## The AI agent is accountable for its changes

- A proposal can declare what it should change (race completion rate, delivered races per hour or queue wait) and over what window. The next run scores it as effective, no effect or regressed, against the same hours one week earlier. It reports "unscored" instead of guessing when there isn't enough data.
- **On by default:** proposals that can't have any effect are rejected before they apply, for example more slots than the transfer gate allows.
- **On by default:** rule, exclusion and mapping changes must pass a replay of your last 7–30 days of announces, races and wishlist decisions. The replay uses the same announce matcher as live racing. A rejected proposal leaves your settings as they are.
- Automatic revert of a regressed change is available (`agent.autoRevertRegressions`) but **off**. When on, it goes through the same validators and never touches frozen settings.
- Your own manual corrections of agent changes count as negative feedback for it.
- MCP: `agent.simulate`, `agent.outcomes`.

## Library import (opt-in, starts in dry-run)

- `library.enabled` (off) imports a completed single-video movie or episode from a staging folder outside your Plex library into a Plex-style path, keeping its resolution. Turning it on always starts in dry-run, and real moves need a separate, explicit save.
- Imports are built never to lose data:
  - A destination file is never overwritten or deleted.
  - A move on the same drive is a no-replace rename.
  - A move across drives copies, flushes and verifies size, plus SHA-256 up to 64 MiB, before removing the source.
  - Anything uncertain (active downloads, reparse points, overlapping roots, ambiguous names) refuses that import and leaves the source in place.
- An optional Plex scan targets only the imported folder.
- A read-only library index (Plex metadata plus a disk scan) shows what you already own and at what quality. It never changes the wishlist or downloads.

## Review fixes

Four independent reviewers checked this batch before release and found 28 issues. 27 are fixed, and one is partly mitigated and deferred. The live IRC announce path was moved into a shared matcher for the agent's replay. A replay of six days of real channel logs gave the same 6,591 announce matches as the previous code, with none lost and none gained.

Fixes that affect default behaviour:

- **The agent's replay check no longer blocks legitimate fixes.**
  - New announce matches are verified against the release evidence of every site, with sections compared case-insensitively. A rule passes with at least 3 verified gains, as long as unverified ones don't outnumber them.
  - Only releases that actually raced count as losses.
  - Section-mapping changes are judged with the runtime fallback included, so narrowing a default trigger can pass.
  - Before, almost every announce-rule or mapping proposal was rejected.
- **A model formatting slip no longer voids the night.** A malformed `expected_effect` now counts as "undeclared"; before, it discarded every change and suggestion in that response.
- **Scheduled agent changes are attributed to the agent.** An attribution scope leaked into the nightly timer, so the agent's own commits could be recorded as your edits.
- **The agent's track record in its prompt is bounded.** It holds the newest 50 scored agent changes from the last 30 days, each identified by run, target and metric. Before, it grew without limit and lost its newest rows first when trimmed.
- **Your explicit approvals are advisory checks.** "Apply anyway" and MCP apply record the replay result instead of being rejected by it, and the replay no longer runs on the UI thread.
- **Approving a follow-up agent suggestion no longer counts against the agent.**
- **A timed change ends as soon as you change that setting.** Before, changing a setting away and back to the leased value let the old lease revert it later. A timed change that fails to apply is no longer retried silently a minute later.
- **Readers no longer drop live log writes.** Telemetry and IRC log readers now share write access, and writers retry briefly on contention instead of dropping lines.
- The "GlDrive restarted" warning has its warning icon back.

Fixes to opt-in features:

- **Alerts:** tray notices are decided immediately, and only outbound delivery is queued, one bounded queue per target. Retries respect `Retry-After` and give permanent errors up. Snoozing one entry snoozes only that entry. Partial updates keep the other fields. Dated release names survive address redaction.
- **Library:** cross-drive copies go to a hidden temp file, which is verified and then renamed into place without replacing anything. Dated episodes, samples and extras stay staged. Plex scans require a matching media type. Settings are re-checked before publishing and before the source is removed. Library enablement and dry-run can't be time-limited.
- Experiment metrics now read telemetry files by local date.

Deferred: config history still rewrites its whole store on each save while enabled. Saves with an empty diff are now skipped, and incremental storage is planned. History remains off by default.
