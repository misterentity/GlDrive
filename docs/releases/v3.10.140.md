# v3.10.140 — enforce AI change targets and record actual configuration changes

## Log review and root causes

The September 30 review began with v3.10.139 installed and running from
`C:\Program Files\GlDrive`, matching release commit
`ceaf6a29208923a1ff120f96b8fbfff087bb5ca4`. The retained September 28–30 logs,
snapshotted through 17:05:03 UTC, contained 19,645 records, 244 warnings,
and **zero Error or Fatal records**. All warning records were classified.
Windows Application Error/Critical events attributable to GlDrive were also
absent from September 28 through the inspection.

The current process started September 29 at 23:18:16 PDT. Its reviewed window
contained 2,007 successful file transfers and 94 completed races, with no
failed races or transfer deadlines. Across the retained logs, all 11 reported
FXP file failures subsequently completed, all four source-relocation events
ended in completed races, and six PreDB timeouts were followed by new release
events. Those recovered incidents were not treated as outstanding defects.

The current session's 53 warnings consisted of 28 parked-download notices for
the unavailable T: drive, one extraction-space notice for D:, 14 SYN connection
notices, and ten notices for recovered source relocations (eight paired FTP
warnings and two relocation notices).

Review of v3.10.139's AI mutation contract identified additional correctness
gaps. These are reproduced configuration cases, not newly observed crashes:

- Server targets were canonicalized to ID-based validator aliases, then
  resolved directly against index-based configuration JSON. This bypassed
  stale `before` checks for server settings.
- Applied audit rows retained model-requested values even when validators
  clamped the result. Missing `before` values also lost the actual prior state.
- Freezes and proposals could use different spellings for the same path.
  Shared server-path parsing accepted malformed missing separators.
- The concurrent-race setting inherited the pool-size minimum of two, even
  though one is a valid and sometimes necessary concurrency setting.
- Request-filler validation expected leading slashes that the shared parser
  removed. Valid subfield proposals were rejected.
- A null skiplist append could insert a null rule instead of being rejected.
- UI undo paths marked changes undone even when validation rejected the
  inverse operation. Rejected undo now leaves the audit state intact and
  reports the reason instead of displaying a false success.

Today's scheduled AI run completed successfully at 04:00:21 PDT with no live
changes: two live proposals and one suggestion were rejected as frozen or below
the confidence threshold. No extra paid AI run or production configuration change
was triggered to exercise this release.

## Remaining external conditions and limits

- **SYN:** one five-second TCP probe timed out before authentication. The
  endpoint/network operator must restore reachability or correct its routing
  or configured endpoint. The probe cannot identify the failed network hop.
  The two other configured servers were connected at baseline.
- **T: download destination:** the remembered Windows mapping is unavailable
  (`ERROR_CONNECTION_UNAVAIL`, 1201), and reading its share root returned
  `ERROR_LOGON_FAILURE` (1326). Restoring valid Windows SMB access and the
  mapping is required. Downloads remain parked without consuming retries.
- **D: extraction capacity:** 16.056 GiB was available; the waiting archive
  needs at least 22.565 GiB under the application's preflight rule, a shortfall
  of **6.509 GiB**. Expanded content and concurrent writers may need more.
  Extraction remains parked. No user files were deleted or moved to free space.
- Loopback native verification does not replace a remote BNC/CPSV soak.
  A short production observation cannot establish multi-day reliability or
  guarantee the content of the next scheduled model response.
- Inno Setup emitted its existing warning about administrator installation
  combined with per-user HKCU settings. Packaging succeeded; installation under
  a different administrator account may affect which user's settings are set.
- Existing inaccurate historical audit rows are preserved; this release
  corrects future accepted changes. No data migration is required. The
  preceding signed release, v3.10.139, remains the rollback artifact.
- Undo continues to honor validator invariants. Historical inaccurate rows,
  append operations without a reversible target, or trigger changes protected
  as user edits may be rejected; the UI must report that failure and retain
  the original audit row rather than claim it was reverted.

Local evidence is retained under `.release-tools/verification-20260930/`.
Production tokens, credentials, remote paths, and private signing keys are
