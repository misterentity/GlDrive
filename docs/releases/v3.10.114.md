Log sweep of 2026-09-08 → 2026-09-10 (three days, ~134k lines, spanning 3.10.108 → 3.10.113). **0 ERR, 0 FTL on every day.** The v3.10.113 hotfix is confirmed in production. No code-caused error was found; this release closes two diagnostic gaps the sweep ran into and records three server-side conditions that need Dave.

That is the second change below.

## Changes

- **A failed direct CPSV-PASV re-probe is now logged at Information.** Relay mode remembers a route whose direct probe failed and re-probes it every 6 h. A failed re-probe poisons both connections (two logins on a 4-login account), exactly like the first failure, but `RecordDirectFailure` reported it as a bare `false` and the caller logged at Debug. On the Information sink the only trace was `FXP complete` followed by two poisoned-discards with no explaining line (2026-09-10 14:01:09, the 6 h expiry of the 07:53:57 switch). The method now returns `DirectProbeFailure { NotCached, First, Reprobe }` and both `First` and `Reprobe` log at Information. Behaviour of the route memory (TTL, re-arm, directionality, success clears) is unchanged. A unit test had locked in the old contract by asserting `false` at +7 h; it was replaced.
- **Pool log lines name their server.** `Pool: quarantined connection`, `Pool: new connection failed` and the two `Pool: server entering … cooldown/backoff` lines now read `Pool[host]: …`. Every server runs at least two pools (main + spread) and the pool never said which one it was; the five-minute superbnc stall below had to be tied to superbnc by the borrow-timeout line thirty seconds later.

## Server-side conditions found by the sweep (not code; need Dave)

- **superbnc control channel stalled for 5 min on 2026-09-10 08:38:35 → 08:43:36.** A borrow probe (NOOP) on a pooled connection got no reply, the GnuTLS recv never drained (`recv did not drain within 20s — leaking session`, by design), and every new connection for five minutes timed out with `The operation has timed out` (TCP accepted, no FTP reply). zephyr answered normally throughout, so the fault is on superbnc's side. Cost: 10 `FXP borrow timeout` warnings on one race (The.Perfect.Lie.S01E05), which then completed. First occurrence of this shape in the three days; the leaked session is the only one (`drain=0` on 09-08 and 09-09).
- **zephyr's `425 Can't build data connection: Connection refused` ceiling persists** (recorded in the .112 doc): every hourly search-index build since v3.10.112 reports 16–22 failed listings, first path changing each hour, and indexes ~7,100 entries vs ~2,000 before .112 (the first 425 used to abort the build). The same 425 hits ~1 % of Relay `STOR`s to zephyr and one `NewReleaseMonitor` poll per day. Site-side data-connection issue on zephyr.
- **SYN's FTP host is still down** (55 remount warnings in three days at the 21 s OS connect ceiling; open since 2026-08-13).
- PreDB HTTP fetch timed out twice at 00:16 on 09-10 (15 s `HttpClient` timeout), backed off 30 s → 60 s, recovered. External.
