## Dated section folders per site

Some sites file a section under a per-day folder (`/FLAC/1109/Release`), others
keep the same section flat (`/incoming/mp3/Release`). The race engine guessed this
from the folder name — only `mp3` and `0day` were dated — so a site that dates a
differently named section could only be routed into its read-only section root.

- A section path may now carry `{MMDD}` (e.g. `/FLAC/{MMDD}`). Races, the source
  probe, wishlist announce resolution, download relocation and the health check
  expand it to today's UTC folder; the literal token never reaches the server.
- Source-path guessing still refuses dated trees and waits for a discovered path.
- Untokened paths keep the existing `mp3`/`0day` behaviour.

The November 9 section audit (live listings of every site) also corrected site
configuration outside this release: sitec TV and x264 routes pointed at folders that
do not exist (`/tv-hd`, `/x264-hd`; real: `/tv-x264`, `/x264`), sited's 1080p TV
pointed at a missing `/TV-1080`, and sitea had no sections at all.
