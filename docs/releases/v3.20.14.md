## Preserve extraction capacity across fallback

- Download extraction now keeps the known unpacked size when SharpCompress falls
  back to UnRAR/7-Zip. Previously the fallback replaced that reservation with the
  compressed archive size, allowing extraction and later retries before enough
  disk space was available.
- A capacity shortage parks the download before invoking the external tool.
  Disk-full failures retain the larger known requirement for recovery, preserve
  the archive, and release the reservation.
- Regression coverage exercises both capacity loss before fallback and a disk-full
  failure after fallback starts. If the managed reader cannot determine the
  unpacked size, the existing archive-size estimate still applies.

The log review found no current application error in the retained production
window. This fix addresses a regression reproduced during the review. The known
remote FTP outage and intermittent local storage delays remain environmental
limitations. Detailed validation and deployment evidence will be recorded in
`docs/releases/v3.20.14-deployment.md`.
