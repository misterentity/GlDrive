# GlDrive v3.10.104 release record

## Findings and root causes

- Retained application logs for September 2–4 contained no `ERR` or `FTL` records. Elevated
  warnings were attributable to external services: SYN's FTP endpoint remained unreachable,
  PreDB requests had bounded timeouts and recovery, and transient FXP refusals followed the
  existing retry path.
- The September 3 production process stopped at 09:53 without an Application Error, .NET Runtime,
  WER, or power event and was not restarted by its watchdog. A second launch was writing and
  claiming the primary process's `.running` marker before acquiring the single-instance mutex;
  its `OnExit` then deleted that shared marker. The primary watchdog consequently interpreted the
  primary's later death as a clean exit.
- The v3.10.102 production update left 1,156 `.old` rollback files. The SYSTEM updater created
  them under Program Files, but cleanup ran later in the normal user's process and silently lacked
  permission to delete them.
- The first privileged cleanup in v3.10.103 removed 1,122 files and left 34 runtime files. The
  cleanup task had raced the exiting updater, which still had those assemblies mapped. A second
  run after updater exit removed all 34.

## Changes

- Acquire the per-user single-instance mutex in `Program.Main`, before watchdog creation, WPF
  construction, restart registration, or lifecycle-marker access.
- Hand the pre-acquired guard to `App`; remove the owned crash marker while the guard remains held
  during shutdown.
- Allow the rolling Serilog file sink and early duplicate-instance audit append to share the log
  file safely.
- Register a separate no-trigger, fixed-action SYSTEM task for rollback cleanup. Its only action is
  the installed executable with `--cleanup-old-updates`; callers cannot provide a path or alter the
  task action. Uninstall removes both update tasks.
- Pin rollback cleanup to `AppContext.BaseDirectory`, wait 10 seconds for the updater's rollback
  window to close, and retry temporarily locked files for up to 30 seconds.
- Add regression coverage for startup/shutdown ordering, mutex exclusion, log sharing, screenshot
  isolation, fixed task registration, fixed-root cleanup, and a real Windows locked-file retry.

## Remaining risks

- SYN's FTP endpoint is externally unreachable. GlDrive remains healthy and keeps it on the
  bounded remount schedule; resolution requires the remote service/network owner.
- The Inno compiler still reports its existing warning that an admin-mode installer writes an
  optional HKCU autostart value. This is harmless for the normal same-user elevation flow but can
  target the elevating account during an over-the-shoulder administrator install.
- Task Scheduler reports `0xFFFFFFFF` for the update-installer task because the updater deliberately
  terminates its own process after replacing its loaded files. Completion is instead verified by
  the authenticated hand-off consumption, watchdog completion signal, installed version, and
  application confirmation log; the cleanup task itself returns 0.
