# v3.10.154 — verify source relocation over native FTPS

## Log review and root causes

The October 12 audit covered all retained October 10–12 application logs,
telemetry since installed v3.10.153 started at **2026-10-10 03:16:49 UTC**, the
watchdog/heartbeat, and Windows Application/System errors. At 17:02 UTC it found
**13,375 log records, 177 warnings, zero Error/Fatal records, and no GL Drive or
WinFsp Windows faults**. The retained text logs start at October 10 07:00 UTC;
earlier deployment activity is available in telemetry, not retained text logs.
All 28 retained crashdumps predate this release; the newest is from July 20.
There are no retained disk-full errors, and D: currently has 273.76 GiB free.

| Finding | Root cause and outcome |
|---|---|
| 116 destination-drive warnings | T: is absent. Two queued downloads are safely parked; the application preserves their destination and retries when the drive returns. |
| 54 SYN FTP timeout warnings | The remote FTP endpoint remains unreachable. Bounded remount retries continue; the other two servers stay connected. |
| Four SYN IRC connection failures | Temporary socket connection failures; IRC reconnects at October 11 07:24:56 UTC. |
| One FXP reset, logged as two warning records | The peer reset a data connection. The same file succeeds on retry 348 seconds later and its race completes. |
| One AI-provider HTTP 429 | Upstream rate limiting. The scheduled run retries after two minutes and finishes successfully at October 12 11:04:38 UTC. |

Telemetry since deployment records **207 completed races and 3,459 successful
transfers (about 413 GB)** with no parse errors. All three aborted transfer attempts
subsequently succeeded in their original race: the remote reset above and two
source-550 attempts before the retained text-log window. Both 550 retries succeeded
from changed source paths, establishing that the v3.10.153 relocation recovery
worked in production. The missing text logs prevent measuring probe latency.

No new application defect was established. This release closes a validation gap:
the previous relocation change lacked a native FTPS regression for a move while
the old directory still exists. Application behavior is unchanged apart from the
release version. Existing recovery mechanisms handled the transient failures;
the absent drive and unreachable FTP service remain external operator items.
Post-deployment checks confirm no T: volume, partition or SMB mapping exists in
the current session, so there is no existing mapping to reconnect. A single
independent TCP connection attempt to SYN's configured FTP endpoint also times
out before authentication. The precise remote/network cause remains unconfirmed;
changing credentials, TLS settings or retry logic would not address that result.

## Changes

- Extend the disposable loopback FTPS release harness to exercise source relocation
  after a real RETR 550 and after an empty LIST, while the original directory
  remains present. Verify watch-path priority over a populated decoy, rescanning,
  resolution of the new RETR path from pre-move metadata, and payload integrity.
- Exercise negative directory probes and fallback using a reusable native session.
  Add `--relocation-only` for focused regression runs.
- These tests seed the source role/path and exercise the real scanner, migration
  handler and downloads; they do not run the complete race scheduler or a
  server-to-server FXP race.
- Update the version and release documentation.

## Remaining risks

- T: must be restored, or the operator must deliberately choose another destination
  for the two parked downloads. No destination was silently redirected.
- SYN FTP remains unavailable; restoring its service/network access requires the
  remote operator. IRC recovery does not establish FTP availability.
- D: has 273.76 GiB free (3.67% of its capacity); continued downloads still need
  capacity monitoring, although the prior immediate disk-full concern is absent.
- Loopback FTPS regression does not reproduce every remote glftpd/BNC CPSV behavior.
  Historical production transfer success is not a checksum audit of remote files.
- Live transfers are verified on v3.10.154, but no source relocation occurred in
  the observation window; exact production relocation-probe latency remains unmeasured.
- Production monitoring covers a bounded observation window, not an extended soak.
- The installer has a previously documented Inno Setup `UsedUserAreasWarning`.
- Automatic approval review rejected temporary fixture deletion with "blocked by
  policy". Its process is stopped; the fixture remains at
