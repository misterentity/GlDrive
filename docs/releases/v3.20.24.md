# GL Drive v3.20.24

This follow-up fixes premature race admission during startup and source-pool
recovery. Production verification of v3.20.23 exposed queued races starting while
their announced source was still waiting for a local login budget, resulting in
repeated inconclusive source probes.

- Keep announced-source work queued while an intended source pool is still being
  initialized or recovered, including the period before its factory is registered.
- Recognize factory-owned login holds. Expiry permits another connection attempt;
  it does not by itself make a missing source pool ready for a race.
- Resume admission when a source pool registers successfully, or let an already
  usable announced alternative source proceed.
- Preserve request identity, retry budgets, intentional disconnect/configuration
  behavior, cleanup work, and destination-only admission rules.

This release includes the fullscreen ownership, source-search cancellation and
clean relay-refusal fixes from [v3.20.23](v3.20.23.md). Remote directory policies,
server outages, content movement and genuinely stalled commands remain possible.
Login limits and conservative protocol quarantine remain enforced.

[The deployment report](v3.20.24-deployment.md) documents the original log review, both release stages,
validation results, production observations and remaining risks.
