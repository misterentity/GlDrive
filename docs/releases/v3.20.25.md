# GL Drive v3.20.25

This release prevents date containers from becoming automatic release jobs and
keeps request-fill permissions restricted to the intended destination.

- Release polling ignores valid four-digit `MMDD` date containers. It continues
  to accept ordinary short directory names and names containing dates. This avoids
  false notifications, wishlist candidates and automatic races of entire buckets.
- Ordinary queued races retain their original routing and policy when a request
  for the same release arrives. The request waits for admission without spending
  its transfer-failure retry budget.
- Duplicate ordinary announces cannot add destinations to a request fill. Request
  policy exemptions remain restricted to the intended request destination.
- Request directory creation requires the existing request parent to remain
  accessible. A removed parent is never recreated by the general directory walker.

Date-container suppression does not introduce recursive polling of archives.
Bare directory names that are valid `MMDD` dates are excluded from polling in
every category; intentional transfers can still be started manually.
Remote directory permissions, moved or removed content and remote timeouts remain
external operational limits. This release does not change server permissions,
account login limits or configured routing.

The [deployment report](v3.20.25-deployment.md) records the bounded log review, regression and native smoke
results, signed release identity, production observations and remaining risks.
