# GL Drive v3.19.0

Feature-gap roadmap, Phase D batch 2 (D5, D3, D6). Codex implemented it, and three independent reviewers plus Claude reviewed it. This release includes v3.18.1. Full suite: 5,416 tests (5,328 app, 64 core, 24 MCP), 0 failures.

## Data stewardship (D5)

- **Verified protected copies of secrets.** On start, GlDrive writes a DPAPI-protected copy of the control-API token and the configured IRC channel keys, then reads it back to verify it. The copy is recovery evidence only: the originals stay where they are, so older builds and MCP bridges keep working. Removing the originals is deferred until a safe downgrade path exists.
- **FiSH key store hardening:**
  - Each key entry is checked on its own; a bad entry is skipped with a warning and never discards the rest.
  - `/key` and MCP `irc_key_set` refuse an empty key or target.
  - An unreadable key file is copied to quarantine, verified, and moved aside. Keys learned since then are promoted, and the degraded state appears in the Problems panel.
  - Lookups return copies, so callers can't mutate stored keys.
- **Encrypted portable backup** (Recovery Center): Argon2id with AES-256-GCM, a versioned envelope, and a passphrase you enter twice that is never stored.
  - Each export is reopened and authenticated from disk before it's published.
  - Import runs offline, re-reads every entry first, and keeps your current secrets unless you tick replace.
- **Recovery Center** (Settings → Diagnostics): an inventory showing whether each secret is present and how old it is, never its value.

## Least-privilege automation (D3)

- **Your existing control-API token works exactly as before**, with full access, no approval prompts and the same responses. Restricting it is opt-in (`requireLegacyApproval`).
- **Scoped tokens** (opt-in): named clients limited to read-only access, chosen tool families, or destructive operations.
- **Local tray approval** for scoped clients guards secret reveal, remote-site administration and destructive deletions. Prompts name their target. They're asynchronous, never block the engine, time out to deny, and don't take up job slots.
- Refusals use distinct error codes, so the MCP bridge reports them as tool errors instead of "token rejected".
- **Call ledger:** append-only and bounded. It records the client, argument *types* (never values) and the result.

## Crash-loop safe mode and update probation (D6)

- A single crash still restarts exactly as before.
- A genuine **crash loop** boots into a self-explaining **safe mode**: no logins, IRC, races, downloads or agent runs, with exit, rollback and diagnostics. Safe mode still checks for and installs newer builds, and ends on its own after a bounded time. An unattended PC isn't left offline indefinitely.
- After an auto-update, the previous build is kept for **24 hours of probation**. Rollback is offered, and happens automatically only for a crash loop, never because a site is down. A rollback can't loop, and **probation never blocks installing a newer hotfix**.
- Leftover update folders are cleaned up per folder, and finished rollback stages are removed.

## Review

The reviewers found 15 issues, all addressed before release; one, about manual downgrades, is only partly fixed and is listed last. The ones that would have affected default users:

- **One bad FiSH entry could wipe the key store at the next start.** Typing `/key` with no argument stored an empty key. The new loader then rejected the whole store, and announces on channels keyed only in the store would have stopped decrypting.
  - A real-data check loaded the three real key stores through the new decoder; every key matched by hash.
- **An unreadable FiSH file would have stayed forever.** That made the secret inventory fail permanently, blocking alerts, every AI request and diagnostics.
- **The owner token's ordinary config edits needed tray approval**, and approval refusals looked like "token rejected" to the MCP bridge. MCP config edits also stopped counting as human corrections for the nightly agent.
- **Probation blocked every follow-up auto-install, including hotfixes, for 24 hours.** Safe mode never ran the updater.
- **Changed restart flags meant GlDrive might not relaunch after an installer closed it.** The previous flags are restored.
- One untrusted folder disabled all leftover-update cleanup.
- After a rollback, the older build's MCP config tools could reject the new config sections. That's fixed for default settings and local rollback; a manual downgrade with non-default opt-ins still needs care.
