## Changes and root causes

- A borrowed FTP download lane could fail to yield while its CPSV data connection was opening because the yield watcher started after `OpenAsync`. The watcher now covers managed setup and reads; interrupted setup retires the assignment and quarantines the failed control connection safely.
- Manual file and directory FXP did not reserve their endpoints in the lender's busy-site check. Reference-counted activity scopes now prevent new loans and reclaim existing loans for the whole operation, including gaps between directory files.
- Opposite-direction manual FXP could each hold one source endpoint and wait indefinitely for the other. Both operations now acquire endpoints in canonical order, with a combined 30-second deadline, cleanup on failure/cancellation, preserved source/destination roles, and same-site rejection.

Main and priority pools remain separate and share the account login gate. Failed connections are poisoned; existing delayed native teardown is retained so GnuTLS is not disposed while native reads remain active. See [the release notes](v3.11.13.md) for implementation and operational scope.

### Updater exit-status interpretation

The scheduled updater task reported `0xFFFFFFFF`. Independent source and event review established that successful completion intentionally calls `Process.GetCurrentProcess().Kill()` after signaling completion and waiting two seconds, avoiding teardown of replaced loaded files. On this .NET 10 path, `TerminateProcess(-1)` produces that task status. This attempt logged signed-file verification, rename/copy, successful task registration and completion signaling; the watchdog launched the healthy new process, with no rollback/failure record. The deployment observer did not itself catch the short-lived completion signal, so that single observer field is not used to claim success.

No product fix is required for this intentional termination. The status is diagnostically ambiguous because failed paths can share the exit code; signed-content verification, updater event review and independent production-health gates remain required. Supporting evidence is retained under `updater-exit-audit/`.

## Remaining risks and limits

- One configured FTP site remains unreachable, matching the baseline. Mount/remount timeouts continue with backoff; server/network availability has not been changed.
- One site's IRC invitation requests time out and three invite-only channels remain inaccessible. Access requires server-side resolution.
- Two extractor warnings concern a preexisting incomplete archive. Read-only disk/SFV verification found 3 of 15 volumes, 12 zero-byte missing markers, and no persisted managed-queue owner. Its latest data write predates deployment by more than a day. The readiness gate correctly avoids extraction; completing the set requires restoring the missing source data. See `extractor-stall-audit.md` and its sanitized JSON evidence. No production data or queue was changed.
- The production observation covers approximately five minutes of formal health monitoring and eight minutes of log review. It does not prove all FTP/BNC combinations or a long-running soak.
- Existing race backlog prevented demonstrating a production second-stream loan; isolated protocol tests provide that evidence. A second admitted download can still wait for the main pool at whole-batch granularity.
- Quarantine releases account permits before the delayed native connection teardown completes. A transient physical-socket count above the logical account count is expected in the poisoned case and is distinguished from the clean same-session handoff.
