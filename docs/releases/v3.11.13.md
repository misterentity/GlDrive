# v3.11.13 — FTP download connection sharing

FTP downloads can borrow a site's idle spread login as a second CPSV stream.
The account login gate still limits the combined main and spread pools. Active,
starting and queued races reserve their sites' spread logins; direct file and
directory FXP operations also reserve both endpoints for their full lifetime.

## Findings and fixes

The live v3.11.12 review on October 15 found sharing enabled on the connected
sites. Their configured login cap of four and headroom of two leave two usable
logins: one general/download connection and one priority/spread connection.
An active race and 38 other persisted requests covered the local download
period. Consequently no eligible idle interval or production second-lane loan
was demonstrated. Two admitted local downloads do not imply two main-pool
connections; one can wait while the other owns the connection.

A deterministic regression reproduced a borrowed lane failing to yield while
its data connection was still opening. The yield watcher started only after
OpenAsync completed. It now covers stoppable managed data setup as well as
reads. An interrupted open faults and quarantines the control connection,
releases the assignment and retires the loan. Native data opens retain their
existing cancellation behavior. Quarantine releases accounting immediately
while retaining the existing delayed native teardown; it does not imply an
immediate physical logout.

Direct FXP previously did not participate in the lender's busy-site check.
Reference-counted activity scopes now prevent lending, or request an existing
loan back, before either endpoint is borrowed or a directory is listed. They
cover the full directory operation, including gaps between files, and unwind
on cancellation or failure without clearing another overlapping operation.

Opposite-direction direct transfers previously acquired their source first,
allowing each to hold one endpoint and wait indefinitely for the other. Both
file and directory transfers now acquire endpoints in the same ordinal order,
with a combined 30-second borrow deadline. Failure or cancellation returns an
already-acquired peer. Source and destination roles remain unchanged, and a
same-site request is rejected before acquiring a login. Cancelled account-gate
waits retain cancellation or timeout meaning even when the pool wraps them as
an unavailable-permit exception.

## Validation and release

- Release solution build: successful, zero warnings and errors.
- Full regression: 2,292 application tests and 20 MCP tests passed.
- Native sharing fixture against assembly 3.11.13.0: 64 assertions passed,
  including byte-exact 2 MiB content after yield/reacquisition, clean session
  reuse, stalled setup quarantine, actual manual FXP handoff, opposite-direction
  pool acquisition, waiter wakeup and account-permit cleanup. Measured handoffs
  were 187 ms clean, 306 ms stalled setup and 291 ms manual FXP.
- Existing native FTPS/WinFsp regression: 87 assertions passed.
- Dependency audit: no known vulnerable application packages reported.

Version 3.11.13 follows the standard commit, push, exact-commit CI and signed
installer/ZIP release pipeline. Packaged smoke tests and production observation
are recorded in the deployment report after those gates complete. Local evidence
is retained under `.release-tools/ftp-sharing-20261015/` in the isolated sharing
worktree.

## Operational limits

The controlled native fixture uses synthetic content and real GnuTLS control
plus managed CPSV data TLS. It is evidence of the protocol handoff, not a remote
BNC soak or a claim that a production download acquired a second stream during
the observed race backlog. Main-pool borrowing remains at whole-download-batch
granularity, so a second admitted download may wait behind the first.

A configuration remount briefly encountered an account-cap wait. The old FXP
borrow returned before the next bounded recovery succeeded; no permit
under-release, over-release or login storm was observed. One configured server
remained unreachable. Those conditions were not changed to manufacture an idle
sharing test.
