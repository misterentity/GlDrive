# v3.10.126 — preserve healthy FTPS sessions

## Incident and root cause

Reviewed the retained September 20–21 application logs and the installed 3.10.125 prerelease on September 21, 2026 (America/Vancouver). At the initial capture, the two daily logs contained 47 `SelfConnectMode` exceptions, 579 pending-data-reply discards and 20 logged 530 login-limit exceptions. There were 75 Warning entries and no Error or Fatal entries. Several failures are logged below Error level, so severity counts alone do not establish health.

Version 3.10.125 set `SelfConnectMode = Never` to keep all logins under pool/gate accounting, but retained FluentFTP's default `SslSessionLength = 750`. In the pinned library, `Execute` requests reconnection when an encrypted session exceeds that transaction count, even while it is still connected. `Never` then throws before sending the command. During custom CPSV operations, this leaves the pending-sequence guard set and forces disposal. Notification polls and transfers fail, and repeated replacement logins add pressure to site login limits.

The [pinned FluentFTP Execute implementation](https://github.com/robinrodricks/FluentFTP/blob/074f222240ad8e1db7768697db0a4d0a6c3a92cf/FluentFTP/Client/AsyncClient/Execute.cs) confirms the branch. A new disposable native FTPS regression reproduced the exact production exception before the fix. This establishes an application cause for healthy-session failures; it does not establish that every historical 530 or remote disconnection had that cause.

The factory now sets `SslSessionLength = 0` together with `SelfConnectMode = Never`. Healthy connections remain reusable past the library's arbitrary threshold. Actual connection failures still pass through pool recovery and the login gate. Native disposal safeguards and package pins remain in place.

## Other findings

- SYN's FTP endpoint repeatedly times out; two other configured servers are connected. This predates this release. No endpoint was guessed or replaced.
- The T: download destination is absent. The existing destination check parks the affected download without consuming retries. No replacement storage path was assumed.
- Auto-races lacking eligible destination sections are correctly skipped. Section mappings and server rules are user configuration.
- September 20's unclean-session marker does not identify a crash cause. No matching GlDrive Windows Application crash event was found in the preceding two days. Older retained crash dumps date from May–July and are not evidence of a current crash.

## Remaining risks and rollback

- SYN and T: require external recovery or intended replacement settings. The release cannot make those dependencies available.
- Remote servers can still refuse transfers or enforce account limits, including limits affected by other clients. A short production observation cannot establish an extended soak result.
- The 800-command native check proves behavior beyond the old threshold; it does not simulate every remote BNC or TLS failure. Long-lived session failures still require monitoring.
- No configuration schema or persisted-data migration. The prior stable v3.10.124 installer is the rollback option, but restores the untracked library-reconnect behavior. Version 3.10.125 contains the reproduced threshold failure.
