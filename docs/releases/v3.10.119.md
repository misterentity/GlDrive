# GlDrive v3.10.119

## Log review and root causes

Reviewed all three retained daily application logs on September 15, 2026, through approximately 09:04 PT. The installed application was v3.10.118. Historical crash dumps predate this window (latest July 20); no GlDrive Application events 1000/1001/1026 were found in the preceding three days.

All 132 warnings were classified: 59 remount failures, two initial mount failures, 26 missing-destination parks, 30 FXP failure headers/cause lines, five notification poll failures, six incomplete-archive warnings, two source relocations, and two warnings for the prose-triggered race already fixed by v3.10.118. Today’s notification rejection is a final remote LIST 425 reply; periodic indexing also reports remote LIST 425 refusals. The existing retry, clean-rejection handling and partial-index behavior remain in effect. A remote control connection reset also appears among September 14’s transfer failures. Client logs cannot determine the server-side cause of these remote refusals/resets.

The new defect was visible at Information level: successful FiSH decrypts wrote the first and last four characters of the encryption key. `MaskKey` protected only keys shorter than eight characters, so an eight-character key was fully reconstructable. The same helper exposed key fragments on PRIVMSG/NOTICE decrypt failures and on both DH1080 exchange completion paths. This bypassed IRC wire-command redaction and the encrypted key store.

Removed secret-key arguments and fields from all five diagnostic paths and deleted `MaskKey`. Useful diagnostics remain: cipher mode/length, selected key index, text statistics, failure quality, ciphertext correlation hash, key origin/presence, and public DH1080 metadata. No private-key fingerprint is substituted. Encryption, key selection, persistence, and exchange behavior are unchanged.

## Remaining risks and rollback

- Historical logs still contain key fragments; upgrading prevents new exposure but does not retract existing logs or their copies. Treat those logs as sensitive and coordinate rotation of affected shared FiSH keys with peers/site operators. No evidence of unauthorized access was established by this review.
- SYN remains disconnected. The app reports connection timeouts, and a separate bounded TCP probe also failed. Restoring its endpoint requires network/server-side intervention.
- `T:` is absent from the local filesystem drive list and SMB mappings. The parked download needs that drive restored or an operator-specified replacement folder; its destination was not guessed.
- Remote 425 data-channel refusals, occasional connection resets, incomplete source RAR sets, and the previously documented overly broad custom announce rule remain external/configuration risks. No service was disabled to suppress warnings.
- The native harness does not reproduce a remote BNC's CPSV stack; bounded production observation is not a long-running soak.
- Inno Setup completed with its existing admin-install/HKCU startup-entry warning. Installing under a different administrator account can apply that optional startup entry to the administrator; the ZIP updater used here does not rewrite it.
- Automatic approval review blocked removal of the disposable native fixture directory with “blocked by policy.” Its server process was stopped; only generated test data and its temporary fixture certificate/key remain under the system temporary directory.
- Roll back with the v3.10.118 installer if necessary. No persisted schema changed. That rollback reintroduces the key-fragment logging defect.
