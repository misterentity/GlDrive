# v3.10.135 — reject removal announces and complete multipart readiness

## Findings and changes

The September 25 review started with installed and published version 3.10.134
at commit `adf47f7572044670a711a8c89050a456bde122f5`. Retained daily logs from
September 23–25 were snapshotted before testing. Errors also appeared at Warning
and Information level, so the review included failed jobs and exception stacks,
not just Error/Fatal events.

The frozen inventory contains **22,331 records: 298 Warning, 0 Error and
0 Fatal**, through September 25 10:02:32 PT. Every warning was classified.
All 15 source-550 failures followed remote path relocations, and all six
remote transport resets were followed by successful transfer of that same
file. Earlier account-stat failures stopped after 3.10.133. Historical
startup, pool, PreDB and Plex incidents were either recovered or already
covered by prior releases; this release does not claim remote services never
fail.

- Two failed races on September 25 originated from IRC `DELETE` messages at
  06:41:46 and 06:41:56 local time. A loose custom section/release regex skipped
  the event label and treated deleted releases as new. Explicit removal labels
  are now rejected before either matcher, deduplication or learning. Real titles
  containing Delete/Nuke and ordinary custom announces remain supported.
- Version 3.10.134 addressed quiet-but-incomplete classic archive sets, but
  modern `.partNN.rar` inputs bypassed that discovery and readiness check.
  The shared sampler now discovers both naming schemes; all RAR inputs pass it.
  It also recognizes the classic `.r99`/`.s00` boundary, ignores unrelated sets,
  and parses valid SFV entries with space or tab separators. Modern retry
  fingerprints now change when another volume arrives.
- Version 3.10.135 requires no configuration or persisted-data migration.

## Remaining conditions and limits

- SYN's FTP endpoint still times out. The other two configured FTP servers are
  connected; network recovery is outside these application changes.
- T: remains unavailable. Windows remembers the `\\zephyr\tv` mapping, while
  the share host's SMB port is reachable. Two downloads are parked awaiting the
  drive. Credentials and download destinations were not changed.
- D: has only 802,816 bytes free at inspection. Six extraction failures after
  the 3.10.134 update were output-write failures caused by insufficient space,
  followed by bounded retry abandonment. Space must be restored before that
  archive can extract; user media was not deleted or moved.
- Numbering gaps and readable SFVs prove missing volumes; an absent final
  volume with no SFV and no later-numbered member cannot be inferred by this
  readiness policy. Files can also change after sampling.
- Native smoke uses a disposable loopback FTPS server and WinFsp drive. It does
  not replace a prolonged remote BNC transfer soak. The desktop automation
  session did not expose a GL Drive window; isolated WPF renders and API checks
  do not cover every interactive UI flow.
- The existing Inno Setup admin/HKCU context warning remains. A short production
  observation cannot establish multi-day stability.
- The disposable FTPS server was stopped. Its synthetic temporary directory
  remains because automatic approval review rejected directory cleanup as
  "blocked by policy".
- Rollback uses the v3.10.134 installer and reintroduces the two corrected
  behaviors. No data migration is needed.
