# v3.10.144 — reliable race admission, final counts and metadata completion

## Findings and changes

The October 5 review covered retained October 3–5 application logs, persisted
race history, telemetry, Windows Application events and the installed v3.10.143
release. The frozen baseline through 17:13 UTC contained 21,880 records,
235 warnings and no Error or Fatal records. All 20 paired failed transfer attempts
subsequently completed the same file and race; all five source relocations were
followed successfully. The review found three application defects:

1. **Completed-race counts lagged behind delivery.** Twenty-two persisted races
   and their telemetry records reported one file short despite successful final
   transfers and an authoritative undelivered count of zero. Transfer completion
   updated ownership, while the site progress used by history and telemetry was
   updated by periodic scans. A race could finish before the next scan. Final
   progress now reconciles against ownership before outcome recording. Transfer
   tracking also remains active until ownership bookkeeping finishes, so the
   final drain cannot finish before the last delivery is recorded.
2. **Race admission had an unrepresented transition.** Code review of v3.10.143's
   queue persistence found that dequeue removed a request before the active job
   was registered. A concurrent save could omit it, concurrent starters could
   pass the same capacity/duplicate checks, and a disappearing pool could lose
   the dequeued request. Admission now reserves the request atomically and keeps
   it represented through persistence and startup. These interleavings are
   reproduced by regression tests; production logs do not establish that a
   request was lost during this review period. Failed direct requests retain
   their existing rejection behavior; previously accepted queued requests wait
   for a later retry, including when pools disappear before the worker starts.
3. **Successful torrent screening waited for its full deadline.** Successful
   screenings logged exactly 300 seconds because the metadata fetch's `finally`
   awaited a progress reporter that kept running until the five-minute deadline.
   The reporter now stops when the fetch finishes, while preserving timeout and
   caller-cancellation handling. This removes the artificial delay; it cannot
   make metadata available when no peer supplies it.

The release also updates the README and changelog version information.

successful file-transfer logs and a zero-undelivered completion; they are
reporting defects, not evidence of missing delivered files.

The standard pipeline is commit/push, successful GitHub CI, then
`installer/release.ps1` (tests, publish, installer, ZIP and RSA-signed checksums).
Deployment will use the installed application's startup updater at a safe
transfer boundary, followed by independent asset and installed-file verification,
API smoke tests and continuous health observation.

## Remaining conditions and limits

- SYN's configured FTP endpoint still times out before authentication. Existing
  capped retries remain active; the probe cannot distinguish remote outage,
  firewall or routing causes.
- The remembered T: mapping remains unavailable. DNS resolves, but SMB TCP 445
  refuses the connection and the share root returns `ERROR_BAD_NETPATH`.
  Downloads remain parked. Restore the intended SMB service/share before
  reconnecting the mapping; a credential failure has not been established.
- The prior D: shortage is resolved: logs record space becoming available on
  October 3 at 10:00 PDT and the parked extraction completing at 10:12 PDT.
  D: now has approximately 355.6 GiB free.
- Two older abandoned archive inputs remain unchanged, each with only its
  initial RAR and no continuation volumes. Supply the missing volumes or replace
  the incomplete inputs; this pass did not extract or alter them.
- Single-race capacity and relay throughput can still produce long queue waits.
  The existing 24-hour queue expiry and two-resume crash-loop limit remain.
- The count correction applies to new outcomes. Existing history and telemetry
  records are retained as audit evidence and are not rewritten.
- Transient remote resets, source relocation, PreDB timeouts and an OpenRouter
  429 occurred. Transfer/provider retries recovered where explicitly observed.
  The logs do not prove recovery of the specific failed torrent metadata fetches
  or the PreDB endpoint; those external outcomes remain unverified. Notification
  and account-stat transport stalls did not prevent subsequent race delivery,
  but no explicit next-poll success event establishes their exact recovery time.
  The relay ceiling still restarts slow transfers; this release does not change
  transfer timeout policy.
- The local native harness exercises FTPS/GnuTLS/WinFsp, but does not reproduce a
  remote BNC's CPSV implementation. WPF rendering does not exercise every
  interactive command, external Upcoming data, Plex authentication or playback.
  Minor existing Wishlist-header and Upcoming-selector clipping remains.
- Windows restart/logoff was not induced on production. No production
  configuration, credentials, mappings or user content were changed by this
  maintenance pass.
