# GL Drive v3.19.7

This release fixes two defects found in the November 2 production log review.

- **Drives on ioFTPD sites now work.** GL Drive assumed every server that advertises CPSV is glftpd, which starts TLS on the data connection itself. ioFTPD also advertises CPSV, but it waits for the client to start TLS. Both sides waited, so every directory listing, download and stream on the new **sitea** site failed with "data channel TLS handshake not completed within 10s". Each failure also quarantined a login, and the extra logins tripped the account's "Maximum concurrent connections" limit (530) during setup. GL Drive now detects the data-channel TLS role of each data address the first time it connects. A peer that sends its TLS hello first is treated as glftpd-style, as before. A peer that stays silent for 3 seconds is answered as a TLS client. The detected role is cached per address and discarded after a handshake failure, so a site that changes daemon is detected again. Sites that have already been detected as glftpd-style are never guessed, so existing glftpd sites see no change in behavior after their first transfer.
- **AI Setup no longer uses a retired OpenRouter model.** The Server dialog's AI Setup requested `openai/gpt-oss-120b:free`, which OpenRouter has retired (HTTP 404). It then fell back silently to the rule parser alone. The background agent already handled this retirement, but AI Setup used a separate client without that handling. AI Setup now uses the same retired-model table. It also retries once with the replacement model named in a 404 response. Its error log contains only the provider's error code and message; the full response, which includes the OpenRouter account ID, is no longer logged. The retired model has been removed from the Settings model list.

The reviewed logs (October 31 to November 2) contain no error or fatal records. The November 1 incomplete-shutdown warning matches a Windows unclean reboot (Kernel-Power 41, EventLog 6008). SITEC's FTP endpoint remains unreachable, and automatic retry is still active.

Validation and deployment details are in the [deployment report](https://github.com/misterentity/GlDrive/blob/master/docs/releases/v3.19.7-deployment.md).
