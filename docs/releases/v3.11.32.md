# GL Drive v3.11.32

Production log review (2026-10-24..26, v3.11.29 → v3.11.31) found no ERR or FTL
entries. Races were healthy: 76/78, 114/116 and 117/119 completed per day, and
51/52 in the v3.11.31 window. One defect ran at a 100% duty cycle, visible only
as Debug volume.

- **SITE DISKFREE is now asked once per mount, not every 30 seconds.** While the
  dashboard is open, its status bar sends `SITE DISKFREE` to every connected
  server every 30s. Neither production glftpd implements it. Across the three
  days the logs hold 15,110 lines of this exchange, and every reply was
  `500 'SITE DISKFREE': Command not understood.` In the 7.2 hours after the
  v3.11.31 deploy that was 1,278 sends, 54% of all 5xx replies. Each send
  borrowed the main pool, which on superbnc is a single login shared with
  spread scans and SITE INVITE.
- **A transient failure no longer disables drive free-space reporting.** The
  filesystem's own 5-minute query had the opposite bug: any null result,
  including a 5s borrow timeout on that busy pool, marked the server
  unsupported for the whole mount. One timeout left the drive reporting
  default free space until the next remount.

`FtpOperations` (one instance per mount) now owns the verdict for both callers.
Following RFC 959, a 5yz reply is a permanent negative completion and so is an
unreadable 2xx body. A 4yz reply, a missing reply, a borrow timeout or a
cancellation teaches nothing about the server and is retried later. A remount
re-probes once.

Validation: Release build with zero warnings/errors; full solution regression
suite green; 11 new focused tests in `DiskFreeVerdictTests`, written first and
confirmed failing. Six mutants of the new guard were all killed: verdict not
recorded, catch records a verdict, 5xx ignored, 4xx treated as permanent, no
short-circuit, and unreadable 2xx treated as transient. Each mutant was
checked to change the source before it ran. The isolated ReleaseCheck native
FTPS/WinFsp harness passed (see the deployment record).

Reviewed and left unchanged (external, or by design):
- SYN's FTP host is still down (since 2026-08-13): 21–23 remount WRNs/day.
- superbnc stalled twice (10-24 01:06, 10-25 02:39). New connections timed out
  at the handshake, and the pools recovered on their own within about 6 minutes.
  Both races completed. The 10-24 "ghost sessions are plausible" advice came
  from the pre-v3.11.30 build; v3.11.30 already removed it.
- PreDB HTTP timeouts and 503s, UDP torrent tracker failures, one 429 from
  OpenRouter at 04:00 on 10-26 (the agent's 2-minute catch-up run succeeded).
- Mid-race source relocation (`/incoming` → `/recent`) is recovered by the
  v3.10.153 relocation path. One race whose release the source moved away
  mid-race parked about 2 minutes and then ended correctly.
- `*.*.*.*` in `[FTP]` Debug lines (for example
  `The.Price.Is.Right.*.*.*.*p.WEB.h264-DiRT`) is FluentFTP's IP-address log
  masking rewriting a dotted date plus resolution (`2026.10.26.1080`). It is not
  a bad path; the commands sent carried the real names.
