# v3.10.152 — refresh restarted directory listings on open handles

## Log review and root cause

Reviewed the retained October 7–9 application logs, AI audit/briefs and transfer
telemetry, Windows Application/System events, the installed release and its control
API. The baseline was v3.10.151, PID 91720, started October 9 at 03:26:51 UTC.
Application logs use local UTC−07:00 timestamps.

The 17:03:38 UTC audit covered 23,655 records: 230 warnings, zero Error/Fatal
records and no unclassified warning patterns. Since the baseline process started,
51 warnings were attributable to the absent T: drive (34), unavailable SYN server
(16, including startup), and a recovered OpenRouter HTTP 429 (1). That process had
completed 1,860 transfers totaling 275,104,851,846 bytes and 120 race outcomes,
with no aborted transfer telemetry or Windows Application errors.

The prior cache fix correctly rejects a LIST fetched before invalidation, but a
second cache remained on each open directory handle: `FileNode.DirEntries`.
`ReadDirectoryEntry` filled it once and never reloaded it when Windows restarted
enumeration. A deterministic reproduction on the released binary enumerated
`deleted.bin`, invalidated and replaced the shared cache with `replacement.bin`,
then restarted the same handle with null context/marker. It still returned
`deleted.bin`. A shared-cache fix alone cannot repair that retained snapshot.

The callback now reloads the listing on the first entry of a restarted enumeration
(null marker). Continuations after a marker and subsequent callbacks within the
same page retain the snapshot, avoiding skips or duplicates when files change
between pages. The existing directory-cache invalidation guard remains in use.

README and changelog version references were also brought up to date.

## Remaining risks and external conditions

- SYN remains unavailable and T: remains unmounted. Downloads targeting T: are
  parked; restoring the endpoint/storage requires working infrastructure. No
  server was disabled and no download destination was silently changed.
- OpenRouter returned 429 at 11:00:02 UTC and the scheduled retry succeeded at
  11:02:09 UTC with a nonempty brief and no applied changes. The configured slug
  ends in `:free`, but the existing migration actually calls `openai/gpt-oss-120b`;
  v3.10.151's report incorrectly described the effective model as the free slug.
  Provider availability and output quality remain external risks.
- Remote direct-FXP probes can return STOR 425; the observed probes recovered by
  selecting Relay. The previous machine-wide ephemeral-port exhaustion source
  remains unidentified; the application's bounded search recovery is in place.
- Zephyr upload eligibility and section mappings remain frozen. Existing policy
  and application configuration were preserved.
- Native loopback FTPS/WinFsp checks and a bounded production observation window
  cannot cover every remote BNC condition or replace a long-duration soak.
- Inno Setup emitted its existing admin/HKCU warning: an interactive clean install
  elevated with another account's credentials may register optional autostart for
  that administrator instead of the initiating user. This deployment uses the
  signed SYSTEM updater, so that installer-specific behavior was not exercised.
