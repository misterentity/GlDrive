# v3.10.130 — keep server status directories out of search

## Log review and root causes

Reviewed the retained September 21–23 application logs on September 23, 2026
(America/Vancouver). Snapshots contain 33,405, 46,359 and 349 events respectively;
the September 23 snapshot ends at 10:00:48. No Error/Fatal events occurred in
these logs, but Warning and Information events exposed the following failures.

- **Search defect:** repeated index builds report five failed listings, starting
  with a directory named `[Z] - ( 1591M 17F - COMPLETE ) - [Z]`. The server
  advertises zipscript status entries as directories but rejects their LIST with
  `550 Bad directory components`. Search treated them as real releases, indexed
  them, and recursed into them. In live mode the exception also aborts traversal
  of later siblings within that root. Filtering before indexing/recursion fixes
  both effects without hiding genuine listing failures.
- **SYN endpoint:** nine September 23 warnings are mount/remount TCP timeouts.
  A separate five-second connection probe also timed out. Two other FTP servers
  are healthy. This is an unresolved external dependency.
- **T: destination:** sixteen warnings park two downloads without consuming
  their retry budgets. Windows remembers `T:` as `\\zephyr\tv`, but T: cannot
  be accessed in the current session. Previous investigation established a
  share authentication failure. No credentials or replacement destination were
  guessed; restoring the mapping requires operator action.
- **Transient network/source failures:** September 22 has four transfer failures
  (plus their four job-level reports): two source files moved, followed by source
  relocation handling, and two remote connection resets followed by successful
  retries. September 23 has one CPSV TLS handshake timeout, quarantines the
  affected connection, and continues polling. These are external events handled
  by existing recovery, not evidence of a new deterministic code defect.
- **Historical TLS errors:** the September 21 SelfConnectMode failures precede
  v3.10.126; none recur in September 22–23. Native smoke still crosses the
  former transaction limit with 800 commands on one session. The historical
  stats-refresh warning hit BNC cooldown at 05:24:16; the server reconnected
  at 05:24:21. No stats-refresh warning recurs in September 22–23.
- **Startup diagnostics:** Windows System events 1074/6006/6005 record Windows
  Update restarts around 02:29–02:33, consistent with the leftover running marker
  at 07:31. No GL Drive Application error/crash event was found in the preceding
  two days. A second instance was safely rejected. The daily agent performed
  one successful catch-up at 07:32–07:34 and scheduled the next 04:00 slot.
- **Plex transient during smoke:** opening the installed dashboard triggered a
  10:09 warning that WORKSTATION was unreachable. Follow-up probes confirmed
  the configured HTTPS endpoint and loopback both identify the selected server;
  authenticated identity and library requests all returned HTTP 200, and the
  application's own `PlexClient.ProbeAsync` passed. Account resource discovery
  succeeded with the existing credential. No configuration or credential was
  changed; a read-only diagnostic saved only statuses, not tokens or payloads.

## Changes

- Apply one narrow status-directory filter to cached and live crawling. It
  requires bracket decoration and a standalone complete/incomplete status word.
  Ordinary COMPLETE releases, bracketed group prefixes, Sample and Subs remain.
- Extract the live listing delegate so both traversal modes can be exercised
  against a synthetic server tree. Pool borrowing retains its timeout and
  per-listing disposal behavior.
- Add regression cases that throw the observed 550 if a marker is listed and
  assert that all later real directories remain in results. Add both search
  modes to the real native FTPS harness.
- Version 3.10.130; no configuration or persisted-data migration.

## Remaining risks and rollback

- SYN and T: remain unavailable; the app is operational with degraded external
  services. A code release cannot restore an unreachable FTP endpoint or supply
  missing share credentials.
- The filter deliberately recognizes decorated completion/progress status names,
  not every possible custom zipscript artifact. Genuine listing errors remain
  visible. SITE SEARCH server-side results are unchanged.
- Native smoke does not simulate remote BNC CPSV behavior. UI render checks do
  not establish every interactive flow or long-term stability.
- Inno Setup emits its existing administrative-install/HKCU warning: installing
  under another administrator account can affect that account's autostart.
- Roll back with the v3.10.129 installer; no data migration is required.
