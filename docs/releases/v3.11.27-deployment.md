## Changes and diagnosis

Direct FXP previously warned about failed completion replies but still credited
delivery. Version 3.11.27 requires 226/250 replies from both servers and preserves
cancellation, the shared timeout and native reply-drain safeguards. Rejected or
timed-out direct probes remember the failed route and quarantine both sessions;
a later attempt can use relay with fresh sessions. The failed sessions are never
immediately reused for relay. Existing relay byte-count checks and glftpd's
destination `426 Data Connection: Success.` handling remain unchanged.

This was a reproduced latent defect, not the cause of the seven transfer failures
observed in the audited pre-update production run. Those failures comprised four
missing remote paths, two passive-data connection timeouts and one remote reset. Every
affected file/route subsequently completed, and all four associated races
completed through normal retry or relocation.

The audit read all 23 retained logs. Records span October 20 07:00:04.867 through
October 22 17:01:47.411 UTC: 331 warnings and zero Error/Fatal records. The
3.11.25 process, started October 21 17:36:29.761759 UTC, contributed 1,070,865
records, 54 warnings and zero Error/Fatal records. Its 2,815 FXP and 174 race
completions are application observations, not independent byte verification.
The earlier local account-permit/reconnect failure did not recur. One connection
loss recovered in 7.445 seconds. All 30 historical crash-report hashes were
unchanged; Windows crash-event queries through October 22 17:03:16.0315856 UTC
succeeded with zero GL Drive events.

The closing old-process window, after 17:01:47.411 UTC through the new process
boundary at 17:28:58.390581 UTC, adds 23,814 records, zero Warning/Error/Fatal,
93 FXP completions and four race completions. The complete reviewed old run
therefore has 2,908 FXP and 178 race completion records. Crash hashes and Windows
event checks remained unchanged through that boundary.

Two release-monitor control-channel read timeouts were isolated first failures;
neither was followed by a repeated warning sequence or exhausted main pool.
Twelve Debug SFV-read cancellations were examined: nine occurred within 14 ms
after their race completed; the other three races completed 171–273 seconds
later. Existing bounded reads, fallback and refresh behavior did not establish
persistent starvation or malformed parsing. An informational connection timeout
also belonged to a race that subsequently completed. The existing archive's
startup verification failed at Debug level without a subsequent extraction
Warning/Error; successful extraction was not established.

  transient remote failures recovered; this release does not change external
  service availability.
- PreDB's seven earlier HTTP 404 warnings had recovered during independent checks
  on October 22 at approximately 17:05 UTC: its root/query returned HTTP 200 and
  the query contained valid JSON. The optional keyless metadata hostname remained
  NXDOMAIN at 17:04:54 UTC; OMDB and PreDB resolved. No supported metadata endpoint
  replacement was established.
- One existing failed torrent remains blocked pending explicit approval to omit
  prohibited file types. It was not retried. Existing remote file/credit failures
  and an incomplete-archive verification are not claimed repaired by this fix.
- At **17:44:21.005306 UTC**, cleanup had returned 1 and retained **420 old files /
  370,469,120 bytes**, increased from 378 files / 333,422,208 bytes before release.
  Eighteen existing MCP clients remain. Thirteen exposed 923 loaded modules;
  their 42 distinct original installed paths correspond to all 420 backup
  candidates. No module reported an exact renamed generation, and five clients
  exposed no module information. Retained mapped runtimes are a supported
  explanation, but individual lock owners were not proven. The installer task
  remains successful (result 0); unrelated clients were not terminated.
- Automatic approval review rejected deletion of this release's temporary
  signing-key copy with reason **"blocked by policy"**. The copy remains in the
  release worktree's `installer/keys/checksum-private.pem`; inheritance is disabled

  evidence. The original key remains present and unchanged. No key was committed

- Historical native/WPF crashes remain unreproduced. Finite observation cannot
  prove their elimination. The pre-update 3.11.25 audit contains 1,049,529 Debug
  and 11,424 Verbose records, with roughly two days retained. Logging volume
  remains high after the update, as the new-process counts above show.
- Production has MountDrive disabled on every server. Real mounted I/O passed in
  the isolated fixture; ordinary production drive inventory is not mount proof.
- A pre-existing v3.11.26 worktree and unrelated checkout changes were left
  untouched and excluded. Version 3.11.27 isolates this reviewed release.
