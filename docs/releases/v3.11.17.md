# GL Drive v3.11.17 — FTP recovery during pool contention

Source relocation now borrows an available main or spread FTP connection. Previously,
an existing but busy main pool hid the usable spread pool: one source move caused
repeated four-minute waits and retries against its old path. Unavailable connections
and failed directory probes no longer count as evidence that a release is absent.
Failed command sessions are quarantined before pool reuse.

SITE NUKES now falls back to the live spread pool after ten seconds waiting on the
main pool, within its existing thirty-second poll budget. If no connection becomes
available, the poll is deferred without charging the remote-command circuit breaker.
Actual server failures and command deadlines still count toward the breaker.

Regression coverage exercises occupied and exhausted pools, relocation recovery,
incomplete probe evidence, lease reuse, cancellation, nuke-poll recovery and actual
command failures. The UDP tracker fixture also has a realistic bounded retry budget
for a fully parallel test run; its wire-format and scheduling assertions are unchanged.

Existing external conditions remain visible: an unreachable configured FTP site,
transient DNS/connection loss and AI-provider failures, and partial searches while
the account's connection capacity is occupied. This release does not change account
limits, remote services, or supply missing archive content. Short control probes may
briefly share the spread pool with transfers.

Build, regression, native smoke, signed-release and production-health results are
recorded in the [deployment report](v3.11.17-deployment.md).
