## Defect 1: ioFTPD CPSV data channels deadlocked

**Root cause.** `CpsvDataHelper` assumed every CPSV server is glftpd, which starts TLS on the data connection itself, so GL Drive always waited as the TLS server. sitea runs **ioFTPD**. It advertises CPSV in FEAT, but it waits for the client to start TLS. Both ends waited, and every transfer timed out after 10 s. A direct probe confirmed this: after `150 … using SSL/TLS`, the peer sent nothing for 4 s, and a client-initiated handshake on the same socket returned the listing (`ioFTPD` owner/group in the entries).

**v3.19.7 (insufficient).** GL Drive learned the TLS role per data address and answered silent peers as a TLS **client** using Windows SChannel. In production, ioFTPD reset all three of those handshakes (`10054 forcibly closed`, at `AuthenticateAsClientAsync`). In the same window, an OpenSSL client succeeded with both TLS 1.2 and TLS 1.3. SChannel's ClientHello was ordinary (142 B for TLS 1.2, standard ECDHE/RSA GCM and CBC suites, groups x25519/P-256/P-384), so the specific incompatibility is still unidentified. A follow-up cipher map was invalidated when sitea's connection-flood protection banned the probing IP (see *Incident* below).

**v3.19.8 (fix).** CPSV offers no benefit on a server that stays the TLS server. When a site's data peer does not send a TLS hello, GL Drive marks the **control host**, and `FtpConnectionPool.UseCpsv` becomes false for it. Its transfers then use FluentFTP's standard PASV path, where GnuTLS starts TLS — the stack the control channel already proves works. FXP mode detection uses the same flag. Guards against misclassifying a glftpd site:

- A host or data address that has completed a glftpd-style handshake is never reclassified. A stalled data channel there still waits the full deadline, as in v3.19.6.
- A host without that history must show **2 consecutive** silent data channels before it is switched.
- A switch expires after **6 h**, then GL Drive tries CPSV again.
- Data sockets record their control host when they connect (`ConnectDataSocket`), so every one of the 9 data-TLS call sites is covered by the same code.

**Production evidence (v3.19.8).** At 21:26:36 and 21:26:40, two silent channels triggered the switch: `CPSV unusable on sitea.example.net … using standard PASV data connections for 6h`. After that, a listing through GL Drive returned sitea's root (18 entries), `G:\` and `G:\0DAY` list in Explorer and the shell, `Stats available for sitea via standard LIST trailer` was logged, and the release monitor reported **0 poll errors**. glftpd sites in the same window: 9 FXP transfers completed siteb → sited, search indexes were built (siteb 3,259 entries), and no data-TLS failures occurred.

## Defect 2: AI Setup used a retired OpenRouter model

`AgentClient` already handled OpenRouter retiring `openai/gpt-oss-120b:free`, but its sibling `OpenRouterClient`, used by the Server dialog's AI Setup, did not. It sent the retired model, received a 404 and fell back silently to the rule parser alone. It also logged the full provider response, including the OpenRouter `user_id`. It now applies the same retired-model table, retries once with the replacement model named in a 404 (only on a 404), and logs only the error code and message. The retired model has been removed from the Settings model list.

## Incident during diagnosis

A burst of roughly a dozen probe handshakes to map sitea's TLS ciphers tripped ioFTPD's connection-flood protection at about 20:41. sitea then dropped all connections before sending a banner, including GL Drive's own reconnects (backoff 10 → 120 s). The ban had lifted by 21:07. No configuration was changed.

## Remaining risks and follow-ups

- **SChannel versus ioFTPD is unexplained.** The PASV fallback avoids it, but any future direct-FXP pairing where GL Drive must be the TLS client through SChannel against this daemon would hit the same reset.
- **sitea `/recent` has no category folders.** The release monitor warns `found no categories under /recent` because ioFTPD lays out `/recent` differently. Wishlist polling has nothing to watch on sitea until the watch path is configured. sitea also has no spread sections, so it does not race.
- **The PASV path is new for this account.** None of the other configured sites use it. It is FluentFTP's default path, but this is its first sustained production use here.
- **Reclassification needs a restart.** A host proven glftpd-style is never reclassified during the process lifetime, so a daemon swap on such a host is only detected after a restart.
- **Flaky test:** `FishKeyRecoveryTests.Verified_import_keeps_chosen_primary_even_if_stale_pending_cleanup_fails(lockPending: true)` failed once under full-suite load inside `release.ps1`. It passed 5 of 5 in isolation, in CI and in the release rerun. It is unrelated to these changes but timing-sensitive.
- **Agent model config:** `/agent/modelId` and `/downloads/openRouterModel` still name the retired `:free` model. Both clients now map it at runtime. Choosing a model in Settings would make the configuration explicit.
- **Unchanged from v3.19.5:** SITEC's FTP endpoint is unreachable, and the frozen sited `-TV-` section mapping still needs Dave's decision.
