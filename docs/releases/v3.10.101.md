This is the validated hotfix release that supersedes v3.10.100. It includes the relocated-source

release.

## Log review

The complete post-v3.10.99 production window reviewed was 2026-09-02 09:38:16 through
2026-09-03 09:14:59 local time. It contained **85,853 structured records, 0 ERR, 0 FTL,
and 79 WRN**. Windows Application Error, .NET Runtime, and Windows Error Reporting contained
no matching GlDrive failures.

Every warning was classified:

- 29 mount records were the known externally unavailable SYN FTP endpoint (two initial mounts
  and 27 bounded remount attempts). SYN IRC remained connected independently.
- 42 FXP records were 21 detail/summary pairs: 18 transient `425` data-connection races, two
  transport resets, and one terminal `550`. Every transient race later completed.
- Four NewReleaseMonitor polls failed once and recovered on the next poll.
- One SharpCompress warning fell back to external UnRAR, which exited 0; extraction completed.
- One source-migration warning and one terminal spread failure were the same relocated-source
  incident described below.
- One stale-heartbeat warning aligned with Windows Kernel-Power 41 and EventLog 6008 after an
  unexpected system restart; no GlDrive crash event existed.

## Root causes and changes

| Area | Root cause | Resolution |
|---|---|---|
| Relocated spread source | glftpd moved a finished release from `/incoming/tv-hd` to `/recent/tv-hd` during a race. The migration handler only retried the stale canonical path, marked that site migrated, and excluded it from alternate-source discovery. RETR also continued to use the first observed path. | `SpreadJob` now probes the source site's alternate configured section/watch roots, records the relocated base path, forces an immediate rescan, and resolves each RETR against the per-source base path. |
| Race-history test isolation | `RaceSummarizeTests` constructed `RaceHistoryStore` with its parameterless production default. A full local Release test run therefore persisted synthetic test records to `%AppData%\GlDrive\race-history.json`. | `RaceHistoryStore` now requires an explicit path. Production passes `DefaultFilePath`; tests pass unique temporary paths. The constructor contract prevents future accidental calls from compiling. |

The version of record and changelog were advanced first to 3.10.100 for the spread fix and then
to 3.10.101 for the isolation hotfix.

## Remaining risks

1. SYN's FTP endpoint remains externally unavailable. Its retry loop is bounded and healthy, and
   SYN IRC remains independently connected.
2. The 500 reconstructed history records preserve operational outcome data, but inferred failure
   categories and absent legacy presentation fields are not byte-for-byte copies of the lost file.
3. Remote FTP servers can still produce transient `425` refusals or transport resets. Existing
   quarantine/retry behavior recovered every such race in the reviewed window.
4. The standalone installer is not Authenticode-signed. Auto-update does verify the RSA-signed
   checksum manifest and ZIP SHA-256 before installation.
5. The production transfer smoke ran on v3.10.100, which contains the same spread code as v3.10.101.
   The v3.10.101-only change is persistence-path isolation; its production validation was the
   500-record reload and unchanged history hash across the release test run.
