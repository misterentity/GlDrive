# v3.10.137 — recover nuke polling and exclude unavailable search entries

## Findings and changes

The September 28 review started from installed version 3.10.136. The three
retained daily logs (September 26–28) were reviewed for warning/error events,
failed operations logged at Information, exception stacks and recovery evidence.
Private log snapshots and validation artifacts are retained locally under
`.release-tools/verification-20260928/` and are excluded from git.

The frozen window is **September 26 00:00:18 through September 28 09:56:35
PT**: **10,518 records, 189 Warning, 0 Error and 0 Fatal**. All warnings were
classified: 116 parked downloads, 54 SYN remount timeouts, three IRC timeouts,
ten records for five FXP failures, three relocation notices, one recovered
OpenRouter 429, one recovered release-listing timeout and one nuke-poll timeout.
All five affected FXP files subsequently transferred successfully. Information
records also exposed 14 recurring nuked-directory listing failures, plus one
transient socket-resource listing failure which recovered on the next rebuild.
No GL Drive Error/Critical Windows Application events were found since September 26.

- **Nuke polling:** the poller borrowed from a disconnected mount that was still
  attempting recovery. A never-connected pool is not considered exhausted, so
  that check alone started an unnecessary login to the unavailable SYN endpoint.
  Polling now requires a connected mount. Its 30-second deadline also covers
  the command, interrupted sessions are quarantined through the existing native
  safety path, and a three-failure breaker permits a recovery probe after the
  configured polling interval. Concurrent runs are suppressed and shutdown
  cancels the managed wait. Native GnuTLS reads are not forcibly cancelled.
- **Search:** an explicitly `[NUKED]-` directory remained visible in a parent
  listing while child access returned `550 Bad directory components`. Cached
  search retried it every rebuild, and live search could stop before reaching
  later releases. Cached, live and SITE SEARCH now exclude explicit nuke status
  entries. Ordinary NUKED titles and bracketed group names remain searchable.
- **Read-only rendering:** the smoke-test review found that screenshot mode
  constructed a SpreadManager which loaded and later saved production transfer
  speed history. That could overwrite a concurrent real transfer update. A
  read-only manager now leaves persistence disabled; tests use temporary stores
  to verify preservation and normal writable behavior.
- Version is 3.10.137. No configuration or persisted-data migration is required.

## Remaining external conditions and limits

- SYN's FTP endpoint times out on a direct five-second TCP probe. The other two
  configured FTP servers were connected at baseline. Remote availability cannot
  be repaired by this application release.
- T: remembers `\\zephyr\tv`. SMB port 445 is reachable, but directory access
  fails with Windows **1326 (logon failure)**, and no matching stored host
  credential was found. Two downloads remain parked. Restoring valid Windows
  authentication is required; no credentials or download paths were changed.
- D: has **17,239,916,544 bytes free (about 16.1 GiB)** at baseline, below the
  previously parked archive's approximately 22.6 GB requirement including
  headroom. The prior release's space parking remains in force. No user media
  was moved or deleted to reclaim space.
- Handled remote path relocations, transport failures and upstream HTTP rate
  limits can recur; recovered incidents are not evidence of permanent service
  availability.
- Native smoke uses a disposable loopback FTPS server and an unused WinFsp
  drive; it does not replace a prolonged remote BNC/CPSV soak. WPF renders cover
  layout/startup rather than every interactive workflow, and may make read-only
  public metadata requests.
- A short production observation window cannot establish multi-day stability.
  The existing Inno Setup admin/HKCU context warning remains a packaging limit.
- Nuke-poll recovery becomes eligible one polling interval after a failure.
  Because the timer uses a fixed cadence, automatic recovery can wait up to two
  intervals. Native timeout tests prove quarantine routing using a synthetic
  lease; they do not reproduce a stuck real GnuTLS read.
- Rollback uses the v3.10.136 installer and reintroduces the corrected behaviors;
  no data migration is necessary.
