# v3.10.128 — preserve useful diagnostic history

## Log review and root causes

Reviewed the retained September 20–22 application logs on September 22, 2026
(America/Vancouver), including exception stacks and Information-level failures.
The September 22 snapshot through approximately 09:02 contained 39,253 lines,
38,249 Information events, 28 Warnings, and no Error or Fatal events.

- The earlier FluentFTP `SelfConnectMode` failures are confined to sessions before
  v3.10.126. They have not recurred in the current v3.10.127 session.
- No duplicate skips were recorded on September 22; more than 1,800 FXP transfers
  completed. The ownership-epoch correction in v3.10.127 continues to hold.
- SYN still times out connecting to its configured FTP endpoint. It accounts for
  nine of today's warnings; its retry loop backs off. The other two FTP servers
  are connected. This is an unresolved external endpoint failure.
- Nineteen warnings park two downloads because their destination drive `T:` is
  absent. Retry budgets are preserved. There is no mapped T: drive in this
  session. Restoring its intended device/share or selecting replacement storage
  requires environment information; no alternative destination was guessed.
- Two quarantines follow a direct CPSV-PASV capability probe, with Relay fallback;
  races continue successfully. Section/rule exclusions are expected configuration
  decisions. Stats ACL denials fall through the existing candidate chain.
- No GlDrive error/crash events were found in the Windows Application log for
  the preceding two days. Retained May–July crash dumps are historical evidence,
  not a current crash. The live heartbeat reported 261 MB working set after
  nearly 12 hours, versus 242 MB at the previous release's 45-minute checkpoint.

The actionable logging defect is volume: approximately 32,600 routine scan events
account for over 80% of today's Information events. Successful FiSH decryption
adds over 1,000 diagnostics, while repeated stats probes log account response
bodies. These events accelerate size-based rolling and obscure failure evidence.

## Changes

- Move per-snapshot scan start/list/result/application details to Debug. Keep
  transfer outcomes, fallback/failure explanations, contention summaries, and
  Warning/Error events at their existing levels.
- Move successful FiSH message diagnostics to Debug; retain decryption failures,
  recovery, and key-transition diagnostics. Skip diagnostic string computation
  when Debug is disabled.
- Move routine stats polling/results to Debug and remove raw SITE/LIST response
  bodies from logs entirely. Stats parsing and dashboard updates are unchanged.
- Bump the application and README version to 3.10.128. There is no configuration
  schema or persisted-data migration.

To investigate snapshot ordering or successful decryption, choose Debug in
Settings → Diagnostics, then return to Information after collecting evidence.
No existing log files are deleted by this change.

## Remaining risks and rollback

- SYN and T: remain unavailable pending endpoint/storage recovery details.
  Publishing this diagnostic change does not resolve those external failures.
- Debug logs intentionally remain verbose; enable them only while diagnosing.
- Automatic approval review rejected cleanup of the disposable fixture directory
  (`%TEMP%/gldrive-ftps-check-enzathm8`) as "blocked by policy". Its server process
  is stopped; the synthetic fixture files remain on disk.
- A short observation cannot prove multi-day stability, remote BNC behavior, or
  the absence of a memory leak. Retention improvement is workload-dependent.
- Rollback is the previous v3.10.127 installer; it restores verbose logging and
  raw stats-body diagnostics, with no data migration required.
