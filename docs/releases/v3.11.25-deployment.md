## Log review and fixes

The hashed audit read all 21 rolling logs between 17:02:22 and 17:02:29 UTC.
Retained records span October 19 00:00:00.358 through October 21 10:02:28.053
local (UTC−07:00): 316 warnings and zero Error/Fatal records. The pre-update
v3.11.24 run contains 203 warnings, zero Error/Fatal records, 1,986 logged FXP
completions and 127 race completions. All 30 historical crash reports match the
previous audit; no relevant Windows crash event occurred in the current run
through 17:09:17 UTC. A closing audit from the last captured record through the
new process start at 17:36:29.761759 UTC adds 16 warnings, zero Error/Fatal,
70 logged FXP completions and four race completions. Those warnings comprise
12 more local-permit reconnect failures, one related poll failure, one related
connection-loss event and two PreDB 404 responses. Crash reports remained
unchanged and the extended Windows event check found no GL Drive crash event.
The closing audit replaces its overlapping intermediate sample. Millisecond
timestamps cannot distinguish later-appended records sharing the exact original
capture boundary.

The principal incident followed a configuration remount. Initialization opened
a connection without reserving its pool slot, then overwrote the connection
count. A concurrent borrow could reserve another slot, wait for the same account
permit, and undo the initializer's count when cancelled. Logs show successful
initialization followed by an abandoned borrow reporting zero connections and
subsequent login-gate backoff. This explains the observed remount sequence;
the logs cannot establish the identity of every permit behind all 151 reconnect
warnings. Both initialization entry points now reserve capacity atomically,
retain ownership when publishing the connection, and reclaim unpublished
connections and reservations on failure. Disposal no longer invalidates a
semaphore still held by initialization. Native quarantine safeguards remain.
The mount also withholds the public pool until initialization is complete and
rejects disposed pools. This closes the adjacent borrower-first ordering window
without changing private ownership or mount-failure cleanup. Initialized but
exhausted pools remain visible to recovery callers.

Review of v3.11.24's duplicate-file handling found that a destination's short
copy could be credited as a transfer source or used for SFV inventory. A later
source-size increase could also revoke the duplicate hold and restart the
refused upload. Duplicate suppression now survives source growth, while the
unverified copy is excluded from onward transfers and SFV reads. Only a fresh
full-size listing verifies it; disappearance still clears the hold.

The updater previously killed itself with exit code −1 after both successful
installation and rollback. It now preserves native forced termination while
reporting success as 0 and failure as 1. Rejected handoffs fail before dispatch.
Signature verification, authorization and rollback safeguards are unchanged.

## Remaining conditions and limits

- One remote FTP endpoint remains unavailable; its independent IRC connection is
  healthy. Remote missing/moved files and account-credit rejections remain
  external conditions.
- PreDB's API returned HTTP 404 at 17:11:53 UTC. Its public site remains available
  and still references the same API; no supported replacement was established.
  The optional keyless metadata host remains NXDOMAIN; OMDB resolves.
- The one failed torrent is intentionally blocked pending explicit approval to
  omit prohibited file types. Zero bytes were downloaded and it was not retried.
  Three older inactive FTP failures reflect remote file/credit conditions.
- Historical WPF render/resource crashes remain unreproduced. The finite
  observation window cannot establish that every historical crash is eliminated.
- Existing diagnostic logging remains verbose: 14,020 Debug and 244 Verbose
  records were generated in the bounded production window. Log-volume and longer
  remote-service observations remain operational considerations.
- Post-update cleanup deleted 1,338 old files and retained 378, unchanged from
  the pre-update retained count; the cleanup task returned 1. Sixteen pre-update
  MCP client processes remain and may hold old runtimes mapped. Unrelated clients
  were not terminated for this release.
- The v3.11.24 updater performed this installation and reported
  `4294967295` (−1), as expected for its forced self-termination path. The new
  success/failure exit reporting applies when v3.11.25 later acts as updater.
  Isolated native subprocess tests cover the new behavior; installed hashes,
  version and functional checks establish this deployment's success.
- Automatic approval review rejected deletion of the temporary signing-key copy
  with the reason **"blocked by policy"**. The copy remains in the release
  worktree's `installer/keys/checksum-private.pem`, with inheritance disabled and
  access restricted to the user and SYSTEM. It was not committed or published;
  the original key is unchanged. Removal of this temporary copy remains pending.
