# v3.10.150 — preserve cached search results when the FTP root cannot be listed

## Log review and root cause

The October 8 follow-up audit at 17:01:36 UTC reviewed all retained October 6–8
application logs, current-process telemetry, Windows Application errors and
production dependencies. The baseline was v3.10.149, PID 15280, started at
03:21:05 UTC. Application text logs use UTC−07:00.

- All 21,605 retained records contained zero Error/Fatal events. The current process
  contributed 5,358 records and 60 warnings; there were no GlDrive Windows
  Application Error/Critical events in the audited window.
- Current warnings comprised 34 missing-drive notices, 16 SYN mount/remount
  notices, four RETR 550 failures with four paired exception records, and two
  source-relocation notices. The four rejected transfers belonged to two races
  that subsequently completed. This establishes race-level recovery, not an
  independent byte-for-byte verification of each remote destination file.
- Current telemetry contained 1,130 transfers and 85 complete race outcomes,
  with no parsing, short-success or timeout violations detected by the audit.
- The historical ephemeral-port exhaustion incident and associated BNC cooldown
  were already addressed by v3.10.149; no recurrence was found in this process.

Review of that search-index recovery fix found a reproducible boundary defect.
The default search path `/` was trimmed to an empty string before listing. The
cache merge checked only named ancestors, never the filesystem root. A single
failed root listing therefore replaced the previous index with an empty one,
without reaching the five-failure threshold that preserves the whole index.
This is a test-reproduced defect found during source review, not a newly observed
production cache-loss incident. The default configuration and the configured
SYN search root use `/`.

## Changes

- Preserve the filesystem root when normalizing configured cached and live search paths.
- Carry previous entries forward after a failed root listing, preserving fresh
  entries and avoiding duplicates. Named-subtree and clean-crawl behavior remain
  covered by the existing regressions.
- Increment the release version to 3.10.150 and document the audit and validation.

## Remaining risks

- T: has a remembered network mapping, but its host resolves and actively refuses
  SMB TCP 445 (10061); Windows reports the remembered connection unavailable
  (1201). Restoring the host's SMB service/network access must precede reconnecting
  that mapping. A bounded share-root lookup timed out; no authentication failure
  was established in this audit. M: is absent with no remembered mapping (2250),
  so its intended mount target is unknown. SYN resolves but its configured FTP
  TCP port times out before login. Parked downloads and remount attempts remain
  blocked by these dependencies. No alternate destinations were configured.
- Machine-wide ephemeral-port exhaustion from another local process can recur.
  Preserving the search cache does not restore ports or upstream availability.
- Retained cache entries can be stale until a successful refresh. Remote source
  moves, connection resets and service rate limits remain possible.
- Native loopback tests do not cover every remote BNC/CPSV topology. Production
  observation is bounded; no long Relay soak or independent verification of all
  remote file contents is claimed.
