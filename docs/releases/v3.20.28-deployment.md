# GL Drive v3.20.28 deployment review

## Change and reproduction

Four warnings across two downloads showed the FTP governor refusing new logins during an account-wide hold. The download manager charged these local admission refusals against the transfer retry budget. It also showed the later admission deadline in the waiting state while scheduling the actual wake-up on the shorter transfer backoff.

Commit `6b8e1153405bf4dbf85142deda9e22e05be61aed` keeps timed login holds queued, preserves the remaining transfer retries, and schedules the next attempt at or after both the guard deadline and the configured retry interval. Normal login admission applies again when the item returns to the queue. Holds without a deadline retain the existing bounded failure path. A restart rebuilds the runtime download queue and consults the FTP guards again.

The regression uses the download manager's normal processing loop with zero transfer retries. It checks that a refused plan is attempted again only after the guard deadline, completes successfully, and consumes zero retries. The old code immediately marked the download failed.

The first candidate also exposed two failures during segmented-download growth recovery. Windows denied one atomic checkpoint replacement during the first suite. Six isolated repetitions of the existing tests passed, followed by a complete 6,290-test pass. The publication pipeline then caught a separate race in the same test. After EOF detected growth, the supervisor could cancel the transfer before the originating lane recorded its fault. The caller received the growth exception, but the lane recorded cancellation. The pipeline stopped before publishing.

The final candidate, `c91a235dcb2a5f237a69f4467939fc3ca9f6e89e`, preserves the initiating lane's exception and allows short, bounded retries for Windows access and sharing errors during checkpoint replacement. A new test holds the checkpoint open without delete sharing. It failed on the previous commit and checks that the corrected replacement persists the empty list of completed ranges. The original intermittent access denial did not identify the identity of the lock holder. Permanent disk errors still surface.
