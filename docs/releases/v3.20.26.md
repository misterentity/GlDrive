# GL Drive v3.20.26

This release preserves unused FTP sessions when a CPSV operation starts with an
already-cancelled token and makes pending-reply quarantines diagnosable.

- Check cancellation before starting a CPSV sequence. Previously, cancelled
  listing/download/upload operations could mark a session unsafe despite sending
  no command, forcing an unnecessary reconnect. A real FTPS regression verifies
  zero commands, same-session reuse, successful NOOP and unchanged login accounting.
- Keep an existing pending reply unsafe if another cancelled call arrives, and
  retain quarantine for interrupted operations that may have issued commands.
- Add the operation, last recorded phase and caller cancellation status to pending
  quarantine diagnostics. Nested setup preserves the original operation; clean
  completion clears all context. The first explicit fault remains visible.
- Record phases for CPSV listing and file operations, segmented downloads,
  relayed transfers and media reads. This diagnostic context contains no remote
  paths, credentials, reply text or file payload.

The retained production logs contain remote directory-policy refusals, missing
content, idle disconnections, timeouts and PreDB HTTP 503/404 responses. This
release does not change remote permissions or configured routing. The historical
unattributed quarantine cannot be conclusively assigned to the reproduced
cancellation defect; the new diagnostics will support future attribution.

The deployment report records validation, signed release identity, the bounded
production observation and remaining risks after rollout.
