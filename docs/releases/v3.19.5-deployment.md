## Root causes and corrections

**Config synchronization misreported expected cooldowns.** When an enabled server had no mounted service, `SyncAfterConfigChangeCore` described it as a new server and caught `SiteRetryDeferredException` as a general failure. Nightly agent configuration updates consequently produced a warning and stack trace for an existing offline server, despite the retry guard correctly preventing a login. Both the unmounted-server and changed-server branches now report the existing retry deadline at Information level. Unexpected exceptions still produce warnings with their original exception. Retry admission, pending work and cooldown timing are unchanged.

**History confused source display roles with receiver eligibility.** Of 49 Completed race records in the audited pre-release session, two incorrectly had `FilesDelivered=0` and `CleanComplete=false`. In both, the first announcing site was also a legitimate receiver. One was already present; the other received payload and finished with 23/23 files. `RecordHistory` excluded the primary source by its display label, although the engine verified that receiver's completion. History now uses the existing participating-receiver policy and authoritative inventory, shared with destination outcomes. It excludes download-only, affiliated, nonparticipating and unopened fill-only sites. Clean completion requires a Completed result, nonzero inventory, all receivers' expected files, no missing placeholders and the configured completion evidence. Failed/stopped attempts retain their inventory counts without claiming clean completion.

`FilesDelivered` means the **best participating receiver's inventory count, including pre-existing files**; it is not a count of files uploaded by this attempt. `BytesTransferred` retains transfer volume. A full writable source cannot hide a partial peer: all participating receivers must satisfy completion. Live scoring is unchanged. A verified clean history result receives the full terminal score of 65,535; non-clean history retains the existing live score. Existing historical records are preserved without inferred backfill.

## Remaining risks and limits

- **Existing standalone-installer warning:** Inno Setup warns that the administrative installer writes the optional per-user HKCU autostart entry. This is unchanged and also appears in the prior release log. Fresh installation using a different administrator account may target that account; this scenario was not exercised. The signed ZIP/SYSTEM updater used for this deployment does not execute that installer entry. The zero-warning claim above applies to the .NET builds.

- **SITEC FTP remains unavailable.** A three-second TCP-only check at **17:07:20 UTC** timed out. The normal retry ladder continues. The release does not repair the remote host/service.
- **The earlier machine reboot's underlying cause remains unknown.** Application logs and the available Windows events cannot identify it more precisely.
- **Existing configuration notices remain:** example announce rules reference unconfigured `#announce`/`#pre` channels; one Sited destination is outside configured search-index coverage; section-routing proposals remain intentionally frozen pending the owner's decision. These are preserved configuration choices, not changes made by this release.
- **The 56 old queued races expired before this review** under the existing >24-hour restore policy during the long outage. The November 1 restart log records the expiry. They are not claimed as retained by this deployment.
- **Previously incorrect history stays unchanged.** New metrics apply to future records. Consumers must interpret `FilesDelivered` as receiver inventory, not uploaded work; live scoring still uses the existing source-role display model.
- Upstream relocation may still produce bounded recoverable transfer warnings. The observed relocation races recovered without application changes to transfer scheduling.
- The 12.0-minute production watch and disposable native fixtures are bounded checks, not a long-running remote-service soak. The receiving-source correction was reproduced in regression tests; its exact production topology need not recur during this watch. Production rollback was not exercised. Passing tests and a bounded production watch cannot prove all remote endpoints or historical driver/rendering failures are permanently healthy.
