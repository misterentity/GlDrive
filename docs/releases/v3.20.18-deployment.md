## Review coverage and findings

The initial retained-log capture covers **November 8 07:00:01.760 through November
10 16:01:49.043 UTC**: **82,687 records**, including 2,214 Warning and one Error,
with no Fatal. It spans several installed versions. A separate v3.20.17 capture
covers its November 9 23:56:16.928 UTC startup through November 10 16:03:01.866 UTC:
**21,583 records**, 260 Warning and one Error, with 71 failed races, 46 completed
races and 3,874 FXP completions. Two download-completion log messages were present;
they were not independently established as user-download completions.

The review identified and corrected these application defects:

- **Direct FXP TLS roles:** fourteen peer-reported TLS negotiation failures on
  one route are consistent with ordinary CPSV/PASV transfers setting SSCN ON on
  both peers. Local tests prove this code defect; production logs do not establish
  that it was the exclusive cause of every observed failure.
  SSCN chooses the TLS role, independently of TCP active/passive mode. All three
  ordinary direct modes now assign one client and one server, explicitly resetting
  pooled state. A positive SSCN reply is required before direct data commands;
  closing or unexpected replies cannot trigger same-session Relay fallback.
  Successful transfers and clean duplicate skips restore the active peer to
  SSCN OFF for a later local download. Cleanup has a three-second managed bound
  without canceling the native read. Failed, ambiguous or unresolved cleanup
  quarantines the affected session; cleanup failure does not erase delivery
  success or cause the delivered file to be retried. Tests cover actual TLS bytes
  and a subsequent local TLS RETR on the same session in all three direct modes.
- **Disconnected standard listings:** three stacked null-reference warning events
  on v3.20.17, and 18 across retained versions. FluentFTP 53 retries a failed LIST
  using cached TYPE state, then dereferences a disconnected stream's missing local
  endpoint. GL Drive preserves that exception as the inner cause of an IO failure.
  Spread scans now quarantine all unsafe failures after borrowing a session;
  clean final protocol rejections remain reusable and caller cancellation retains
  its meaning. Login admission, native deferred disposal and library reconnect
  restrictions remain enabled.
- **Dated mapping discovery:** destination routing supported explicit `{MMDD}`
  mapping paths, but source discovery and relocation did not probe those paths
  when absent from the section dictionary. Both now include the first enabled,
  trigger-matching mapping as an advisory candidate. Existence still must be
  confirmed. Date folders use invariant Gregorian formatting in UTC.
- **Metadata request amplification:** an enabled filter with no thresholds made
  requests, and music/software were guessed to be movies. Those requests are now
  skipped; trusted exact sitebot facts retain precedence. Search and detail calls
  share a serialized, one-minute provider retry delay after failure. Healthy
  fallback and changed API keys can recover, and caller cancellation no longer
  launches fallback or counts as provider failure.
- **Native smoke drift:** v3.20.17 changed the monitor to PWD, but the fixture still
  rejected NOOP. The fixture now verifies one stale session recovers without a
  false outage, four rejected probes delay recovery until a positive reply, and
  native session/login accounting stays balanced. A real interrupted GnuTLS LIST
  reproduces the library null dereference and verifies fresh-login recovery.

The pinned upstream implementation is documented in
[OpenDataStream](https://github.com/robinrodricks/FluentFTP/blob/074f222240ad8e1db7768697db0a4d0a6c3a92cf/FluentFTP/Client/AsyncClient/OpenDataStream.cs)
and [GetListing](https://github.com/robinrodricks/FluentFTP/blob/074f222240ad8e1db7768697db0a4d0a6c3a92cf/FluentFTP/Client/AsyncClient/GetListing.cs).
The inference from production stacks was verified with managed loopback and actual
GnuTLS fixtures; no production disconnect was induced.

Pinned primary protocol references establish [SSCN ON as TLS client and OFF as
server](https://github.com/proftpd/proftpd/blob/c796c56f2387405a2ee50f65828f4ac0f2549fe4/contrib/mod_tls.c#L13163-L13169)
and [client-mode TLS connection behavior](https://github.com/proftpd/proftpd/blob/c796c56f2387405a2ee50f65828f4ac0f2549fe4/contrib/mod_tls.c#L11842-L11848).
[cbftp resets an inherited SSCN ON before a local encrypted transfer](https://github.com/peps1/cbftp/blob/869354159a19d7cedac68399a876b39f803ff5c5/src/sitelogic.cpp#L1266-L1281).
The pinned [FluentFTP passive data path](https://github.com/robinrodricks/FluentFTP/blob/074f222240ad8e1db7768697db0a4d0a6c3a92cf/FluentFTP/Client/AsyncClient/OpenPassiveDataStream.cs#L133-L141)
initiates local TLS without resetting that persistent SSCN role, explaining why
GL Drive must restore it before returning a reusable session.

preceding offline/invalid tracker replies. The failed item is retained. The free
IMDb endpoint returned NXDOMAIN in live DNS checks, including 16:13:19 UTC; the
release bounds retry pressure but cannot restore the external provider. PreDB's
existing backoff handled seven request failures, and an unavailable Plex watchlist
request retained existing entries.

One FTP site disconnected at **06:01:53.822 UTC** after `530 Goodbye`. The app's
"credentials rejected" text is a classifier result, not proof of an incorrect
password. Later observed slow probes timed out in TCP ConnectAsync. The existing
authentication circuit retains its hold during transport-failed recovery probes;
no manual credential reset or retry-guard override was performed. Other three FTP sites, all enabled IRC
sessions, authenticated API, unauthenticated 401 rejection and heartbeat passed
the initial checks. Windows Application-event queries found no matching current

## Limits and remaining risks

- Remote account/site availability, permissions, disk capacity, missing content,
  mapping decisions and provider DNS require external action. No access policy,
  credential, production queue or failed item was removed to improve results.
- The provider outage delay may postpone the next recovery attempt by up to one
  minute; filtering continues to fail open when metadata is unavailable.
- Native fixtures exercise local FTPS/WinFsp/CPSV paths; they do not reproduce
  every remote glftpd/BNC configuration. UI screenshots use isolated demo data.
  All four enabled production sites had drive mounting disabled at the
  17:28:44 UTC coverage check, so a live drive-letter read was not applicable.
  WinFsp behavior was exercised with isolated native mounts; no production
  configuration was changed to manufacture drive-letter coverage.
- Peers without usable SSCN support now fail closed for ordinary direct FXP
  because the required TLS roles cannot be confirmed. This compatibility risk is
  explicit; encrypted data protection and certificate trust were not weakened.
- Site 3 FTP remains unavailable. Its enabled IRC session recovered after restart.
  Production health remains degraded despite successful installation and the
  other smoke checks.
- The preserved maintenance-paused race is eligible in the restored queue under
  existing priorities; immediate execution or completion has not been observed.
- Bounded log retention checks cannot prove logger emission or long-term uptime.
  Production API/heartbeat and Windows-event checks provide independent evidence.
- Live destructive remote tests, alternate-administrator installation and rollback
  are outside this verification. Recovery inventories are checked without rolling back.
