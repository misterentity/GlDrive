## Log review and fixes

The authoritative baseline covers **2026-11-11 16:51:25.051429 through
2026-11-12 16:02:33.616808**, across versions 3.20.19–3.20.22. It contains
**25,529 records: 24,936 Information, 592 Warning, zero Error and one Fatal**.
Every Warning/Fatal record was classified; independent recount and retained-prefix
hash checks passed. The bounded Windows Application event query succeeded with no
matching events. An initial capture with a future endpoint was explicitly
superseded; it is not acceptance evidence.

Three application defects were reproduced and fixed in v3.20.23. A fourth defect,
found during startup verification, is addressed by v3.20.24 later in this report.

1. **Fullscreen teardown reentered itself.** `Window.Close()` synchronously
   invoked `Closed`, which called the exit routine again before its active-window
   reference was cleared. The second insertion of the same video view raised
   `ArgumentException`. The reference is now cleared before reparenting and close;
   dashboard closure also exits fullscreen before player disposal. The production
   event at 01:58:22.663 on 3.20.19 was handled by the dispatcher exception handler;
   subsequent activity proves that it was not a process termination.
2. **Automatic source searches cancelled healthy commands.** The first source
   result and each per-site search budget hard-cancelled outstanding LIST/SITE
   commands, correctly forcing their sessions into quarantine but needlessly
   consuming new logins. Both now stop traversal between commands. Issued commands
   drain under the existing 90-second hard search deadline; explicit caller
   cancellation still interrupts them. Tests cover first-result latency, budget
   expiry, late matches, explicit cancellation, source policies and hard deadlines.
3. **Clean relay directory refusals left pending-reply markers.** Relay setup
   opened both CPSV sockets before the deferred directory callback. A clean refusal
   before RETR/STOR left both sessions marked for discard. The directory walker now
   retains a typed final reply, and only that proven rejection in the pre-transfer
   phase clears the markers. Interrupted, closing, malformed, preliminary and
   ambiguous replies retain quarantine. Directory walking also stops immediately
   on unsafe replies so a later refusal cannot falsely establish synchronization.

The baseline has **312 search-LIST cancellation records**, **988 pending-sequence
discard records**, and **243 request-source misses**. These are records, not
independent incidents; the evidence does not attribute every login denial to one
mechanism. A read-only live listing failed during review with the exact
`FtpLoginHeldException` new-login-budget exhaustion path, independently confirmed
from the in-memory flight recorder despite a previously healthy connectivity
snapshot.

Other classified outcomes include 145 remote mkdir-policy failed jobs, 34
inconclusive-source failed jobs with separate summaries, one no-activity failure,
three informational partial-index outcomes, reconnect/admission holds, idle 421
closures, remote login-cap refusals, transport resets, relocated/missing content,

launch. Existing backoff, quarantine, retry and permission boundaries were retained.
The full baseline also records 5,607 FXP file completions and 221 completed races.

## Remaining risks and limits

- Remote directory policies, content movement, remote resets and idle timeouts
  remain possible. Client fixes prevent unnecessary session loss; they do not grant
  remote permissions or establish every server-side cause.
- Six existing announce-channel configuration warnings and four informational
  frozen-agent notices require operator intent. No mappings, channels, credentials,
  remote permissions, freezes or login limits were changed to silence them.
- Source-search traversal budgets can expire while an issued command drains to
  the existing hard deadline. Truly stalled commands still require quarantine.
- One pre-publication regression run unexpectedly redownloaded a canceled file
  from offset zero. Its exact cause remains unconfirmed despite passing focused
  and class-wide repetitions. New checkpoint assertions improve future diagnosis;
  they do not fix an established production defect.
- A separate pre-publication native-keyboard test intermittently failed to invoke
  its filter command despite delivered key events. Ten focused reruns passed, but
  the precise historical focus/capture/input state is unavailable. The failure was
  retained and no test was weakened or disabled.
- The optional autostart task in the standalone EXE installer writes to HKCU.
  When elevation uses another administrator's credentials, it can target that
  account instead of the intended user. The signed ZIP updater used for this
  deployment does not execute those installer registry sections. For a manual
  EXE installation under another account, leave autostart unchecked and configure
  it in the intended user's context. A durable installer fix needs separate-account
  coverage; see [Inno's privilege documentation](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)
  and [administrative install mode](https://jrsoftware.org/is6help/topic_admininstallmode.htm).
- Two separate request-fill edge cases found in source review remain follow-up
  work: promotion of an ordinary queued race can apply request exemptions to extra
  participants, and general directory creation can recreate a vanished REQUEST
  ancestor. Neither was established as the cause of a captured production failure;
  their behavior and remediation require dedicated regression coverage.
- Native fixtures cannot reproduce every glftpd/BNC setup. UI smoke uses isolated
  demo data and the documented headless rendering override. No destructive remote
  write, media playback or rollback execution test is claimed. Backup verification
  is not a rollback. Readiness snapshots and monitoring are bounded observations.

Existing unrelated user work is preserved; before/after hashes cover all six files.
