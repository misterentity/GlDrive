# GL Drive v3.11.18 — runtime and development efficiency

Closing a dashboard now cancels its owned disk poll and prevents late callbacks
from restarting timers or adding download subscriptions. The poll drains its real
FTP operation before releasing its lifetime resources; connection ownership and
native quarantine rules are unchanged.

Notification arrivals update only the inserted and evicted rows. A burst of 100
arrivals at the 5,000-row limit now produces 200 collection changes while preserving
grid selection, instead of rebuilding the collection for every arrival. Wishlist
imports deduplicate the whole batch and perform one ordered secure save. A failed
batch save leaves the live wishlist and imported IDs unchanged.

Download capacity limits are shared by Settings and automation: 1–5 concurrent
downloads and 1–32 HTTP lanes per network. API values outside those supported
ranges are rejected before any configuration is saved. Existing manually stored
download concurrency is not silently rewritten. Section blacklist, extraction
abandonment and network-usage persistence reuse the existing secure atomic writer.
Shared release-name predicates retain the different download and spreading rules.

Pure parsing and policies now live in a dependency-free `GlDrive.Core` project,
with a separate test graph and Linux CI job. Existing public type names are
forwarded by the desktop assembly. The initial Core test output is 4.44 MiB versus
225.71 MiB for the previous full Windows test output; the full Windows/native
verification remains required. Two unused Configuration package references and
nine unused resolved dependencies were removed. New health events omit the
unmeasured `errors5xx` field; historical values remain readable.

Render checks own unique output directories and publish a manifest only after all
recorded images pass inventory and hash verification. Failed renders retain their
evidence without claiming completion. Release scripts restore and build the test
graph once, run all three suites without rebuilding, and separately restore the
self-contained publish graph. Packaging-only reuse now verifies source, commit,
SDK, build properties and every payload hash. UTF-8 filenames and invocation from
another working directory are covered.

See the [development guide](../development-guide.md) for the smaller test workflow
and the [deployment report](v3.11.18-deployment.md) for validation, signed assets,
production monitoring and remaining risks.
