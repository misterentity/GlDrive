## Finding and root cause

**Every FTP connection teardown leaked its native GnuTLS session and certificate credentials.**

- Signal: `last-heartbeat.json` reported `WorkingSetMb: 1040` after 51 h of uptime, against
  202–334 MB at 1–2 h on the same version. Nothing in the logs pointed at it.
- `dotnet-counters`: GC committed 193 MB (live 100 MB), working set 1,091 MB. `dotnet-gcdump`:
  5 `AsyncFtpClient`, 5 `GnuTlsInternalStream`, 17 sockets alive — no managed leak. A
  `VirtualQueryEx` scan of the live process: 899 MB private committed, 662 MB of it in 2,387
  regions of 64 KB–1 MB laid out as 16 MB heap segments — native malloc.
- Growth was event-driven, not time-driven: private bytes were flat across idle minutes with no
  teardowns, and the window held 293 connections against ~680 MB of growth (≈2.3 MB each).
- Decompiled FluentFTP.GnuTLS 1.0.38: each control connection allocates `CertificateCredentials`
  and imports the whole Windows trust store into it (~150 certificates, parsed), plus a session;
  only `GnuTlsInternalStream.Dispose` frees them, and FluentFTP reaches that only through
  `FtpSocketStream.m_customStream`.
- `FtpConnectionPool.NeutralizeGnuTls` (the v3.5.1 crash guard) nulled `m_customStream` and
  dropped the wrapper, with a comment calling the resulting leak "small + bounded". Every
  teardown path — the quarantine funnel and both disconnect paths — ran through it.

## Changes

- `NeutralizeGnuTls` now returns the detached `IFtpStream`; new `FreeDetachedGnuTls` disposes it.
- The quarantine funnel frees the detached wrapper after `client.Dispose()` on its deferred task
  (after the 20 s recv-drain window). `SerializedGnuTlsStream.Dispose` additionally serializes
  the free against any in-flight recv, which is what makes freeing safe now and was not true in
  v3.5.1. With `IsSessionUsable` already false the library skips `gnutls_bye` and only runs
  `gnutls_deinit` + `gnutls_certificate_free_credentials`.
- `DisconnectAndDispose` / `SafeDisconnectAndDispose` free the detached wrapper after dispose.
- `AbandonedReclaimDelay` is an internal overridable so the funnel is testable in milliseconds.
