# GL Drive v3.13.0

Feature-gap roadmap, Phase B batch 1. Codex implemented it and Claude reviewed it. Full suite: 3,371 tests (3,298 app, 53 core, 20 MCP), 0 failures.

## Race queue: shortest-work-first with ageing (on by default)

- The single race slot is now assigned by **highest response ratio**: how long a release has waited, measured against how long it is predicted to take. Predictions use announced sizes, falling back to per-section and per-resolution medians. A five-second dupe check no longer waits behind an eight-minute 2160p fill. In a synthetic replay, the median queue wait fell from 2,469 s to 687 s.
- The policy never pre-empts a running race. Phase A priority classes still apply: partial cleanup first, then fresh releases, then resumes.
- Any release queued longer than `spread.raceQueueMaxAgeMinutes` (default 120) goes ahead oldest-first, so nothing starves.
- **Announce merge:** when the same release is announced twice (for example a destination's NEW line a few milliseconds before the real source's), the second announce's source hint now merges into the queued or active race. Before, it was dropped. A hint can never re-admit a site that source rules or filters excluded. Paths in dated trees are never guessed.
- Settings: `spread.sizeAwareRaceQueue` and `spread.mergeRaceAnnounces` (both on by default) and `spread.raceQueueMaxAgeMinutes`.

## Scored quality profiles (opt-in)

- Wishlist items can use a **scored profile** that weighs source tier, resolution, HDR, untouched vs encode, edition, PROPER/REPACK and size band.
  - A profile has a floor and a cutoff.
  - The wishlist grabs a copy only when it beats the best copy already grabbed.
  - It reserves pending copies, so two sites can't grab the same title at once.
  - The item completes when it reaches the cutoff. A PROPER/REPACK can optionally still upgrade it after that.
- Off by default (`downloads.scoredQualityEnabled`), so existing grabs behave exactly as before. With it on, existing resolution-only items get an equivalent built-in profile. Custom profiles live in `downloads.profiles`.

## Sitebot events (opt-in, zero extra FTP traffic)

- Lines from bots you mark as trusted on a channel are decoded into typed events: NEW, completion with size and file count, HALFWAY, RACE, NUKE/UNNUKE and TV metadata. Set `irc.channels[].sitebot`: `botNick`, an optional `userHostPattern`, and templates.
- Announced sizes feed the queue's work estimates. Race history records verified per-destination outcomes. A new MCP tool, `spread.report`, gives a daily race report.
- Using bot completion and metadata to make decisions stays off until you enable it (`spread.useSitebotCompletionHints`, `spread.useSitebotMetadata`). Even then, bot hints only accompany listing verification that is already scheduled.
