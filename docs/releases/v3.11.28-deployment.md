## Changes

1. **GnuTLS send on a dead connection** (`Ftp/SerializedGnuTlsStream.cs`, `Ftp/FtpConnectionPool.cs`). The failure is now an `IOException` that names the GnuTLS error, and the session is marked unusable. Before, FluentFTP.GnuTLS 1.0.38 threw `ArgumentOutOfRangeException: sourceIndex ('-53')` and left the session flagged usable.
2. **Disk writes excluded from the 90 s download stall clock** (`Downloads/Segmented/SegmentedTransfer.cs`). Writes of 10 s or more are logged as disk saturation. A stalled open now reports `Could not open <file> within 90s`.
3. **Bounded main-pool re-borrow with backoff** (`Downloads/Segmented/FtpLane.cs`). The wait is capped at 45 s, then the lane backs off with `LaneBackoffException` instead of being retired.

## Remaining risks

- **The fixed paths have not run in production yet.** The observation window had no downloads, network resets or lane faults. Coverage so far comes from unit tests. Watch for `GnuTLS send failed:`, `local disk write took`, `no free login on the pool` and `Could not open`.
- **The SMR-disk cause is strongly supported but not proven.** Both stalls happened only while two extractions overlapped downloads on E: (ST8000DM004). The new `disk write took` line will confirm or rule it out. If it confirms, reducing concurrent extractions/downloads on E: is a configuration decision for the owner.
- **Read-side GnuTLS failures (`GnuTlsException`, e.g. `PULL_ERROR`) are still not `IOException`s.** The `IOException`-based classifiers (spread scan poisoning, search transient retry) still miss them. The pool's borrow-time NOOP probe catches the dead connection, at the cost of one probe. Not changed in this release.
- SYN FTP host down, PreDB API instability and the Verbose logging level are unchanged and outside this release.
