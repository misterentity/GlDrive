# GL Drive v3.15.1

Reliability fixes from the October 28 production log review and regression pass.

- **Background remounts respect account holds.** An expired site-health deadline
  could cause a failed mount to be attempted every second while the login governor
  still held the account. Remount scheduling now retains the latest applicable
  admission deadline and bounded retry delay. It also handles deferred TCP probes,
  missing or stale deadlines, endpoint changes, and disabled health supervision.
  Manual recovery remains available, and local admission refusals do not count as
  new remote outages.
- **Later settings edits take precedence over timed changes immediately.** A user
  could change a leased setting away and back between timer ticks, allowing the
  old lease to revert the user's choice later. Successful configuration saves now
  relinquish lease ownership immediately, including raw settings saves. Lease-owned
  writes and unrelated edits retain their existing behavior.
- **Native smoke tests isolate their state.** ReleaseCheck now uses its own
  application-state directory and an explicit budget for its shared synthetic
  account. A separate native FTPS scenario verifies that the production default
  admits seven ordinary logins, reserves the recovery slot, rejects the next login
  before authentication, and still allows existing-session reuse.

The deployment report records build/regression/native/UI checks, signed package
verification, production observation, and remaining external service limitations.
The operational correction to Zephyr's notification watch path is local
configuration, not a change to other installations' defaults.
