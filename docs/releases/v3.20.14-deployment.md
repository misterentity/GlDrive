## Findings and changes

Review began with installed v3.20.13. Its 24 retained log chunks cover November 6
**12:33:01.420–16:01:21.957 UTC**: **1,580,407 records**, zero Warning/Error/Fatal
entries and no failed operation outcomes at lower severity. They include 565 FXP
completions and 23 completed races. A further pre-release audit through
**16:22:33.145730 UTC** covers 287,992 records, 54 FXP completions and three completed
races, also without warnings, errors or failed outcomes.

Historical review since November 5 **16:53:25 UTC** examined census records,
incident capsules, telemetry, persisted outcomes, updater records and Windows
events. All 213 retained recent race outcomes were clean; telemetry reports 12
completed downloads and no failed download outcomes. Earlier sampled connection,
source-relocation and lane-retry failures recovered. No matching application crash
or storage-provider fault was found. Local writes lasting 18 and 30 seconds remain
evidence of storage latency, not proof of a specific hardware fault. Stale failed
queues from June/July and legacy March state were preserved.

Independent code review nevertheless **reproduced a v3.20.13 capacity regression**:
after discovering a 4,096-byte unpacked payload in a 93-byte RAR, a managed decoder
failure replaced the known reservation with compressed size. With only 1,000 bytes
free, external extraction could start and later retain 93 bytes as its disk-full
recovery threshold. That allowed retries before sufficient space returned. This
was reproduced against the installed binary; it was not a new failure observed in
today's clean production logs.

The fallback now reserves the larger of the known unpacked requirement and archive
volume size. Capacity loss parks work before external-tool invocation, and a later
disk-full failure retains the correct recovery threshold. Regression checks cover
preserved archives/output, reservation cleanup and capacity recovery. Both new
tests failed before correction; **102 targeted tests passed afterward**. Independent
review found no blocker. README version and release/changelog documentation were
updated.

Private deployment helpers were also corrected: signature verification uses the
public key's current source location; monitoring rejects empty logs or coverage
missing more than 60 seconds at either observation boundary; installation
acceptance requires fresh task results, the correct receipt
lineage and matching payload counts. Five log-coverage fixtures passed. These
helpers are local evidence tooling, not application changes.

## Remaining risks

- The remote FTP outage and physical capacity/storage latency are environmental
  dependencies. This release task did not change credentials, TLS, routing or user
  destinations, and preserved the concurrent settings edit.
- When managed discovery never determines unpacked size, external fallback still
  uses archive volume size as an estimate. Other processes can consume capacity
  after admission. This patch preserves known requirements; it does not acquire
  an external tool's full size manifest or eliminate every possible disk-full event.
- Verbose logging had shortened detailed retention to about 3.47 hours at initial
  review; the later Settings save changed it to Information. Older census
  and capsule evidence is sampled and reports drops; it cannot prove an exhaustive
  overnight absence of errors.
- Initial standing diagnostics included six unavailable announce-channel warnings,
  one index-coverage warning, Verbose logging and four pending frozen decisions.
  The remote FTP exception is also retained in diagnostics.
- Bounded monitoring cannot establish long-term uptime. No production disk
  exhaustion, live rollback or alternate-administrator installation was induced.
