# GL Drive v3.11.28

Fixes three defects found in a sweep of the v3.11.27 production logs
(2026-10-22 10:28–20:01, 361k lines, 0 Error/Fatal, 69 warnings).

**Dead connections reported as argument errors.** At 13:17:18 every remote
connection was reset at once (a local network blip). SITE INVITE, the
NewReleaseMonitor LIST and ConnectionMonitor then failed with
`ArgumentOutOfRangeException: sourceIndex ('-53')`. FluentFTP.GnuTLS 1.0.38
`GnuTlsInternalStream.Write` exits its retry loop holding a fatal
`gnutls_record_send` result and uses it as an array index. The throw also skips
the library's `IsSessionUsable = false`. `SerializedGnuTlsStream` now converts
this case to an `IOException` naming the GnuTLS error, so the transport
classifiers that match `IOException` see it. It also marks the session unusable
so the pool health check and teardown treat it as dead. Everything recovered
within 25 s, both before and after this fix.

**Disk saturation reported as network stalls.** At 16:47:32 and 16:54:06, both
lanes of a download hit `No data for 90s` at the same moment. Both times, two
~6 GB extractions were writing to the same SMR disk (E:). A single concurrent
extraction at 19:21 caused no stall. The stall watcher counted time blocked in
a local disk write as network silence and dropped working connections. Disk
writes are now excluded from the stall clock, as pacer waits already were. Any
write that takes 10 s or longer is logged, so the next occurrence leaves direct
evidence.

**Queueing for a login reported as a lane failure.** After that stall, the
download's main lane re-borrowed from zephyr's pool. The next queued download
had just taken the pool's only login. The re-borrow waited until the 90 s watcher
cancelled it, twice, and the lane was "retired after 3 consecutive failures: The
operation was canceled." A re-borrow now waits at most 45 s, then backs off and
retries without counting a failure. A genuinely stalled open now reports
`Could not open <file> within 90s` instead of a bare cancellation.

Build, regression, smoke and production observation results are recorded in the
[deployment report](https://github.com/misterentity/GlDrive/blob/master/docs/releases/v3.11.28-deployment.md).
