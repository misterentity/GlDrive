# v3.11.11 — industrial terminal UI and source recovery lifecycle

The Cyberpunk theme now follows an industrial hacker-terminal direction: graphite
surfaces, monospace typography, restrained mint/lime accents and sharp controls.
Bright color marks actions and live state; release names and ordinary text use
neutral foregrounds. Scanlines and glow are reduced, and repeated decorative
corner frames are removed from the dashboard.

The overview uses compact connection/throughput panels, a horizontal health strip
and a full-width operations journal. Race cards, download rows, navigation and
settings forms fit more information with less padding. Streams settings have
aligned controls and explanations; MCP setup retains selectable, wrapping
configuration and reachable actions at minimum window size. Disabled primary
buttons are visibly inactive, scrollbars have distinct hover/drag states, and
disclosure controls use a simple keyboard-accessible chevron. Dark and Light
retain their own palettes and input corner defaults.

## Source recovery

Source-relocation probes could keep borrowing FTP connections after their race
completed or parked, then modify a race whose cleanup and history had already run.
The v3.11.10 lifetime fix covered directory scans and SFV reads, but omitted the
two fire-and-forget migration paths. This release tracks migration work, closes
admission when the race exits, and drains commands already in progress. Pending
borrows and later commands stop; late relocation and alternate-source results
cannot register another source. Alternate-source searches carry separate stop
and command tokens, preserving ordinary cancellation and time limits.

Migration diagnostics now include the release so future audits can attribute
delayed operations directly. The production audit found repeated migration
messages roughly 49 seconds after completed-race events, but the old messages
omitted the release; this timing supports the investigation without proving
individual attribution. Behavioral tests reproduce the underlying defect through
real loopback FTP commands and the actual race-finalization path.

## Log audit

At 2026-10-15 17:06:55 UTC, the installed v3.11.10 process had 9,043 records:
68 warnings and zero errors or fatals. All 29,184 warnings, one error and two
fatals in 63,431 retained records were classified.

- Historical disposed-pool/remount errors, invalid initial-directory crashes,
  updater rollback failures and statistics-borrow timeouts have fixes in the
  inherited release history and no recurrence in the current process.
- Eighteen source-file `RETR 550` attempts produced 36 paired warnings. One
  affected release later completed; another is durably parked for 13 source
  files. No recovery of those missing files is claimed.
- Thirteen archive warnings describe an unchanged three-part input with twelve
  missing volumes and bounded retry abandonment. These are missing inputs,
  distinct from the two older persisted skipped archives.
- Seventeen mount warnings concern SYN. A fresh DNS lookup succeeded, while a
  single five-second TCP probe timed out before authentication. The exact remote
  server, firewall or route fault remains unconfirmed.
- One AI-provider HTTP 429 and one 300-second timeout recovered through bounded
  retries, ending successfully at 11:11:29 UTC.
- No new application crashdump or relevant Windows application fault was found.

Before changes, the process recorded 1,228 successful transfers, approximately
337.8 GB of reported bytes and 85 completed races. Transfer telemetry does not
substitute for remote-content checksum verification.

## Remaining risks

SYN transport availability, missing remote files and local archive volumes remain
external/input conditions. D: had approximately 272.5 GiB free (3.66%) at the
baseline audit; T: was absent, with no current missing-drive download park.
No files or queues were deleted to hide these conditions. Retained old MCP
binaries are permitted only when their signed-release bytes and live mapped
owners are verified. Native smoke tests use disposable loopback FTPS fixtures;
UI rendering uses demo data, and production observation is finite. These checks
do not cover every remote BNC/CPSV behavior or reproduce old hardware/render faults.
