# GL Drive v3.11.32 — log review and production verification, 2026-10-27

## Outcome and release decision

No new application defect was established. The current signed **v3.11.32**
release remains installed and healthy on the two available FTP sites. No
application source, version, server configuration, or remote content was changed.
No new release was published and no application restart was performed during this
review: the requested deployment was already present, and publishing unchanged
binaries under a new version would not address the external failures found.

One operational cleanup was completed through the existing fixed
`GlDrive Update Cleanup` task. It removed **42 obsolete backup files**, reducing
the retained count from 84 to 42. The remaining 42 files (37,046,912 bytes) are
mapped by six existing MCP clients whose parent Claude processes are still alive.
Windows `GetMappedFileName` confirmed their actual backup mappings. Those clients
were left running; the cleanup task correctly retains result 1 while files remain.
After those MCP sessions close or reconnect, the standard cleanup task can reclaim
the remaining generation. The installed payload itself is intact.

This supplements [the original deployment record](v3.11.32-deployment.md) and
[release notes](v3.11.32.md).

The Windows Application critical/error/warning query succeeded with zero matching
GL Drive events. The newest retained crash dump predates this release.

Every current-release warning was classified:

- **17 SYN mount/remount warnings:** TCP establishment times out before
  authentication, consistent with the documented external FTP outage. Bounded
  retries remain active. SYN IRC is independently connected.
- **11 PreDB warnings:** nine HTTP 503 responses and two 15-second timeouts.
  Backoff worked; a read-only provider probe at 17:05:12 UTC returned HTTP 200,
  success, and 20 records. This verifies recovery at probe time only.
- **Four warning lines for two RETR 550 operations, plus one relocation warning:**
  the source moved a release from `/incoming` to `/recent`. The probe followed the
  new path within 0.244 seconds of the first rejection; the race completed with
  24/24 delivered and `CleanComplete=true`.
- **Two warning lines for one RETR 550:** an unexpected file really existed inside
  another source release, as proved by an earlier accepted RETR and completed
  transfer. It subsequently disappeared; the next scan pruned it and the race
  completed. The later transfer from its correct release directory also completed.
  Client listing contamination was ruled out; why the source created/removed that
  entry is not observable from client logs.

Debug-level failures were also traced. Five SFV cancellations occurred at or within
one millisecond of race completion, before obtaining a connection. One LIST reply
timeout activated pending-reply quarantine; reconnection succeeded and the race
completed. Three direct route probes quarantined their endpoints and recovered
through relay. Config reload safely quarantined its interrupted read. None
established an unhandled failure or unsafe connection reuse.

The current release completed **1,202 FXP transfers and all 66 unique races** in
the audit window. There were 67 start lines because one race safely requeued while
waiting for final files. The three `SITE DISKFREE` requests were each suppressed
after one unsupported reply per mount; a config reload explains the third mount.
The v3.11.32 fix is still effective in production.

Older retained warnings include recovered BNC and SYN IRC outages, provider
throttling, tracker failures, and a torrent metadata timeout followed by a scheduled
retry. That particular torrent's completion was not established by the audit.
Two native disposal warnings during the older BNC stall used the safe retained
session path, avoiding disposal beneath an active native read.

## Remaining risks and follow-up

- SYN FTP is unavailable externally; all three IRC services and the other two FTP
  sites are healthy. No server setting was changed to conceal the outage.
- PreDB, BNC, torrent trackers and model providers can still fail or throttle;
  the observed recoveries do not establish continuous external availability.
- Forty-two old MCP backups remain locked by six existing client sessions.
  Reconnect/close those sessions normally, then run the standard cleanup task.
  They are not installed-payload mismatches and do not block the current release.
- Native fixtures do not implement a complete remote glftpd/BNC server-to-server
  race. Historical current-release production activity supplies real FXP evidence;
  a short health window is not a sustained failure/recovery soak.
- Verbose production logging continues to produce high volume; this review is
  bounded by the retained files. No logging preference was changed.
- Production Windows drive mounting is disabled in the existing configuration;
  mounted-file regression coverage comes from the isolated WinFsp fixture.

Sanitized audit results, TRX, build logs, native assertions, UI manifests,
published/installed/provenance verification, mapped-backup evidence and production
samples are retained under `.release-tools/review-20261027/`. Private raw source
file context and local configuration were not added to Git. Existing unrelated
