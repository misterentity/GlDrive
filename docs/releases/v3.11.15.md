# v3.11.15 — Torrent discovery and downloads across selected networks

Source validation is complete. Packaged release and production results will be
recorded after the standard pipeline and guarded update finish.

Torrent discovery now corrects four defects in the pinned MonoTorrent library
without changing the dependency version. Returned Offline/InvalidResponse
announces trigger fallback instead of being counted as success and skipping
healthy trackers. Successful responses retain their advertised retry intervals;
the library previously left its stored announce response at constructor defaults.
UDP announces now encode None=0, Completed=1, Started=2 and Stopped=3, while
preserving the engine's original lifecycle event and HTTP/HTTPS behavior. The
UDP response's advertised interval also governs ordinary retries, correcting a
parser assignment that otherwise left those retries at 30 minutes. The UDP
mapping and schedule follow [BEP 15](https://www.bittorrent.org/beps/bep_0015.html).
New tracker failure logs contain scheme and status, not URLs, tokens or server messages.
Cancellation drains an in-flight request before returning; the pinned UDP
transport can still take its timeout to finish.

Queued torrents can use the engine's full connection budget: currently 100
connections across that engine, with up to 16 connection attempts in flight.
The library's default previously imposed a hidden 60-peer limit on each torrent.
Download rows show waiting/connecting activity and discovered candidate counts
alongside connected seeds and peers. Candidate counts describe discovery state,
not a guarantee that those peers are reachable or providing content.

New outgoing torrent peer connections rotate across the selected download
adapters, allowing Ethernet and Wi-Fi to carry different peer connections.
Addresses are resolved again for each connection. When more than one eligible
path exists, a failed attempt gives another path a chance after at most three
seconds. Explicit IPv4 selections do not fall through to an unbound IPv6 route.
Received bytes on these outgoing connections use the existing shared download
pacer and per-network usage ledger, including peer protocol traffic. Allowance
checks read current settings, so replacing a network's configuration affects
established connections instead of retaining an old allowance value.

Standard PASV FTP data connections now bind to the lane's selected adapter,
matching the existing CPSV path. The bind setting is scoped to data-stream
creation and restored even after setup failure or cancellation. Existing control
sessions, login caps, reserved race capacity and CPSV yield/cleanup rules remain
authoritative; using two networks does not create extra FTP login permits.

The original live torrent completed on the installed v3.11.14 at
**2026-10-15 21:49:19 UTC**, with **5,687,339,410 of 5,687,339,410 bytes** reported
complete and no download error. An item-level pause/resume restored discovery
before these permanent fixes were deployed. During the initial stall, metadata
was present but connected, available and connecting peer counts were zero.
The observed tracker state was consistent with the reproduced fallback defect,
but this library overwrites announce diagnostics during scrapes, so the exact
historical announce response cannot be established. Four of five trackers
answered independent scrape requests; that evidence did not support assuming
an empty swarm. DHT had not bootstrapped, and its configured bootstrap endpoint
timed out in one isolated ping probe. This does not establish a specific VPN or
firewall cause, and this release does not change DHT bootstrap behavior.

Validation covers returned and thrown tracker failures, cancellation, response
intervals, all four UDP event bytes, HTTP/HTTPS preservation and private-data
exclusion. Real local UDP tracker tests exercise metadata-to-content handoff and
fallback without injecting peer addresses. An isolated eight-peer transfer
received exactly 2 MiB from each peer, observed all eight transmitting within
one sample, and verified the complete 16 MiB file by SHA-256. Network tests cover
binding, alternate-path selection, cancellation, pacing, usage and allowance
changes. Native CPSV tests exercise simultaneous main/borrowed lanes, byte
integrity, race yielding and synchronized control-session reuse. Same-host
source-address checks prove socket binding. A separate external check used the
actual torrent peer factory for two concurrent, normally validated HTTPS
downloads: exactly 1 MiB through Ethernet and 1 MiB through Wi-Fi, with actual
socket source addresses matched to their selected adapters. Both sockets closed
and each route's isolated ledger recorded its traffic. This verifies external
connectivity through both adapters, without establishing independent WAN capacity.

Full-suite validation also exposed an existing search test that raced a 20 ms
caller-cancellation timer against an 80 ms internal deadline. Its cancellation
half now explicitly cancels an active listing with a bounded cleanup path; the
deadline/partial-results assertions remain intact. No search behavior was changed.

Incoming torrent peers retain the native listener path and engine rate cap;
they do not use the new outgoing-connection per-network pacer or ledger. This
release therefore does not claim complete combined FTP/torrent rate or allowance
accounting for every torrent connection. Tracker and DNS traffic are not bound
to the selected peer adapters. An explicit torrent VPN preference takes precedence
over ordinary download adapters when available; a missing adapter retains the
warning-and-default-route policy, not a VPN kill switch. Existing connections
are not migrated, and changing listener/DHT bindings requires service recreation.
Parallel peers and two selected adapters do not guarantee additive WAN bandwidth,
a particular download speed, or saturation of 100 peer connections. Performance
still depends on routing, the swarm and peers' upload capacity.
