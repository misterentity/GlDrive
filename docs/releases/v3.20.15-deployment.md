# GL Drive v3.20.15 — log review and deployment

[v3.20.15](https://github.com/misterentity/GlDrive/releases/tag/v3.20.15) is published
and installed from commit `5672149c34072690eab4573c0413d077eb29f466`.
Build, regression, native/UI smoke, package integrity and startup checks passed.
**All 15 production health samples passed. The strict operation monitor failed**
because one race encountered an existing remote directory-creation restriction.
The failed result is preserved; this is not a claim that all operational errors
have been eliminated.

## Findings and corrections

Review began with v3.20.14, which had remained running since November 6. Three
retained daily logs cover **November 7 07:00:06.384–November 9 16:00:51.461 UTC**:
**65,008 records**, comprising 63,750 Information and 1,258 Warning records. There
were no Error/Fatal entries in this retained interval, but **682 failed races**
were logged at Warning:

| Count | Root cause | Disposition |
| ---: | --- | --- |
| 135 | A recovered server pool had no matching participant progress/slot record | Fixed and reproduced with regression tests. |
| 467 | All remaining destinations rejected directory creation | Remote permission/policy restriction remains. |
| 53 | Release absent from all probed paths | Unavailable remote content; no authoritative alternate path. |
| 19 | GAMES mapping had no usable destination path | Repaired the existing mapping using a verified live directory. |
| 5 | Inconclusive source listings under connection/login pressure | External/admission limits remain. |
| 3 | Remaining source excluded by NeverSource policy | Preserved the configured policy. |

Pool refresh now creates progress before publishing recovered pools, preserves
existing transfer counters across replacement, and rejects unconfigured pools
before modifying state. Failover preserves the source role. Unexpected race
warnings retain the original exception and stack. Public site membership and
completion readers take structural snapshots, while score enumeration is locked.
The latter addresses a separately reproduced collection-modified exception; it
was not a second observed production exception in these logs.

Eight new regression cases failed before their respective fixes. They cover
recovered source/destination scheduling through direct and live refresh, slot
release, counter preservation, invalid pool rejection, exception diagnostics and
UI enumeration interleaved with recovery. **105 related tests passed** afterward;
these counts overlap the full suite below. Independent source review found no
blocker, including lock ordering and source-role handling.

The separate operational routing correction changes exactly one property: the
enabled `games → GAMES` mapping's empty path to **`/games`**. Read-only live root
and section listings verified the directory and its release-directory structure.
The revision-checked settings API saved the change; an independent semantic diff
and disk read verified no other setting changed. Four checks using the installed
application's actual resolver proved that both `games` and `GAMES` previously had
no usable base and now resolve there. Directory listing does not establish remote
create/upload permission, and no synthetic remote write was performed.

Historical review also examined 73 hourly census files, 27 incident capsules,
telemetry, queues, updater records and Windows events. The Windows Application
query through **November 9 16:11:47.828168 UTC** found no matching application
warning/error event since the previous installation. Sampled telemetry records a
November 6 connection timeout outside the retained daily window; this report does
not claim zero errors across the entire interval. The three failed live download
entries date to June/July and were preserved.

## Remaining risks

- Remote directory restrictions remain: 822 individual MKD denials across seven
  section bases account for 467 failed races. The same site accepted 81 FXP files
  into other/existing directories, so it is not a complete outage. Permission or
  policy changes require authoritative site access; no rights were bypassed.
- Account concurrency/rate limits, 300-second remote idle disconnects, missing
  remote content and NeverSource restrictions can still interrupt work. Login
  admission and native-session quarantine protections remain enabled.
- The strict production operation check remains failed for the remote permission
  denial described above. A local software rollback would not grant remote rights
  and would reintroduce the repaired recovery defect; no rollback was performed.
- The repaired GAMES path is verified for existence and resolver selection, not a
  claim of successful live GAMES creation/transfer.
- Seven standing configuration warnings remain: six enabled example announce rules
  reference unconfigured channels, and one proposed TV destination lies outside
  index coverage and was absent from the live root listing. All actual configured
  IRC channels are joined. Four frozen routing proposals await the owner's decision.
  No channel targets, disputed paths or approval decisions were invented or changed.
- Historical census/capsules are sampled. Bounded retention checks cannot prove
  logger emission or detect a wholly transient log file with no surviving rollover
  evidence; API/heartbeat and Windows-event checks provide separate evidence.
- The Inno compiler reports the existing admin-install/per-user HKCU caveat.
  Alternate-administrator installation and live rollback were not exercised;
  this deployment uses the signed in-app updater.
- A bounded production observation does not establish long-term uptime. No remote
  destructive probe or production disk exhaustion was induced.
