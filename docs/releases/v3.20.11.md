# GL Drive v3.20.11

Downloads now reserve space for extracted archive entries before writing them. A
download that cannot fit keeps its verified archives and waits for capacity without
consuming retries. That wait survives restart, and local extraction recovery does
not depend on the source FTP connection or race priority. Changed inputs return
through normal verification, and recovery stays within the download directory.

Download admission measures the actual remaining files instead of trusting a saved
progress counter. Single-file FTP downloads obtain their size before admission.
Insufficient capacity parks work for recovery instead of marking the download failed.

Relocation checks exact release paths beneath configured search roots as well as
watch and spread roots. This lets an inferred `/recent` download recover a release
that has moved under another configured root, without a recursive server crawl.

Queued torrent downloads now finish their completion checkpoint before stopping.
Their dedicated engine uses accurate resume data, and shutdown unregisters a stopped
manager even if writing resume data fails. Player streaming keeps its existing policy.
Regression fixtures cover delayed completion, interrupted transfers, resume-file
contention, peer discovery and timeout cleanup.

These changes complete the previously unshipped download and torrent repairs and
address additional gaps found while reviewing v3.20.10 production evidence. The
deployment report records the build, regression, native smoke and production results.
