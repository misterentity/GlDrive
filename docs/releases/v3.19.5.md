# GL Drive v3.19.5

This release corrects two diagnostic defects found in the October 31–November 2 production log review.

- Configuration refreshes now report an existing site's scheduled retry deferral as information with its retry deadline. They no longer describe it as a failed mount of a new server. Genuine mount failures retain their warning and exception evidence.
- Race history accounts for receiving sites even when they first announced the release and also supplied files. A partially populated source that receives its missing files can now record delivered files and a clean completion correctly. Download-only sites, excluded participants and unopened fill-only destinations do not become successful deliveries.

Completion uses actual inventory, expected-file checks, missing-file markers and the configured completion policy. `FilesDelivered` represents the largest inventory on a participating receiving site, including files already present; transferred bytes remain a separate metric. A clean recorded completion earns the full history score. Live progress scoring and transfer scheduling retain their existing behavior.

The reviewed logs had no error or fatal records. The previous incomplete shutdown coincided with a Windows unclean reboot, and historical network/DNS failures recovered. Sited is connected again and live races are completing. SITEC's FTP endpoint remains unavailable; this release preserves automatic retry and connection safety controls.

Existing race history is retained. Configuration notices about unused example announce channels, search coverage and frozen section mappings still require a configuration decision. Detailed validation and production observation are recorded in the [deployment report](https://github.com/misterentity/GlDrive/blob/master/docs/releases/v3.19.5-deployment.md).
