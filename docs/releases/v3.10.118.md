# GlDrive v3.10.118

## Log review and root causes

Reviewed all retained application logs, September 12–14, 2026, through 19:00 PT on September 14. The installed version was v3.10.117 from 09:31 on September 14 (v3.10.116 before that). No crash dumps or watchdog crash markers were written in the window.

| Day | Lines | Error | Fatal | Warning |
| --- | ---: | ---: | ---: | ---: |
| September 12 | 22,470 | 0 | 0 | 38 |
| September 13 | 30,713 | 0 | 0 | 43 |
| September 14, to 19:00 | 28,425 | 0 | 0 | 54 |

All 135 warnings were classified. 66 were SYN remount failures (host still unreachable). 34 were FXP transfer failure headers and cause lines, all remote `425 Can't build data connection` or `550 No such file` after a source relocation, each retried and completed. 10 were notification poll failures, every one `(1 consecutive)` and recovered on the next poll, which confirms the v3.10.117 recovery change in production. 8 were the same download parked hourly because local drive `T:\` is not mounted. 6 were two incomplete watched RAR sets abandoned at startup. 2 were source relocation notices. Every poisoned-discard line carried a cause (22 were the scheduled six-hour direct-route re-probe pairs).

That left one event with no external cause. On September 14 at 14:01:17 a FiSH-decrypted line on `#SYN-SPAM`, `Plot: A father-to-be tries to figure out what is happening with all this AI insanity.`, matched the user-configured announce rule `(?<section>\w[\w-]*)\s+(?<release>\S+)` as section `A` and release `father-to-be`. The rule matches any two-word text. `IrcAnnounceListener.IsPlausibleReleaseName` accepted the candidate because it treated a lone hyphen as release-name structure. An auto-race started across two servers, probed 23 base paths, and failed with "Release not found on any server".

Fix: a release name must carry a `.` or `_` separator, a digit, or an uppercase letter (the group tag). A hyphen alone is prose. Before editing code, the new predicate was run over all 24,881 matched announces recorded in `ai-data/matched-announces-*.jsonl` (September 10–14): exactly one was rejected, the prose line. Names such as `Unrailed-RUNE` and `BLOODLETTER-TENOKE` pass on the uppercase group tag. The predicate was made `internal` for testing.

The catch-all rule itself remains in the user configuration; the code change is defence in depth. It should be tightened or removed by the operator.

## Remaining risks and rollback

- Local drive `T:\` is not mounted, so the Backrooms.2026 download stays parked and re-warns hourly. This is the operator's disk, not the client.
- The `#SYN-SPAM` catch-all announce rule still exists in `appsettings.json`. The new gate rejects prose but cannot make the rule specific; a two-word line whose second word carries a digit or capital would still match.
- SYN's FTP endpoint remains unreachable; the retry ladder continues at five-minute intervals.
- Intermittent remote `425` data-connection refusals persist and are outside the client.
- Two incomplete watched RAR sets (single first volume each, April/August timestamps) are durably abandoned and will only retry when their volume set changes.
- Roll back with the v3.10.117 installer if announce matching regresses. No persisted schema or credentials changed.
