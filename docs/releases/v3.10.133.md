# v3.10.133 — restore BNC account-stat refresh and retry correctly

## Findings and changes

This release completes the September 24 log review and includes the sole-receiver
race correction from [v3.10.132](v3.10.132.md). That report records the retained
September 22–24 log inventory, initial release, and external dependency checks.

Production smoke at 10:23 and 10:24 PT exposed another failure at Information
level: `LIST trailer fallback failed` with a refused data endpoint, immediately
followed by `SITE STATS unavailable (no command grants access)` and a six-hour
retry suppression. The server's ordinary CPSV directory operations worked.

- Stats fallback called FluentFTP's standard `GetListing` directly, bypassing
  the CPSV route required by this BNC. It now uses the same operation as browsing,
  on the existing borrowed connection so its 226 reply remains available to the
  stats parser. Protocol selection and connection quarantine are shared.
- A data failure could leave `IsConnected` true, allowing the failure to reach
  the clean no-access cache. Failed LISTs now exit before caching; failed SITE
  commands quarantine the session and abort the refresh. Later refreshes retry.
- Successful replies with no statistics still use the existing bounded cache.
  The first successful trailer probe logs its protocol without account values.
- Version 3.10.133; no configuration or persisted-data migration.

## Remaining risks and rollback

- **SYN remains unreachable.** A fresh TCP probe timed out. The other two FTP
  servers and all three IRC networks connected during the preceding observation.
- **T: remains unavailable.** Windows remembers `\\zephyr\tv`; restoration with
  current Windows credentials failed with an incorrect-network-password error.
  Two downloads remain parked without consuming retry budgets. Correct share
  credentials must be restored in Windows; no credential or destination was guessed.
- Native smoke exercises loopback FTPS/WinFsp. The live stats probe covers the
  actual BNC CPSV path but is not an extended remote-transfer soak. WPF renders
  and API checks do not cover every interactive UI flow. Desktop capture was
  unavailable during the earlier installed UI inspection.
  The production observation is five minutes, not evidence of multi-day stability.
- Directory presence retains the race engine's existing already-present
  semantics; the sole-receiver correction is not a file-completeness audit.
- Inno Setup's existing admin/HKCU warning remains. Jobs that forbid breakaway
  can still terminate both app and watchdog; deployment verifies breakaway.
- Temporary synthetic fixture data remains after automatic approval review
  rejected directory cleanup as "blocked by policy". Fixture servers are stopped.
- Rollback uses the v3.10.132 installer, which reintroduces the account-stats
  defect but retains the sole-receiver correction. No data migration is required.
