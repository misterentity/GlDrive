# GL Drive v3.11.19 — search crawls stop listing inside releases

## Problem (production logs, 2026-10-14 → 2026-10-16)

superbnc's search index (roots `/incoming`, `/recent`, `/archive`, depth 2) never
finished. In two days of logs every `Search index built` line came from zephyr; superbnc's
only outcome was one `crawl aborted` at 06:53 on 10-16, about ten hours after its process
started. On the 3.11.18 process alone, superbnc issued 12,096 `LIST`s under `/recent/flac`
(14:42–18:28, alphabetically, about one per second) and then started on `/recent/mp3`.

The cause was the crawl's last level. With depth 2 it also listed each release directory
(`/recent/flac/<release>`), but a release's only child folders are its own `Sample`, `Subs`,
`CD1` or `Proof`. Those listings added junk index entries and nothing searchable. They ran
serially over superbnc's single main-pool login, so the crawl used that login almost
continuously and never published an index. Searching superbnc always fell back to a live
crawl. That crawl had the same problem and could cover only about 90 directories before its
90-second deadline. The busy login also shows up in the history: `main pool exhausted for
superbnc` (4,879 on 10-15/16), `SITE INVITE` falling back to the spread pool, and live search
`FTP connection busy`.

## Fix

`FtpSearchService.IsReleaseDirectory` identifies a scene release directory by its naming
pattern: a single token with no whitespace, a digit, `.`/`_` word separators and a trailing
`-GROUP` tag that contains a letter. The index crawl and the live-search walk still add those
directories as entries and results, but they no longer list inside them. Containers are still
descended:

- categories (`tv-hd`, `x264-hd`, `bluray-uhd`)
- boxsets (`007.Boxset`, `Kick-Ass.Boxset`)
- date and numeric directories (`2026-10-16`, `1016`, `Star.Wars.1977-2019`)
- names with spaces

The rule errs toward listing. A release name with no digit is still listed, exactly as
before. Race scans, FXP directory copies and remote deletes still walk inside releases. Only
the two search walkers changed.

Expected effect on superbnc: an index build needs about one listing per root and category,
not one per release. It should complete within minutes and stop occupying the main-pool login.
The index no longer contains entries for `Sample`, `Subs` or `CD1` folders.

## Tests

- `SearchIndexCrawlTests`: the predicate is checked against production names (flac, mp3, NSW,
  TV, boxset releases) and against containers. Both walkers index 40 flac releases and a TV
  release with zero listings inside them, and a boxset is still descended to its releases. The
  status-directory test now expects release-named directories to be returned as results but
  not crawled.
- Mutation-verified: removing the guard from either call site fails that walker's tests.
