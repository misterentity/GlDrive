# v3.10.155 — verify growing-source recovery and production health

## Log review and root causes

The October 13 audit at **17:04:36 UTC** covers all retained application logs and
telemetry since installed v3.10.154 started on October 12 at **17:19:12 UTC**,
together with the watchdog, heartbeat, Windows errors and crashdump inventory.
The retained window contains **17,115 records and 200 classified warnings**;
the current process accounts for **8,716 records and 95 warnings**. Both windows
have **zero Error/Fatal records**. There are **no production GL Drive Windows
faults or new crashdumps**. The entire current deployment lifetime is retained.

| Current-process warnings | Root cause and outcome |
|---|---|
| 54 missing-destination warnings | T: has no root, volume, partition or SMB mapping. Two downloads remain safely parked without spending their normal retry budget. |
| 25 SYN remount timeouts and one initial mount timeout | Unavailable FTP dependency. A separate TCP-only probe also times out after 5.02 seconds, before authentication. The precise remote/network cause remains unconfirmed. |
| Six SYN IRC connection failures | Temporary endpoint/network outage; IRC reconnects at 15:30:05.873 UTC after backoff. |
| One SYN SITE INVITE timeout | FTP remains unavailable after IRC reconnects; the invitation call reaches its bounded 30-second deadline. Invite-only channel membership is unverified. |
| Two source-550 warnings, two paired exception details, two relocation notices | Two failed attempts recovered through relocated source paths. The details are duplicate diagnostics, not additional failed transfers. |
| One AI-provider HTTP 429 | Provider rate limit; the two-minute retry finishes successfully at 11:03:46.386 UTC. |
| One torrent metadata timeout | A swarm did not supply metadata within the deadline. There is no later success evidence for this request or established client defect. |

Current-process telemetry records **124 complete races and 2,627 successful
transfers**, reporting **356,267,873,782 bytes**. Both aborted attempts recovered;
there are no telemetry parse failures. Bytes are measured for relay transfers
and otherwise use the listing size, so this is not a content-integrity audit.

Four files had successful transfer records below 50 MB and later successful
50 MB records in the same race. This is consistent with source files growing
during upload: the scanner retains the largest observed size, revokes ownership
of smaller copies and makes the destination eligible for transfer again. All four
were retransferred and their race completed at **14:23:51 UTC**. The existing
relay completion guard rejects delivery below the source size known when the
transfer starts. Telemetry does not record that expected size or the actual mode,
so the earlier smaller successes alone cannot establish a short-relay defect.

The source relocation fix also has direct production evidence: the first missing
file reply at **October 12 20:05:34.980 UTC** was followed by the relocation log at
**20:05:36.771 UTC**, **1.791 seconds** later. Both failed files subsequently
succeeded from the changed source path and the race completed.

No new application defect was established. This is a validation release; changing
working retry logic or suppressing dependency warnings is not justified by these
logs. The missing T: destination and unreachable SYN FTP endpoint remain external
conditions.

## Changes

  and progress reconciliation for growing source files, including a stale smaller
  destination observation and restoration of full-size ownership. These invoke
  the ownership-based completion predicate; they do not run the asynchronous race,
  real transfers or the default destination-completion-marker gate.
- Update release version and documentation. Application behavior is unchanged
  apart from the version.
- Tighten the local release-evidence helpers: reject stale fixture state, report
  native assertion counts separately from the completion marker, reject extra
  installed files, and return failure when the post-deployment audit fails.
  These helpers remain in the gitignored evidence directory.
