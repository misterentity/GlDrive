## Log review and root causes

The active production session and the two retained full daily logs were reviewed. The
current day contained no `ERR` or `FTL` events. The actionable signatures were:

| Signature | Root cause | Resolution/status |
|---|---|---|
| `Spread scan: ALL scans failed or returned 0 results` | Individual scans were correctly classified as login-contention deferrals, but the empty-batch summary unconditionally promoted the same event to Warning. The following scan cycle succeeded. | Fixed in v3.10.81. The aggregate warning now requires evidence of at least one genuine fault. All-contention batches remain informational and rescan. |
| `Spread job failed ... release already present on all ...` | A duplicate announce can be processed after the first race has populated every candidate site. Discovery is the first point where this is knowable; it is an idempotent no-op. | Fixed in v3.10.81. The terminal outcome and dead-race accounting remain intact, but the log event is informational. |
| Repeated SYN mount timeouts | The configured remote TCP endpoint was unreachable from the production host. The other remote endpoint and LAN endpoint were reachable. | External/server condition. Recovery remains enabled; existing retry policy retains detailed Warning evidence hourly and compact Information summaries between warnings. |
| Six queued downloads parked for missing `T:` | The production host has no mounted `T:` volume. The queue correctly preserves these items without consuming retries. | External/storage configuration. No path was changed because the intended mount or replacement destination is not inferable from logs. |
| Intermittent FXP `425`, connection reset, and `GNUTLS_E_PULL_ERROR` | Remote data-channel establishment/transport failures. Logs show connection quarantine, pool replenishment, retry, and subsequent successful transfer of the same file. | Existing recovery behaved correctly; retained as Warning-level operational evidence. No code change required. |

The sole `ERR` in the prior retained day was a recoverable startup mount timeout. That
classification was already corrected in v3.10.79; the same condition is Warning-level in
the current session.

## Changes

- Added batch-aware spread scan severity accounting that distinguishes genuine faults
  from login-contention deferrals.
- Reclassified “already present on every candidate site” as an informational no-work
  outcome while preserving terminal job/dead-race behavior.
- Added regression coverage for contention-only, hard-failure, mixed/successful batch,
  and expected no-work classification paths.

## Remaining risks

- SYN remains unavailable until its remote endpoint/service returns or the server is
  disabled/reconfigured.
- Six queued downloads remain parked until `T:` is mounted or their destination is changed.
- Transient remote FXP/data-channel failures are expected to recur; retry/quarantine was
  observed working, but a sustained live race under v3.10.81 is still the strongest
  end-to-end validation of those external paths.
- The installed production client was still v3.10.79 during release verification. The
  production channel is updated to v3.10.81; applying it locally remains subject to the
  app's normal busy-window deferral and Windows UAC approval.
