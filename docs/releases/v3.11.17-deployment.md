The four errors were `Dashboard search failed` collection-view refresh exceptions,

Thirty retained crash-dump logs were also reviewed. The latest pair, October 13,

for the installed v3.11.16 session through 17:12 UTC found no GL Drive fault events.

Two previously unresolved application defects appeared as warnings rather than
ERR records:

- **Relocation starved behind the main FTP pool.** At 00:38–00:52 on October 16,
  fourteen source-file RETR failures were interleaved with repeated 240-second
  relocation attempts. The probe chose any existing main pool even when the spread
  pool had a usable connection, then repeated a 15-second borrow for each candidate.
  It now prefers available sessions across both pools and stops a pass when no
  connection can be obtained. Unchecked paths and failed commands cannot prove a
  source disappeared. Failed probe sessions are quarantined; a lifecycle stop
  between commands preserves a synchronized session.
- **Nuke polling misclassified local contention.** Three 30-second borrow deadlines
  opened the remote-command breaker at 08:50. The poll now uses the live spread
  pool after a ten-second main-pool budget, retaining its total thirty-second budget.
  A borrow deadline defers polling without consuming or resetting the real command
  failure budget. Actual command failures still open the breaker; native command
  cancellation continues to use managed abandonment and deferred quarantine.

The baseline suite also exposed a timing-sensitive loopback UDP tracker test:
it failed during the full parallel run and passed alone. Its 100 ms transport retry
budget proved sensitive to parallel-run timing; scheduling pressure is the inferred
cause from the failing full run and passing focused retry. The fixture now uses
a one-second retry delay and a bounded fifteen-second overall deadline. Wire-event, response
interval and announce-scheduling assertions are unchanged; production tracker code
was not changed.

Other reviewed warnings were external or expected outcomes: the previously
unreachable third FTP site; a temporary DNS/network interruption followed by
reconnects; bounded partial searches during pool contention; upstream tracker and
PreDB failures; and missing archive content. The daily AI runs recovered after HTTP
429 responses (and on October 15–16 a 300-second request timeout), succeeding at
04:02, 04:11 and 04:12 respectively. One no-activity race had no transferable source
files in the available trace; the next race proceeded. Logs alone do not establish
an additional application defect for that outcome.

## Risks and limits

- One FTP endpoint remains unavailable and one source's three IRC channels remain
  unjoined after the targeted recovery. Automatic announcements from that IRC source
  are degraded. Remote invitation delivery needs server-side investigation; the
  application's existing bounded retry/reconnect policy remains active.
- Remote service availability, missing source content and account login limits are
  unchanged. Partial live searches remain possible under contention.
- A pre-existing, unobserved cancellation boundary remains: cancellation after
  acquiring a nuke-poll lease but before the command's preflight check can still
  consume the command breaker budget although no command was sent. This is distinct
  from the sustained pool-borrow deadlines fixed here; the retained production logs
  do not establish occurrence. Any future refinement must preserve quarantine and
  breaker accounting after command invocation.
- A short control probe may briefly hold a spread connection. Pool and account
  limits still apply; no additional configured login capacity is introduced.
- Native fixture tests exercise FTPS, CPSV and WinFsp locally. They do not reproduce
  every remote glftpd/BNC behavior or replace a long production soak.
- Production update timing uses the existing no-active-transfer policy. Observation
  immediately before handoff is not an atomic reservation against a new transfer.
- Eleven existing MCP clients still hold earlier bridge modules open. Newly launched
  bridges use the verified v3.11.17 payload; clients need a normal restart before
  the 210 locked rollback files can be removed by a subsequent cleanup.
- The installer retained its existing advisory about per-user HKCU entries in an
  administrative install. The signed ZIP updater is the deployment path exercised
  here; standalone installation under an alternate administrator was not tested.
- The fixture processes were stopped. Automatic approval review rejected
  deletion of their generated temporary files with only “blocked by policy”; those
  files were retained as diagnostic evidence instead of retrying cleanup.
