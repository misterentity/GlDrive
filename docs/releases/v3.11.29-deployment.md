## Changes

A real `GNUTLS_E_PULL_ERROR (-54)` at 2026-10-22 13:17:35 confirmed the read-side
gap documented in v3.11.28. It was logged at Information level in the preceding
run; no GnuTLS read failure recurred in the reviewed v3.11.28 window.
The pinned library's `GnuTlsException` does not inherit
from `IOException`, so search retry and spread scan quarantine did not recognize
that exception type. Regression tests establish this handling gap; the historical
log does not establish that a search result was lost.

`SerializedGnuTlsStream` now normalizes synchronous/asynchronous native read failures
to `IOException`, preserves the original exception/code, and marks the session
unusable while holding the existing I/O lock. Cancellation, unrelated errors,
handshake handling and read/dispose serialization retain their behavior. The
background-task handler recognizes the specific wrapper so expected late native
reads retain their Debug classification. Independent review found and resolved
that integration issue before release.
