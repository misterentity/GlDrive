# GL Drive v3.20.20

The auto request filler now fills requests. The previous version recognised a
request and found the release on another site, but then queued an ordinary race
behind everything else, aimed it at a section directory instead of the request
directory, and never marked the request filled.

## What changed

- **Detection.** A request opens on the sitebot's announce
  (`REQUESTED by <nick> : [ n:] <release>`) rather than on the `!request`
  command a user types, so requests made over FTP are seen too. The site's
  requests directory is read at startup and every ten minutes, which picks up
  requests that were already open. A stored `!request` pattern is treated as
  "use the built-in pattern".
- **Search.** The first site to answer with an exact match is used; the search
  no longer waits for the slowest site to time out. A request with no source is
  retried with a backoff (1, 2, 5, 10, 20, then 30 minutes, for 48 hours) and
  immediately when a matching release is announced on any site. Skiplists
  govern what is raced *into* a section, so they no longer disqualify a site as
  the source of a requested release.
- **Fill.** The race goes to `<requests>/REQUEST-<release>/<release>` and takes
  the next free race slot ahead of the ordinary queue. A release that is
  already queued is promoted in place.
- **Completion.** When the upload is complete the filler sends the filled
  command (`!reqfilled <release>` in the request channel by default). If the
  sitebot announces that someone else filled the request first, the fill is
  withdrawn.
- **Safety.** A fill starts only while the site's own `REQUEST-<release>`
  directory exists, so a forged announce cannot make the app upload anything
  or create directories. Rate limits (fills per hour, cooldown) now delay a
  request instead of discarding it. Request chatter no longer reaches the
  release-announce pipeline as a new release.

## Settings

New keys under a server's `irc.requestFiller`, all with working defaults:

| Key | Default | Meaning |
| --- | --- | --- |
| `requestPath` | `/requests` | The site's requests directory |
| `directoryPrefix` | `REQUEST-` | Prefix of an open request's directory |
| `filledCommand` | `!reqfilled {release}` | Sent when a fill completes; `{number}` is also available. A value starting with `SITE ` is sent over FTP instead of IRC |
| `filledPattern` | built-in | The sitebot's "request filled" announce |
| `botNick` | empty | Accept request announces only from this nick |

The fill waits for the running race to finish; it does not preempt it or add
a concurrent race.
