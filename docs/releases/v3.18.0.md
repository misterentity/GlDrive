# GL Drive v3.18.0

Feature-gap roadmap, Phase D batch 1 (D14, D1, D8, D10, D2). Codex implemented it, and three independent reviewers plus Claude reviewed it. Full suite: 5,072 tests (4,999 app, 53 core, 20 MCP), 0 failures.

## Certificate changes no longer freeze everything (D14)

- A server that presents a changed certificate is now **parked on its own**. A non-modal **Certificate decisions** window opens, and every other server keeps connecting. Before, a modal dialog held the shared validation gate, so every connection waited on it.
- A parked server is excluded from races and retries locally without touching the network. It never arms the BNC cooldown, authentication hold or site-health ladder.
- **Trust stays a local, explicit decision.** Accepting a changed certificate is possible only in that window. MCP can list pins and pending decisions but can't accept, clear or re-pin.
  - Editing the server's host, port or proxy, a restore or a snapshot can't bypass a pending decision.
  - First-use trust for new servers is unchanged.
- If `trusted_certs.json` is unreadable, it's quarantined, and servers that had pins wait for your local review instead of silently trusting whatever they see next.

## Flight-recorder logging (D1)

- Your saved `logging.level` is never changed. New installs default to Information on disk, with about 30 days of size-capped retention.
- Verbose detail always goes to a bounded in-memory ring. On an error, a stall or a known signature, the recent ring is written to an **incident capsule** under `logs/capsules`. Capsules are size-capped and rate-limited, and every row passes through the secret redactors first.
- A filterable **Logs console**, per-component trace switches that switch themselves off, and MCP `logs_tail` / `logs_capture`.
- Known signatures, codified from past incidents, raise at most one tray notice per 5 minutes. Over the last 2 days of real logs, the shipped signatures matched almost nothing.

## Problems panel (D8)

- Read-only standing checks, each with its evidence:
  - a site down long enough to escalate its retry ladder;
  - a missing download drive;
  - Verbose logging left on;
  - unindexed destination folders;
  - a monitor with no categories;
  - announce rules targeting unjoined channels;
  - frozen decisions still pending.
- Each fix is previewed with its real effect (for example "triggers a full search re-crawl") and applied only when you click it, through the normal attributed settings save.
- Nothing is fixed automatically. "Verbose left on" is offered, never forced.

## Statistics (D10)

- Per-site GB/day (relay bytes included), race clean rate, queue wait, announce-to-start latency, route speeds, download success and site uptime. There's an MCP tool too.
- Computed off the UI thread within fixed memory and time budgets. Where the data is incomplete, the page says what's missing instead of guessing.

## Release dossier and ops journal (D2)

- One page (and MCP tool) per release joins its history: the announce, rule matches, sightings, the wishlist verdict, per-site auto-race verdicts, queue waits, the race outcome, downloads and nukes.
- A **"what would happen now"** dry run predicts today's verdicts with no side effects. It never starts a race, a download, a login or a site command.
- A durable **ops journal** records operational transitions: remounts and their cause, IRC drops and rejoins, health episodes and decisions. Repeats are coalesced, the store holds days of history, malformed lines are skipped rather than wiping it, and everything is redacted.

## Review

The reviewers found 14 issues, all fixed before release. The ones that affected default behaviour:

- **A pending certificate decision made races spin.** The race engine didn't see the parked server as parked. Each race relaunched a doomed transfer about every 50 ms, logging a stack trace and probing the healthy peer each time. That could run all night on an unattended box.
- The **dead-site check fired during a site's normal retry ladder**, on a first timeout or a BNC cooldown. It offered a one-click "disable automount" that could remove the only race source. It now needs a sustained, escalated outage, and that fix is gone.
- The **ops journal was flooded** with per-announce events and held only 1–2 hours of history.
- The dossier lost evidence once telemetry was trimmed, and its dry run was always "unknown" on a realistic config.
- Export diagnostics could replace the whole recorder log with the redaction mask.
- The recorder rebuilt the full secret inventory (Credential Manager, DPAPI) every second.
