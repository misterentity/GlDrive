application log was narrowed to the current process window beginning at 2026-08-26

The first independent TCP probe mistakenly read `server.port` instead of
`server.connection.port` and reported all three sites down. That result contradicted the
active race and control API, was discarded, and the corrected nested-field probe produced
the two-connected/one-disconnected result above.

## Changes

- Enabled `TreatWarningsAsErrors` for the application. Release builds now fail rather than
  accepting compiler warnings.
- Made intentional WPF dispatcher operations explicitly fire-and-forget and contained the
  startup mount-failure tray notification at its own exception boundary.
- Removed a redundant dispatcher hop from the extraction UI handler, which already resumes
  on the captured WPF synchronization context.
- Removed the write-only PM-history `_savePending` field; timer and dispose flushes remain
  serialized under the existing lock, with the final flush still unconditional.
- Fixed unreadable Cyberpunk ComboBoxes. The theme's setters-only implicit style shadowed
  the full application template, causing WPF to fall back to native white controls with
  light text. The theme now inherits the application template and dynamic Cyberpunk
  brushes, and a regression guard rejects future template-less implicit overrides.
- Updated CI from the deprecated Node 20 action runtimes to Node 24-backed
  `actions/checkout@v7` and `actions/setup-dotnet@v6`.

## Remaining risks

- The production host is healthy but still runs **v3.10.81**. The public latest-release
  endpoint returns v3.10.83, but the running updater has not polled it yet. Live validation
  of the installed v3.10.83 binary therefore remains pending; installation may still be
  deferred by an active race or require an accepted UAC prompt.
- `SYN` remains externally unreachable, and the configured `T:` destination volume remains
  absent. These two conditions account for 86% of current-process warning volume and can
  obscure a new low-frequency signature until the server/storage configuration is restored.
- Inno Setup emits `UsedUserAreasWarning` because the installer requires admin rights for
  WinFsp while the optional autostart task writes HKCU. The build succeeds and this matches
  the existing per-user autostart design, but over-the-shoulder elevation by a different
  administrator could target the administrator's HKCU rather than the interactive user.
- Screenshot smoke mode validates WPF construction and rendering, but the running tray-only
  process exposes no top-level accessibility window; live interactive settings/extraction
  workflows were not exercised against production while an active race was in progress.
