# GL Drive v3.19.4: log review, corrective release and deployment

**v3.19.4 was built, tested, published through the standard pipeline and installed through the signed updater. All 5,487 regression tests passed, all 1,339 installed files match the release, and all 56 queued race requests were retained. A 12-minute production watch found zero errors, fatal events or crashes. The corrected auto-race skip warning fired once for six announces and named the missing sites. FTP availability is still degraded: zephyr and SYN do not answer TCP connections, so cross-site racing is not operational.**

## Audit scope and findings

This review covers the v3.19.3 process from **2026-10-30 17:31:32 UTC to 03:00 UTC**: **1,259 records, 360 warnings, zero errors and zero fatal records**, and no Windows Application crash events. v3.19.3's scan/retry-flood fix held: none of its old signatures appeared.

| Finding | Evidence and root cause | Correction |
|---|---|---|
| Auto-race skip warning flood with the wrong hint | **355 of 360 warnings**: one per IRC announce (348 distinct releases), each saying "only 1 connected spread pool(s) ... check login cap". They never named the unavailable sites. The real cause was zephyr and SYN in site-health backoff, not the login cap. | Name the unavailable race sites. Keep the login-cap hint only when no FXP pool is live. Warn when the set of unavailable sites changes, and hourly while it persists. Repeats log at Debug and report a suppressed count. Recovery re-arms the warning. The skip policy itself is unchanged. |
| Sitebot trust could be revoked by machine load (found by release CI) | `SitebotEventParser.IsTrusted` built a fresh NonBacktracking regex per message with a **50 ms** timeout, and treated `RegexMatchTimeoutException` as untrusted. CI run 41164126807: exact-host case took **65 ms** and returned false. Reproduced locally under CPU saturation: **8–17 genuine checks rejected per run** (3/3 runs). | Host masks (`*`, `?`) are now matched with a bounded linear wildcard matcher, with no timer. 13 parity cases cover anchoring, regex metacharacters, case folding and backtracking. The saturation test went from 8–17 rejections to 0. This is **latent in production**: no sitebot nick or host mask is configured. |
| Relay ceiling test flaked under CI load (found by release CI) | Run 41163357770: a real 100 ms `Task.Delay` stalled past the 1 s window. `047c3e0` had already widened its margins once. | The test now runs on a manual `TimeProvider`. It also checks that the window does not fire 1 ms early. |
| Zephyr FTP unreachable | 2 remount warnings (`Timed out trying to connect`). Zephyr is **192.168.1.86:2010, a host on this LAN**: ARP entry incomplete, ping fails, and **no host on 192.168.1.0/24 accepts TCP 2010**. Zephyr's `#ent` sitebot has been silent since 05:27 UTC, 8 minutes before the FTP drop at 05:35 UTC. | Outside the code. The zephyr machine, or its glftpd/BNC service, is down. The owner must restore it. |
| SYN FTP unreachable | 3 remount warnings. TCP connect to 216.71.209.209:12779 fails. | Outside the code. The normal 4-hour health retry continues. |

All 360 warnings are accounted for: 355 auto-race skips, 3 SYN remounts and 2 zephyr remounts.

**Investigated and ruled out:** every announce channel reports `Learning` / `baselineReady: false`. This is by design. `AnnounceFeedHealthPolicy.Rate` requires at least 2 h of exposure and 20 announces in each hour-of-week slot, and only about 2.5 days have been collected, so baselines need roughly two weeks.

## Remaining risks

- **Zephyr is down at the host/service level on the local network.** Zephyr is where all 56 queued races and every new announce would go. The machine at 192.168.1.86, or its FTP service, needs the owner's attention. If it comes back on a different address, update the server's host in Settings. **SYN** also remains unreachable.
- Announces skipped during the outage are not queued for later replay. The existing queue's age and resume limits still apply during a long outage. This policy is unchanged.
- Suppressed skips log at Debug, and the sink runs at Information, so only the first skip per outage state, plus one per hour, is visible in the file log. Each warning reports how many were suppressed. The per-announce UI event (`AutoRaceAttempted`) still fires every time.
- The sitebot template path (`SitebotEventParser` custom templates) still compiles a fresh regex per message with a 50 ms timeout; a timeout there drops one parsed fact. No templates are configured in production, so it is unused today.
- Existing configuration notices remain: example announce rules target the unconfigured `#announce`/`#pre` channels, and Zephyr `/TV-1080` index coverage and frozen section-mapping proposals await the owner's decision.
- No live cross-site race or endpoint recovery was observed after installation. Production rollback was not exercised.
