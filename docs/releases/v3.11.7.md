# v3.11.7 — distinguish busy statistics refreshes from FTP failures

## Changes and root causes

The audit captured at **2026-10-14 17:07:31 UTC** covers **56,398 retained
records** from October 12 07:00 UTC, including 29,149 warnings, one Error and two
Fatal entries. All are classified. The installed v3.11.6 process, running since
11:08 UTC, accounts for **4,380 records and 49 warnings, with zero Error/Fatal**.
It has no Windows application fault or new crashdump in that interval.

Statistics refresh now skips normally when its ten-second deadline expires while
waiting for a pooled connection. It keeps the last account statistics and cache
state, and retries on a later refresh. The October 14 production audit found eight
warnings caused by this ordinary contention before any FTP command ran.
Cancellation during an actual command or listing remains a warning and retains
the existing connection quarantine behavior. One production statistics warning
was a real cancelled socket read and must remain visible.

The retained logs also contain failures already addressed by the recent releases:

- The disposed-pool retry burst is addressed by resolving replacement pools after
  a remount and bounding retries in v3.11.3 (`8d1611f`). The retained burst contains
  28,008 transfer exceptions; none recurs in the current process.
- Settings folder browsing on an unavailable drive is guarded in v3.11.4.
  Both historical Fatal events at 02:35 UTC originate in the folder dialog;
  `f7d7eb9` validates its initial directory.
- Deleted watched folders are discarded by the extractor in v3.11.5.
- Updates use distinct backup generations in v3.11.6, preventing a running MCP
  host's retained older files from forcing another update to roll back. Installer
  diagnostics are mirrored to the shared application log directory (`8d4c7be`).
  The retained Error at 05:06 UTC is the older updater giving up after three
  unsuccessful v3.11.5 attempts; installed v3.11.6 has since recovered. Attribution
  of those historical rollbacks to retained MCP files comes from the existing
  v3.11.6 fix and release notes; the older SYSTEM updater detail was not accessible
  in this audit.

Source-file failures were checked against subsequent races as well as the
original race IDs. One release followed its relocated source and later completed;
another is durably waiting for the remaining source files. The extractor's
repeated stall warning corresponds to a real incomplete local archive: three
400 MB volumes and twelve missing parts. These conditions must not be reported
as successful transfers or successful extraction.

Current-process telemetry records **35 completed races and 760 successful
transfers**, reporting **219,314,171,384 bytes**. Two of seven aborted attempts
subsequently succeed across resumed race IDs; the other five belong to the
pending release. The search crawler preserved its previous 6,469 entries during
a pool outage, and the connection recovered after bounded cooldown. Transfer
telemetry is not an independent payload-checksum audit.

## Remaining risks

The SYN FTP endpoint remains unavailable. Missing remote release parts and the
incomplete local archive require the remaining files to arrive; this release
keeps them pending. An independent TCP-only probe also timed out before
authentication. D: has **272.54 GiB free (3.66%)**; no retained disk-full error was
found. T: remains absent, but no current download is parked for that drive.
Running MCP hosts retain 42 old mapped files until they exit and a subsequent
cleanup can remove them. The installer still emits its existing warning about
per-user registry changes under admin installation; this deployment used the
signed ZIP updater.
Loopback FTPS/WinFsp verification does not reproduce
every remote glftpd/BNC/CPSV behavior, and bounded production monitoring does not
replace a long soak or content-integrity audit.
