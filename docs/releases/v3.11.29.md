# GL Drive v3.11.29

Completes the TLS transport-error handling identified during the v3.11.28 log
review. The current production run has no Error or Fatal entries; this change
addresses the read-side gap recorded as a remaining risk in the previous release.

FluentFTP.GnuTLS 1.0.38 throws `GnuTlsException` directly from a failed native
read. That exception does not inherit from `IOException`, so search's transient
retry and the spread scanner's transport-failure quarantine did not recognize
it. The serialized TLS wrapper now reports these read failures as `IOException`,
preserves the original exception, and marks the session unusable before releasing
the I/O lock. Synchronous and asynchronous reads follow the same policy.

Caller cancellation and unrelated programming errors retain their original
meaning. The native read/dispose serialization and pinned library versions remain
intact. Expected abandoned background TLS reads keep their existing Debug-level
classification after wrapping, while unrelated failures remain visible.

Regression tests exercise the actual library exception through the stream and
search retry boundary. Build, native FTPS/WinFsp/CPSV smoke, signed package,
deployment, and production observation results are recorded in the
[deployment report](https://github.com/misterentity/GlDrive/blob/master/docs/releases/v3.11.29-deployment.md).

The log review also found recovered source relocations, IRC reconnects and an AI
provider rate limit. SYN's remote FTP outage and runtime files retained by older
MCP clients remain operational risks; this release does not claim to resolve them.
