## Changes

FTP downloads stop an obsolete transfer plan after observing an extra byte past
its expected file size. Both FTP data modes preserve the exact remote path and
expected size in a typed failure. The engine quarantines the affected session,
drains peer readers, blocks publication and clears every affected staging range
again after late reads finish. A second overflow after cancellation is also
invalidated. Sidecar write failures propagate while all owned handles still close.

The download manager obtains a fresh inventory. Only the same ordinal remote path
with a strictly larger size proves growth and enters the existing persistent
source-completion wait without consuming a retry. Missing or unchanged files,
changed siblings, unknown sizes and failed probes retain bounded failure handling.
Cancel/pause retain priority. Single files do not acquire a directory SFV hold.

The native fixture grows a generated file after real LIST/SIZE planning but before
RETR, reproducing the production failure through actual GnuTLS. It checks one
obsolete fetch, no truncated publication, refreshed exact bytes, manager waiting,
slot release, persisted state and recovery after restart.

## Operational limits and remaining risks

- Remote connection failures, data-channel stalls, content relocation and remote
  mkdir restrictions remain possible. Their exact server-side causes are not
  established by client logs; timeout, quarantine, backoff and retry guards remain
  active. The main pool already uses PWD keepalive, so recurring idle-session
  `421` replies cannot be attributed conclusively to missing keepalive.
- Four race failures lacked an eligible section mapping. The Problems API also
  reports six existing announce rules aimed at unconfigured channels and four
  informational frozen agent decisions. These need configuration-owner intent;
  no mappings, channels, credentials, freezes or remote access policies were
  changed to make health checks pass.
- The built-in 24-hour expiry can discard old fresh queue requests when arrivals
  outpace transfer capacity. Owned partials and indefinite source waits are
  excluded from this expiry rule. The 130 expiry records are retained as evidence.
- Source-growth detection requires a fresh larger size for the exact affected
  path. A stale or unavailable listing receives normal bounded retries. Proven
  growing sources wait using the existing source-completion backoff.
- Managed concurrency fixtures model native read lifetime; they do not reproduce
  every remote FTP/BNC configuration. Native integration, UI, installed-payload
  and production observations provide complementary evidence. Bounded snapshots
  cannot guarantee long-term availability or detect logs removed before capture.
