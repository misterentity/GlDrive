# GL Drive v3.11.33

Log sweep 2026-10-26 20:24 → 10-27 20:01 (the whole v3.11.32 window, 871k lines,
Verbose): **0 FTL / 0 ERR / 52 WRN**. Most WRNs are known and external (SYN
remounts, PreDB timeouts, two superbnc transport resets). Two code defects
were behind the rest.

## 1. A race shipped another release's rar volumes

**Evidence.** 2026-10-27 03:00, `Line.of.Fire.2026.S01E06.1080p.WEB.H264-CAKES`.
For about 70 s, superbnc listed `below.deck.s13e03.1080p.web.h264-hotdogwater.r03..r09`
inside the Line.of.Fire directory, and its RETR answered `150 (99876864 bytes)`.
The race had already parsed its own SFV. It still:
- counted 30 files for a 22-file release;
- FXP'd 100 MB of `below.deck…r09` into zephyr's `/TV/Line.of.Fire…` (zephyr's
  zipscript then deleted it);
- held its single race slot about 60 s after zephyr was COMPLETE, while
  `Below.Deck` itself sat queued (`maxConcurrentRaces: 1`).

The same superbnc shape appears 10-26 (Minimum.Wage listed
`marshals.*-sauerkraut` volumes) and 10-27 (90.Day.Hunt listed
`west.indies.*-dev0` volumes).

**Root cause.** `ProcessFiles` admitted every listed file. The parsed SFV
inventory (`_sfvInventory`) was only used to *count* expected files. Nothing
used it to decide which files belong to the release.

**Fix.** The SFV is now the authority for its own directory
(`SpreadJob.IsUndeclaredBySfv`). A file is foreign when all three hold:
- a parsed SFV covers its directory;
- that SFV does not declare it;
- it is the same payload kind the SFV declares. `.rar`, `.rNN`, `.sNN` and
  `.NNN` count as one archive set.

`.nfo`, `Sample/`, `Proof/` and any other extra the SFV never lists still race.
File names are deliberately not used, because groups ship names unrelated to
the directory (`viceroys-sihfnl261025_gsevzsc_en720p.r00` in an
`SIHF.National.League…` dir).

How it is applied:
- Foreign files are skipped at observation, with one INF line per file.
- Files admitted before the SFV was parsed are purged when it is applied
  (`FileOwnershipReconciler.Forget`).
- A resized SFV (pending re-read, possibly truncated) gates nothing until it is
  re-read.

New tell: `Spread: <site> lists <file> in <release>, but the release's SFV does
not declare it — not racing a foreign file`.

## 2. A Relay dupe-skip held the source login for 15 s

**Evidence.** 28 times in the window, each 15 s:
1. Relay sends RETR to the source.
2. The dest answers STOR with `553 … This file looks like a dupe!`.
3. We send ABOR, which gets `225 ABOR command successful` within about 1 s.
4. The RETR's own final reply waits for
   `435 Failed TLS negotiation on data channel (timeout), disconnected [14.999s]`.

That is about 7 minutes of a superbnc login that has a 1-login cap.

**Root cause.** Relay sends RETR before STOR on purpose, so that a source
rejection never leaves a 0-byte stub on the dest. When the STOR is then refused,
the source is in its data-TLS handshake, waiting for us as the TLS server. That
handshake only fails at glftpd's 15 s timeout.

**Fix.** Close the source data socket before ABOR. The handshake then fails at
once, and the same two replies are consumed as before, without the wait.
