# GlDrive v3.10.95 release record

## Findings and root causes

- Retained production logs contained no current `ERR` or `FTL` application records. SYN's FTP
  endpoint remained unreachable by direct TCP probe; intermittent FXP `425` data-channel errors
  recovered on the existing retry path.
- A fresh-runner CI failure exposed a race in first-use DPAPI updater-key creation.
- Live standard-pipeline deployments exposed four unattended updater lifecycle defects: WPF was
  initialized before SYSTEM-mode dispatch; task mode depended on a CurrentUser-DPAPI marker;
  handoff cleanup followed an applicator that never returns; and session-0 could not relaunch the
  desktop app. The tray callback also replaced the authenticated update marker with an unsigned
  timestamp, preventing the watchdog from coordinating recovery.

## Changes

- Atomically initialize and persist one updater HMAC key across concurrent cold-start callers.
- Dispatch updater modes before WPF construction.
- Keep HMAC authorization for interactive elevation; use the task's fixed action, pinned
  destination, strictly-newer version check, RSA signature, and double locked-archive hash
  verification for SYSTEM mode.
- Consume SYSTEM handoffs before non-returning dispatch and write acceptance/rejection diagnostics
  to `%ProgramData%\GlDrive\update-task.log`.
- Preserve the authenticated `.updating` marker. The SYSTEM applicator writes a completion signal
  after install or rollback, and the original interactive watchdog waits for it and relaunches
  GlDrive in the signed-in user's session.
- Add concurrency, privilege-boundary, entry-order, consume-order, and relaunch-ownership tests.

## Remaining risks

- SYN remains externally unreachable; GlDrive's bounded remount loop continues to handle it.
- Remote FXP endpoints can still refuse transient data connections; observed failures recovered
  on retry, so no application change was warranted.
- The scheduled task records result `-1` because the applicator deliberately terminates its own
  process after signalling completion. The authenticated completion signal, task trace, installed
  version, and watchdog relaunch are the authoritative success indicators; this is an observability
  limitation, not an install failure.
- Inno Setup continues to warn that an administrative installer writes per-user registry values.
  This is existing installer behavior and did not affect installation or the unattended update.
