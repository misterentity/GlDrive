## Changes and root causes

**1. Working ioFTPD compatibility expired during healthy use.** sitea uses standard PASV because its data endpoint does not initiate the glftpd-style CPSV TLS handshake. v3.19.8 discarded that compatibility decision six hours after detection even while listings were succeeding. Re-probes at 03:26 and 09:27 local failed listings and quarantined a login; the latter also failed a release-monitor poll.

Successful standard directory listings now renew an existing fallback only after a fresh, positive completion reply is validated. Empty successful listings count; failed, cancelled or incomplete listings do not. Six hours without successful standard listing still permits a retry. Ordinary PASV sites do not acquire a fallback, older completion evidence cannot shorten a newer renewal, and expiry cannot remove a concurrent renewal. Proven glftpd safeguards remain intact.

**2. Live settings edits invalidated search enumeration.** Applying the notification correction below exposed two production `Collection was modified` exceptions in `FtpSearchService.RefreshIndex`. Automation reconciliation cleared shared lists even when the edited setting was unrelated, while crawls enumerated `SearchPaths` across awaited FTP work.

Automation now uses the shared configuration reconciler: unchanged collections remain intact and changed collections are replaced. Index and live-search operations capture method, paths and depth before awaiting, so a mid-crawl edit affects the next operation without invalidating or changing the current crawl. The reproducer covered both unrelated notification edits and intentional search edits.

**3. sitea's watcher pointed at an empty directory.** Pooled read-only listings established that `/recent` had no entries while `/` held the category folders. At **17:23:19Z**, the watch path was changed to `/`, with 11 archive/Today/Yesterday aliases excluded. A private rollback snapshot, expected revision and old-value tests guarded the patch. The preview required no remount or IRC restart.

Effective before/after comparison confirmed exactly the two intended notification fields changed. Three default blocks were omitted on disk by existing downgrade serialization without changing their effective values. Numbered configuration history is disabled; the manual snapshot and patch evidence are retained. The watcher **seeded seven categories at 17:26:06.281Z**, and a fresh complete Problems snapshot at **17:28:21.632Z** reported no sitea problems.

**4. A CI test observer conflicted with queue publication.** CI at the preceding application commit failed because `RaceAdmissionTests.ReadQueue()` opened the queue file without coordinating with its publisher. The test-only fix uses the production path lock and a shared read. A deterministic barrier test proves the observer waits for an in-flight publication and then reads the committed generation. No production queue behavior was changed.
