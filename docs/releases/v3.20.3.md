# GL Drive v3.20.3

Races now stay queued when reconnecting an exhausted transfer pool fails. Previously,
the first job after a connection timeout could continue discovery without a usable
source, then disappear as a failed race. The existing admission timer now defers that
job, preserves its durable request and source hints, and retries after the hold.
Existing sessions remain reusable, and account-level login restrictions still apply.

Updater task helpers now drain standard output and standard error concurrently and
enforce one deadline across output capture and process exit. Previously, synchronous
output reads could block before the timeout was reached. Timed-out helpers are stopped;
task registration remains best-effort so it cannot prevent an otherwise successful
update from relaunching. Additional installation-stage logging distinguishes recovery
receipt work from task registration.

Regression coverage exercises failed reconnect deferral and persistence, retry timing,
heavy subprocess output, nonzero exit status, and termination of a hung registration
helper. The deployment report records full regression, native smoke, release integrity
and production health results.
