The WRN count fell from day to day. Census by reason: SYN remount 21–23/day

Ruled out:
- **superbnc pool-empty episodes** at 10-24 01:06 and 10-25 02:39. New
  connections failed with `GetReply ... The operation has timed out` during
  the handshake, meaning the BNC was unresponsive. ConnectionMonitor
  reconnected within about 6 minutes, and the affected races
  (Fading.Grandeur, The.Block.AU) completed. The "ghost sessions are plausible"
  wording in those lines came from the pre-v3.11.30 build; current source no
  longer emits it.
- **`GnuTLS: recv did not drain within 20s — leaking session`** (2, both in
  the 10-25 stall). This is the designed safe path; freeing a session under a
  live native read is the AVE lineage.
- **Triple `AgentRunner next run in`** at about 02:27. Power-resume and
  time-change events re-arm the timer. `_runGate` admits one run, and there
  was exactly one STARTED per day.
- **`*.*.*.*` inside release names in `[FTP]` lines.** FluentFTP's IP masking
  matches `2026.10.26.1080`. It is a logging artifact only.
- **~1,030 `550` replies to `CWD /incoming/<section>/<release>`.** This is the
  bounded per-race source-locate probe, about 20 per race, by design.

## Deployment

- No races were active or queued. The update was triggered through the
  control API (`app.update_check` → `app.update_install`) and went through the
  signature-verified updater.
- 20:24:54: new process on **3.11.32.0**. The heartbeat, csproj and GitHub
  latest release all agree. The log shows "Update to v3.11.32 confirmed
  installed".
- Startup: zephyr and superbnc connected with CPSV, both IRC networks
  connected, the extractor watch restarted, and announces were flowing. SYN
  failed to mount as before (external).
- First 10.6 minutes: 0 ERR / 0 FTL. The only WRNs were 4 SYN remounts.
- **Fix confirmed live.** The dashboard was opened at 20:35:57. That produced
  exactly 2 `SITE DISKFREE` sends, one per connected server, each followed by
  `SITE DISKFREE unsupported (500 ...) — not asking again on this mount`.
  There were 0 further sends through 20:39:33 (7 poll cycles). The old build
  would have sent about 14. By 21:08 the total since startup was still 2,
  against about 64 at the old rate over that dashboard-open time.
- **Races on 3.11.32.** No raceable announce arrived from 20:25 to 21:00.
  Every announce in that window was for a section no destination hosts.
  `#supers` was quiet for 37 minutes, which is within its normal daily maximum
  gap of 63–92 minutes. `#supers-spam`, on the same connection and decrypt
  path, delivered messages throughout. With the 21:00 burst,
  Phony.S01E03 1080p and 2160p both completed: 41 FXP transfers, 2 RETR 550s
  during the `/incoming` → `/recent` source relocation (followed in 0.24s),
  0 ERR / 0 FTL. Twelve more races queued behind `maxConcurrentRaces: 1`.

## Remaining risks

- **Drive free space still shows defaults** on servers without SITE DISKFREE.
  Neither production glftpd implements it, so this behaviour is unchanged,
  just quieter. A LIST-trailer `[Free: NNNNMB]` (superbnc prints one) could
  feed it later.
- **External, unchanged:** SYN's FTP host has been down since 2026-08-13.
  superbnc has periodic BNC stalls. PreDB has availability problems.
- **Not exercised by the native harness:** remote glftpd/BNC CPSV behaviour and
  a full server-to-server FXP race. Coverage for those comes from production
  monitoring only.
- Open items from earlier reviews still need Dave: the 30-minute race ceiling,
  Verbose logging since 10-16, the zephyr `-TV-` routing freeze, T:\ not
  mounted, and the #SYN-SPAM catch-all rule.
