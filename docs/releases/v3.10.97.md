# GlDrive v3.10.97 release record

## Findings and root causes

- The retained August 30 through September 1 production logs contained no `ERR` or `FTL`
  application records. The recurring operational warnings were an externally unavailable SYN FTP
  endpoint, a short host-network interruption that recovered, and transient FXP data-channel
  refusals already handled by bounded retry logic.
- After the network interruption, FTP `SITE INVITE` commands reported success while four
  invite-only IRC channels remained unjoined for roughly nine hours. When IRC rejected the primary
  nick and accepted the configured fallback, the recovery path still invited the stale primary.
  Each channel's standing retry also issued its own site-wide invite command, producing three
  near-simultaneous commands for one site every retry cycle.
- The screenshot smoke test exposed a separate security defect: Settings constructed its view
  model from the live Windows Credential Manager and rendered production API keys. It also read a
  production certificate count and used a user-specific default download path. Screenshot mode was
  read-only for config writes, but was not isolated from credential or local-state reads.
- The first release-publication attempt reported a missing GitHub `workflow` scope even though the
  scope was present. The CLI had the wrong authenticated account active. Switching to the existing
  repository-owner login resolved publication without changing credentials or rebuilding assets.

## Changes

- Resolve the `SITE INVITE` target from the nick actually accepted by IRC after a 433 collision,
  while preserving the configured invite nick during the normal primary-nick path.
- Coalesce concurrent per-channel invite retries through one single-flight gate. A later retry
  cycle remains eligible after the in-flight command completes.
- Disable all Credential Manager reads, writes, and deletes before screenshot config/view-model
  construction. Settings also has an explicit demo-only state that does not read credentials or
  trusted certificates, uses non-persistent notifications, and renders a neutral download path.
- Regenerate the affected Settings documentation images with empty API-key fields and demo-only
  state, add focused regression coverage, update the changelog, and bump the product to 3.10.97.

## Remaining risks

- SYN remains externally unreachable. GlDrive's bounded remount/backoff loop is operating as
  designed, but the endpoint or its network path requires separate remediation.
- Remote FXP endpoints can still refuse transient data connections. The observed failures
  recovered on retry and did not indicate an application defect.
- Live API credentials were visible in a pre-fix locally generated screenshot. Because historical
  documentation images may have been produced by the same code path, rotate the affected
  OMDB/TMDB/OpenRouter credentials and review Git history, release caches, and documentation mirrors
  for older copies. Current tracked images are sanitized; repository history was not rewritten.
- The active production reconnect did not encounter a nick collision, so the fallback-nick branch
  is validated by focused tests rather than a deliberately disruptive production collision.
- The scheduled task reports result `-1` because the applicator deliberately terminates its own
  process after signalling completion. The task trace, authenticated completion signal, installed
  version, and watchdog relaunch are the authoritative success indicators.
- Inno Setup continues to warn that an administrative installer writes per-user registry values.
  This is existing installer behavior and did not affect the unattended update.
