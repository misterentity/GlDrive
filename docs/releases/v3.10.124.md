# GlDrive v3.10.124

## Log review and root causes

Reviewed all retained daily application logs for September 16–18, including the three September 17 size rolls, through approximately 09:02 PT on September 18. Historical standalone crash dumps predate this review window (the newest is July 20).

| Log | Lines | Error | Fatal | Warning |
| --- | ---: | ---: | ---: | ---: |
| September 16 | 37,891 | 0 | 0 | 77 |
| September 17, all four files | 296,976 | 1 | 0 | 240 |
| September 18, through 09:02 | 37,911 | 0 | 0 | 34 |

The one Error was a download permanently failing at September 17 07:37:13 with `Pool exhausted: all connections discarded and new connections failed`. Its destination drive, T:, was absent. The manager listed the remote directory before checking its local destination; the network outage therefore consumed ordinary retries before the existing volume-parking handler could run. The fix checks destination availability before FTP access, preserving the queued item and retry budget with the existing five-minute-to-one-hour recheck schedule. Cancellation is checked first, and the existing handler still covers a drive disappearing later during a transfer.

The outage also caused DNS failures, unreachable LAN connections, IRC reconnects, notification poll failures, exhausted pools and failed spread scans. Version 3.10.123 already added transport-specific backoff and attribution. That installed version was confirmed by both the authenticated control API and current heartbeat. No additional reconnect storm was observed in the September 18 log. Through 09:02, there were 1,283 successful FXP files, 11 failed attempts, 62 completed races and no failed races.

Other warnings were remote 425 data-connection refusals, connection resets, release paths relocated by the source server (followed by existing recovery), repeated SYN mount failures, and absent T: download parking. No new application crash or native failure was identified in the reviewed daily logs. September 17's unclean-session warning follows the machine outage already investigated for v3.10.123; a running marker alone cannot establish an application crash.

## Remaining risks and rollback

- T: is still absent. Downloads targeting it cannot complete until the drive is restored or an intended replacement path is supplied. The previously failed item requires Retry; the fix does not silently revive all failed downloads.
- SYN's FTP endpoint remains unreachable. Two other configured servers are connected. Restoring SYN requires network/server repair or an updated endpoint.
- Remote 425 refusals, connection resets and source relocation remain possible; existing retry and relocation handling remain in place. Loopback smoke testing does not reproduce a remote BNC's CPSV behavior or constitute an extended live soak.
- Missing destination-section mappings can still make an auto-race infeasible. They are configuration choices, not changed automatically.
- No configuration schema or stored-data migration. Roll back using the v3.10.123 installer if needed; that version retains the destination-check ordering defect.
