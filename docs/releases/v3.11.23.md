# GL Drive v3.11.23 — cancellation and source-discovery recovery

A finished race could cancel a background connection borrow, put the source
pool into a false login-cap cooldown, and cause subsequent races to report
"Release not found on any server." Seven failures in two bursts in the current
3.11.22 logs exposed this chain.

## Changes

- Preserve cancellation when the account login gate returns without a permit,
  and release a permit if cancellation races its grant. An abandoned borrow
  cannot arm login-cap backoff, spend the ghost-kill budget, or open a replacement
  connection. Already-cancelled work leaves idle connections alone.
- Keep interrupted native health probes in deferred quarantine, then propagate
  the caller's cancellation.
- Report source absence only after a complete sweep of negative answers.
  Responsive destinations cannot establish absence on unavailable sources.
  Missing or disposed source pools count as unanswered candidate paths.
- Include actual answered/failed probe counts. Incomplete discovery uses the
  existing five-minute suppression instead of the hour-long absence rule; a
  later announce can retry after that suppression expires.

## Validation and limits

Regression coverage exercises real loopback FTP discovery, dropped control
connections, missing/disposed/cooling pools, cancellation around login permits,
and permit/bookkeeping recovery. Release validation includes all three test
suites, native FTPS/WinFsp and connection-sharing fixtures, WPF screenshot smoke,
GitHub CI, and verification of signed release assets and installed payloads.
Exact results and production observation are recorded in the deployment report.

SYN's remote FTP endpoint remains unavailable. These changes preserve genuine
login-limit backoff and native-session quarantine; they do not repair remote
availability, account permissions, or historical unreproduced Windows rendering
faults. Production monitoring is a bounded observation, not an extended transfer
soak.
