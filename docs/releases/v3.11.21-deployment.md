## Review and root causes

Reviewed all 15 retained rolling application logs, from **October 17 00:00:15.705
through October 19 10:08:09.766**, plus all 30 retained crash dumps. The snapshot
contained **485 warnings, zero errors/fatals**, 2,998 successful FXP completions
and 189 completed races. DEBUG/INFO failure paths were also inspected.

| Finding | Disposition |
| --- | --- |
| Search deadline callback ordering | Fixed. A listing could finish before cancellation reached the linked traversal token and falsely report complete empty results. The source deadline token is now checked directly. |
| Historical tray-tooltip dispatcher crash | Reproduced and fixed. The May 14 `UpdateToolTip failed.` stack still matched the current callback. Handle only that exact shell rejection and retain the latest text for the library's taskbar recreation. Explorer restarting is a possible trigger, not a proven cause. |
| 396 IRC admission warnings | 297 join refusals plus 99 missing invitations after accepted SITE INVITE. Remote admission incident recovered: all three affected channels were joined at the baseline health check. |
| 54 SYN remount warnings + 3 new-mount failures | Remote FTP connection timeouts before authentication. Existing bounded retries remain; endpoint still unavailable. |
| 4 IRC transport failures + 1 monitor timeout | Transient remote transport failures; connections recovered. |
| 20 FXP warning records | Ten missing-source attempts logged at detail and summary levels. Five same-site relocation events all completed. One source disappeared; its job deferred and ended without work when the remaining peers were download-only. Logs cannot prove full delivery of vanished source files. |
| 1 spread inactivity warning | Repeated successful zero-file listings supplied no content; the bounded inactivity policy ended the attempt. |
| 2,998 relay destination `426 Data Connection: Success.` replies | Existing glftpd compatibility behavior; source completion and expected byte counts are checked. Short-transfer and cancellation regressions pass. |
| 183 incomplete SFV reads and 93 gate timeouts | Bounded pool contention/cancellation and one login-cap refusal. Transfers rescheduled; no new deadlock or parser defect established. |

Historical crash groups: nine ProgressBar namescope failures, one read-only binding
failure, three notification rejections and two invalid folder-picker drives already
have fixes/coverage. The tooltip failure above was still actionable. Thirteen July
render-thread failures and one July WPF deferred-resource failure have no current
recurrence; their original internal causes were not reproduced or proven fixed.

## Changes

- Check the search deadline source token after listing completion. The timeout
  regression now forces the relevant callback order deterministically.
- Route initial and server-state tooltip changes through a narrow recovery
  boundary. Preserve both WPF state and the native tray model's requested tooltip;
  unrelated exceptions still propagate.
- Update deployment documentation for signed manifests, SYSTEM-task handoff,
  rollback/watchdog behavior, cleanup, pinned WinFsp and external release worktrees.
- Bump the application version from 3.11.20 to 3.11.21.

## Evidence and remaining risks

Local evidence is under `.release-tools/review-20261019/`: per-file log hashes/counts
in `log-audit.json`, detailed classifications in `log-audit.md`, TRX results,
build/test logs, `native/summary.json`, native protocol assertions, UI image manifest,
and authenticated health snapshots. These ignored artifacts stay local; no private
configuration or credentials are included in the committed report.

- SYN's FTP endpoint remains unavailable. Remote account/channel admission,
  route compatibility and disappearing source files are outside this code fix.
- Verbose logging remains the configured user setting; it increases protocol-log
  volume and can shorten effective retention. No configuration was changed to
  suppress failures.
- Historical July WPF/render faults remain unreproduced; a passing render smoke
  check does not establish that their original cause has been eliminated.
- Inno Setup completed with its existing nonfatal administrator-install/HKCU
  warning. Per-user autostart registration under a different elevated account
  remains an installer caveat; this deployment uses the verified in-app updater.
- Privileged update cleanup deleted 1,340 backup files but retained **294 old MCP
  files** (about 247 MiB, seven generations). Thirteen older MCP processes belong
  to still-running Claude clients from October 14–16; readable memory maps confirm
  210 files across five generations are still mapped. Read-only Restart Manager
  queries identify live owners of the remaining two generations, whose processes
  deny map-query access. These are old runtime backups, not mismatches in the 1,339
  currently installed files. Restarting those clients permits a later cleanup;
  active sessions were not terminated during this deployment.
- Fixture checks do not replace an extended real-server soak or prove a complete
  remote glftpd FXP workflow. Production observation is finite.
- Automatic approval review rejected recursive deletion of the generated fixture
  `C:\Users\davem\AppData\Local\Temp\gldrive-ftps-check-08vb8jj4`
  as “blocked by policy.” Its
  synthetic data remains; its process/listener and temporary mount are stopped.
  Sharing fixture evidence is retained as designed.
- Automatic approval review also rejected deleting the temporary signing-key copy
  as “blocked by policy.” It remains at
  `C:\Users\davem\codex-worktrees\gldrive-release-20261019\installer\keys\checksum-private.pem`.
  Inheritance was removed and its ACL verified to allow only `WORKSTATION\davem`
  and SYSTEM. It is gitignored, was not committed or uploaded, and requires manual
