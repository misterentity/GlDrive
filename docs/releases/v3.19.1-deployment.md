## Findings and corrections

| Finding | Root cause and evidence | Resolution |
|---|---|---|
| FXP login-hold warning burst | **370 transfer-error warnings in about 26 seconds**, all local `FtpLoginHeldException` admissions before transfer protocol began. A GnuTLS connection reset triggered a legitimate health-supervisor hold, but the scheduler never armed its existing endpoint retry deadline. | Park each held endpoint until its own `RetryAtUtc`; use a finite fallback for unavailable/expired deadlines. Keep a healthy borrowed peer reusable, leave alternate routes eligible, and do not consume file retry budgets for pre-transfer holds. Ignore expired entries when selecting the next backoff wake-up. The existing three-minute idle bound still applies. |
| AI saves falsely failed and later runs became blocked | **Seven partial failures in the initial audit**, increasing to **eight consecutive failures before deployment**: the first reports said settings were not persisted, then the pending-commit conflict blocked later runs. The commit journal hashed typed JSON; the actual writer omitted default compatibility blocks and preserved hook formatting, so its successfully saved bytes differed. | Journal and writer now share `ConfigManager.PrepareSerializedSettings`, including library first-enable normalization. Exact before/after verification remains. Legacy pending evidence reconciles only when both the original typed-candidate hash and the entire normalized saved document prove the intended state. |
| Recovery bookkeeping rejected a legacy installation subtree | `C:\Program Files\GlDrive\win-x64` was owned/writable by the interactive user, outside the protected installation trust boundary. Its rejection was correct. Inspection found three legacy directory trees containing **zero files**. | At 17:05:32 UTC, archived only the verified empty `win-x64`, `v1.8.7` and `GlDrive.exe.WebView2` trees to local review evidence. No payload files were removed, no ACL was broadened, and the trust guard was not weakened. The subsequent update created a complete, trusted recovery receipt, verified below. |
| Remaining runtime directory permissions blocked the same recovery guard | After the empty-tree repair, a strict scan found five unprotected paths in the runtime tree: three directories, WebView2Loader.dll and one prior `.old` file. The initial scan covered 1,341 files and 116 directories. | A scoped runtime ownership/inherited-permission repair succeeded at **17:13:32 UTC**, with unchanged file hashes. A fresh strict scan at **17:22:36 UTC** confirmed all **1,341 files and 116 directories protected**, zero unprotected paths and no recovery-read error (`installed-permissions-repaired.json`). The original failing scan is preserved separately. |
| Previous release shipped despite failed CI | [v3.19.0 CI run 40822888896](https://github.com/misterentity/GlDrive/actions/runs/40822888896) failed one test: fixture cleanup deleted its directory while `AlertRouter.Dispose()`'s final asynchronous history write was still open. The release script did not enforce the documented CI wait. | Test awaits existing `DisposeAsync()` and verifies persisted history/no temporary file before teardown. Release now requires clean source at pushed `origin/master`, completed successful CI for that exact SHA, and tracked build inputs; approval is rechecked before publication. |
| Native harness could silently stop compiling | `tools/ReleaseCheck` was outside CI/release compilation; the v3.18.1 report already identified the gap. | CI and the standard release script compile the harness, and CI runs for `tools/**` changes. Real native execution remains a separate local release gate. |

The CI input check reuses the publish-provenance inventory to reject ignored SDK source and root MSBuild inputs that `git status` would miss. Generated `bin`/`obj` and WPF temporary outputs, the ignored signing key and pinned installer dependency remain permitted. A disposable git fixture covers both rejection and permitted cases.

The FXP burst recovered before deployment: the main connection reconnected at 06:53:06.103 local, FXP completed again at 06:53:06.851, and the first affected race completed at 06:59:57.040. By 10:03, v3.19.0 had completed **24 races / 531 FXP files** and six index builds. This recovery does not remove the scheduler defect; v3.19.1 prevents the repeated local admission attempts on future holds.

## Remaining risks and limits

- **SYN FTP remains an external outage.** Its IRC connection can remain healthy while the FTP host is unreachable. No server connectivity or trust setting was changed to mask it.
- **Twelve standing Problems findings are classified, not suppressed:** six warnings come from enabled common-example announce rules targeting two unconfigured channels per server; one warns that zephyr's `/TV-1080` destination is outside configured search roots; one is the SYN FTP outage; four are informational historical proposals rejected by the intentional zephyr routing freeze. The six configured channels are joined. Removing example rules or changing routing/frozen policy would require the intended configuration, so none was guessed during this release. Details are in `problems-review.md`.
- The superbnc→zephyr direct CPSV/PASV route still falls back to Relay. The observed re-probe was beyond the existing six-hour cache TTL and is not evidence that route-memory persistence failed. Native/socket faults can still occur externally; the new hold handling prevents a resulting local retry burst.
- Third-party PreDB timeouts/HTTP failures and remote release relocation/reset events remain possible. Retained historical relocations recovered, and prior remount/pathless-source regressions did not recur after their documented fixes.
- The empty-tree and runtime-permission repairs preserved payload bytes and trust enforcement. The old single-file backup was incomplete; the new update now has a verified complete 3.19.0→3.19.1 receipt with 24-hour retention. An actual rollback was not forced in production.
- Inno Setup still warns that `PrivilegesRequired=admin` is combined with per-user HKCU entries. Package creation succeeded; a different-account interactive installer may apply user-scoped settings to the elevated account. This release used the signed in-app SYSTEM update route, so that installer behavior was not exercised.
- Synthetic FTPS/WinFsp/CPSV tests and a bounded production observation are not a sustained remote BNC soak. WPF screenshot smoke confirms rendering, not every interactive recovery/export/rollback path.
