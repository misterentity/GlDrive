## One extraction engine for downloads

- Download auto-extract now runs on the same extraction engine as the Extractor window (`ArchiveUnpacker.ExtractDirectoryAsync`). Space reservation, disk-full parking, reparse-point checks and atomic writes are unchanged.
- Old-style scene sets (`.rar` + `.r00` …) are opened with an explicit volume list, and a set SharpCompress cannot read falls back to an installed UnRAR/7-Zip, reserving the archive's own size first. Without an external tool the download still fails as before.
- External UnRAR/7-Zip output no longer lets executable files through to the output folder, for the Extractor window too.
- Removed the unused torrent "download and keep" path from `TorrentStreamService` (~265 lines); queued torrents have run through `TorrentDownloadSource` since v3.10.
