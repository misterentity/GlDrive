# GL Drive v3.20.18

This release repairs failure recovery and source discovery issues found during the
November 10 log review.

- Ordinary direct FXP modes now assign opposite data-channel TLS roles: the TCP
  active endpoint uses SSCN ON (TLS client), and the passive endpoint uses SSCN OFF
  (TLS server). Previously both were set to ON, causing negotiation failures on
  compliant peers. Each transfer explicitly resets pooled session roles and requires
  positive SSCN confirmation before starting direct data commands. Closing or
  unexpected replies cannot trigger relay fallback on the same sessions; data
  protection is never downgraded.
- Completed direct transfers and clean duplicates restore the active session to
  TLS server mode for later local downloads. Failed or uncertain cleanup discards
  that session without retrying an already delivered file.
- A disconnected standard FTP listing can trigger a null dereference in the pinned
  FTP library's internal retry. GL Drive now reports the transport failure with the
  original exception attached. Spread scans discard every unsafe post-borrow failure,
  preserving clean protocol rejections and the existing login/quarantine protections.
- Source discovery and relocation now probe the first matching enabled mapping's
  explicit dated path. The path remains advisory until its existence is confirmed.
  `{MMDD}` and legacy date folders use the invariant Gregorian calendar in UTC.
- Metadata filtering avoids requests for non-video releases and filters with no
  active thresholds. Search and detail requests share a one-minute provider outage
  retry delay, while healthy fallback, changed API keys and caller cancellation
  retain their intended behavior.
- Native smoke now exercises the PWD keepalive used since v3.20.17: one stale
  session must recover without an outage, while repeated failures must delay the
  recovery event until a positive reply. Real GnuTLS listing disconnects also
  verify connection discard, fresh-login recovery and intact payloads.

The review also found external failures that this release cannot repair: a remote
FTP site disconnected after a generic `530 Goodbye` reply and later connection
timeouts, remote directory/cleanup permissions and disk limits, unavailable torrent
metadata, and DNS failure at the free IMDb provider. Credential guards, remote
policies and queued work are preserved. Production verification and any remaining
failures are recorded separately in the deployment report.

Ordinary direct FXP now requires acknowledged SSCN role commands. Peers that do
not support them can refuse those routes; there is no fallback to plaintext.
