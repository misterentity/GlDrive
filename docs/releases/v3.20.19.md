# GL Drive v3.20.19

Downloads now refresh an obsolete source inventory promptly when FTP delivers
more bytes than the planned file size. Previously, every lane could repeatedly
download the same obsolete size and consume fresh logins before the download
manager refreshed the listing.

The affected attempt stops, quarantines its FTP connection, drains peer readers,
and clears unconfirmed staging ranges. A fresh listing must confirm that the
same exact remote path grew before the download enters the existing persistent
wait-for-completion state without consuming its failure retry budget. A changed
sibling, missing path, unchanged size or unavailable listing does not establish
growth; ordinary bounded failure handling remains in force. Cancellation and
pause retain priority, and no unconfirmed file is published.

Local regression and native FTPS fixtures cover stale-size rejection, fresh-size
recovery, persistent waiting, peer-reader lifetime and cancellation. The release
deployment report records final test counts, artifact identity and production
observations.
