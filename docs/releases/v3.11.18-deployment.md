## Changes

- Dashboard disposal cancels and drains its owned polling work and blocks late subscriptions/timer restarts. Notification arrivals update affected rows while preserving selection; a 100-arrival burst at the 5,000-row limit produces 200 collection changes. Wishlist imports deduplicate and save one ordered batch, retaining the prior live state if saving fails.
- Settings and automation share supported download limits: 1–5 concurrent downloads and 1–32 HTTP lanes per network. Invalid API values fail before persistence. Blacklist, extraction-abandonment, and network-usage stores reuse secure atomic writes; tests use explicit isolated queue paths. Shared artifact-name predicates preserve the consumers' different classification rules.
- Pure parsing and policy logic moved into dependency-free `GlDrive.Core`, retaining public type compatibility and adding Linux CI. The Core test output measured 4.44 MiB against the previous 225.71 MiB Windows test output; this is an output-footprint comparison, not a startup, memory, or throughput benchmark. Two unused Configuration package references and nine resolved dependencies were removed. New health events omit the unmeasured `errors5xx` field; historical values remain readable.
- Render evidence uses unique owned directories and verified completion manifests. The release pipeline performs one locked test restore/build, runs all three suites without rebuilding, and separately restores the self-contained publish graph. Packaging reuse checks commit, source inputs, SDK, build properties, and every payload hash; UTF-8 filenames and invocation from another directory are covered.
