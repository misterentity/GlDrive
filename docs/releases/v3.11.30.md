# GL Drive v3.11.30

Production log review found two TLS disposal drain timeouts and ten transfer
borrow timeouts whose diagnostics also blamed a successfully borrowed peer.

- Native TLS disposal now defers cleanup until outstanding I/O releases its
  lock. A read that outlasts the bounded disposal wait no longer permanently
  strands its session and credentials after it finishes. Disposal has one
  owner, and new or queued I/O is rejected once disposal starts.
- Transfer timeout diagnostics exclude a peer connection already acquired by
  that transfer and use the account gate's effective capacity. Idle or empty
  pool counters no longer assert unobserved login faults or recommend killing
  remote sessions without evidence.

Validation: Release build with zero warnings/errors, 2,694 regression tests,
84 focused TLS/diagnostic tests, 16 publish-manifest checks, and no known
vulnerable dependencies across the six solution projects. The new tests first
reproduced the disposal and capacity-diagnosis failures before the fixes.
The isolated native FTPS/WinFsp/CPSV smoke pass completed 198 assertions;
the UI smoke pass rendered and verified 64 screens against the application hash.

The native session remains allocated if an I/O call never returns; it must not
be freed under a live native call. Remote FTP outages, source relocations,
provider rate limits and service availability remain external dependencies.
