# GlDrive v3.10.111

This release improves file integrity, resource use, saved-state reliability, and shutdown behavior.

- Mounted-file reads now stage on disk. Partial writes preserve untouched bytes, large writes spill before allocation, open handles share file state, renames update buffered paths, and volume flush uploads dirty files. Failed close uploads retain recovery copies in `%AppData%\GlDrive\write-recovery` with destination metadata.
- Media transfers reject short reads and unsuccessful FTP completion replies. Interrupted connections are discarded, partial range requests do not wait for completion of an intentionally interrupted transfer, and concurrent cache downloads use separate staging files.
- The control API caps active requests at 16, expires stalled requests after 15 seconds, and drains handlers on shutdown. Media HTTP handlers are also bounded.
- AI configuration changes use a detached snapshot, reject concurrent settings edits, and retain recoverable audit evidence across save failures. Unreadable freeze settings block AI changes. AI actions that modify external stores require manual action in this release.
- Resume positions, freeze settings, and nuke cursors use atomic persistence and preserve unreadable files. Download shutdown keeps interrupted work queued, and spread resources remain valid until workers finish.
- Telemetry batches disk writes, bounds queued records, reports dropped records, and drains on shutdown. Directory caching handles expiry, small capacities, and duplicate listings correctly.
- Dashboard metrics reflect actual status, navigation tabs have accessibility names, and disposed views unsubscribe from release events.

Validation: 1,230 Release tests passed, no build warnings, and no known vulnerable NuGet dependencies reported by configured feeds. The local native integration harness passed GnuTLS/FluentFTP transfer checks, media completion handling, dirty rename and volume flush, plus WinFsp create/write/flush/read/rename/delete. WPF screenshot mode rendered 15 images; dashboard layout was inspected and config/trust-store hashes remained unchanged.

Remote glftpd/BNC CPSV behavior and a 24–48 hour soak remain external validation tasks. Recovery copies cover failed close uploads; they are not a crash-proof write journal. Failed uploads may partially replace a remote file, so retain the local recovery copy until restoration is verified.
