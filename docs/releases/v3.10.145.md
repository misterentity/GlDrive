# v3.10.145 — keep unavailable win rates out of automatic upload-role decisions

## Production finding

The October 5 deployment of v3.10.144 exposed an erroneous AI configuration
change persisted on October 4. Zephyr's `downloadOnly` flag had changed from
false to true. The running process continued using its older configuration,
but restart activated the saved change. Both reachable servers then prohibited
receiving files, and eight queued requests failed with the specific
no-eligible-destination/download-only diagnostic.

The audit entry records the AI's rationale as a zero-percent win rate and no
successful uploads. That conclusion was false: race telemetry did not report a
winner at all, and 202 of 206 reviewed outcomes recorded files present on zephyr
as a destination. `Winner = null` had been counted as a loss in race and section activity
digests. The upload-role validator accepted the boolean without establishing
that disabling uploads was justified.

## Changes

- Unknown winners no longer become losses or a zero-percent win rate. Race and
  section activity summaries distinguish known winner observations from
  unavailable data, including legacy rollups.
- Destination file-ownership observations provide separate evidence of useful
  work; they do not identify who uploaded each file or imply winning a race.
- Autonomous configuration runs cannot change `downloadOnly`. They use the
  existing `requires-manual-action` guard; dry-run suggestions and explicit
  manual review remain available. A model confidence score is insufficient to
  change upload eligibility.
- Includes v3.10.144's queue-admission, final race-count and torrent metadata
  lifecycle fixes. See its [release report](v3.10.144.md) for their root causes
  and original validation.

## Remaining risks

- SYN's FTP endpoint remains unreachable. T: remains unavailable because its
  SMB service refuses TCP 445. Restoring those external services remains outside
  the verified application fixes; downloads stay parked.
- The previous D: shortage resolved and its parked extraction completed.
  Two older incomplete archive sets still need their missing continuation data.
- Historical incorrect race summaries and unavailable winner observations are
  retained as evidence; new reporting does not invent missing historical data.
- Remote PreDB/torrent metadata availability is not guaranteed by these fixes.
  Queue capacity, the existing 24-hour expiry and relay timeout policy remain.
- Automatic updates retain their existing busy deferral policy. This deployment
  coordinated the standard signed updater at a safe boundary rather than waiting
  for the next periodic check.
- Native smoke uses a loopback FTPS fixture and real WinFsp; it does not replace
  an extended remote BNC soak. WPF rendering does not validate every interaction
  or external authenticated integration. Existing minor UI clipping remains.
- Inno Setup reports the existing administrator/HKCU warning. It does not affect
  the signed-ZIP production update. An interactive installation using another
  administrator's credentials may register optional autostart for that account
  instead of the initiating user; that alternate-account installer flow was not
  exercised in this deployment. See [Inno Setup's administrator-mode rules](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm).
