# GL Drive v3.20.7

A race whose source probe gets too few answers to prove anything is now retried
instead of dropped. When the release had no partial on any site, the race lifetime
policy returned nothing for a "Source probe inconclusive" or "Source scan never
succeeded" failure, so the request left the queue for good. The dead-race comment
assumed the next announce would re-run it, but each release is announced once.

On 2026-11-04 at 00:14 (v3.20.2), siteb's spread pool died while
Love.Island.Australia.Unseen.Uncut.S01E13 was probing: 7 of 24 probes answered.
That episode was never raced. E14, E15 and E16, queued behind it, waited for the
reconnect and completed within 10 minutes. v3.20.3 already closed that trigger
(a failed pool reinit now holds admission before discovery). This release closes
the remaining path, where the pool is usable at admission and fails during discovery.

The retry uses the existing queue deferral backoff (30 s doubling, 5 min cap).
`PersistedRace.SourceProbeRetries` persists across restarts and caps the retries at 6,
about 17 minutes of probing. A clean "release not found" verdict is still dropped as
before, and races with an owned partial keep their existing retain-until-checked path.

Tests: new `RacePartialPersistenceTests` cases cover both failure messages, the retry
cap, persistence of the counter, and the unchanged absent-release drop. Both guards
were mutation-verified: disabling the branch and an off-by-one on the cap each fail 2 tests.
