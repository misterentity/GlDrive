# GL Drive v3.12.0

The first release from the 2026-10-27 feature-gap review. Every Phase A item was a defect confirmed in the code. Codex implemented them and Claude reviewed them. The full suite passes: 3,066 tests (2,993 app, 53 core, 20 MCP), 0 failures.

## Security

- **No secrets in AI payloads.** Every request to OpenRouter now goes through one outbound redactor: the nightly agent, AI Setup, and any future caller. It works in two passes:
  - It masks secret-named config fields: the control-API token, FiSH channel keys, passwords and API keys.
  - It then scans the final request body for every live secret value (config, Credential Manager, FiSH key stores). If one survives, the request is refused.

  Before this release, the agent's config snapshot included the control-API token and the configured FiSH channel keys. **Regenerate the control-API token after updating:** Settings → MCP → *Regenerate control-API token*.
- The agent can no longer propose changes to secret fields, and its audit trail masks them.
- The README now states plainly that `appsettings.json` contains the control-API token and channel keys. Treat config backups as sensitive.

## Wishlist and downloads

- **IRC announces now feed the wishlist.** Before, they only started races, so a category excluded from `/recent` polling, such as TV, could never match a wishlist item. Exclusions still save directory listings, and IRC-fed matching shares deduplication with `/recent` detections. This adds no FTP traffic.
- **Relocated releases are recovered.** A grab triggered by an announce can start before the release has moved to its final folder (for example `/incoming` → `/recent`). A download whose remote folder disappears now re-resolves the release by name, using a bounded, spaced budget, before it fails.
- **"Default quality" is honoured.** It now applies to the Upcoming tab, the metadata dialog, import and MCP. Before, the Upcoming tab hard-coded 1080p.
- **Category paths understand TV and Movies.** A `TV` or `Movies` key in `categoryPaths` now matches the release's logical class, without adding a second `TV`/`Movies` folder (no more `…\movies\Movies\…`). Exact site-section keys still win.
- A notification monitor whose watch path has no categories now logs one warning per mount.

## Racing

- **Races finish what they start.** The 30-minute wall-clock ceiling is replaced:
  - A race stops when no payload bytes have moved for `hardTimeoutSeconds`, or at an absolute cap (`absoluteRaceTimeoutMinutes`, default 90).
  - A race stopped either way with files already landed is queued again as a resume, behind fresh races, up to 3 times.
  - If a partial can't be finished within `partialRaceDeadlineHours` (default 10, under glftpd's 12-hour incomplete auto-nuke), GlDrive SITE WIPEs only directories it created itself. Ownership is recorded per account.
  - A release with no positive evidence that it is incomplete is never wiped. That means an SFV-listed file must be missing or short, or a missing-part stub must be present.
- **Unknown race winners never count as losses.** The digest reports winner coverage. Priority and download-only proposals that depend on win rate are refused when fewer than 50% of races have an observed winner.
- **Starting a race reports what happened:** queued (with position), already active, duplicate, or suppressed (with the time left).

## Connections

- **Authentication circuit breaker.**
  - A rejected password (`530 Login incorrect` and similar) now holds new logins for that account across all pools, ghost kills and pollers. Login-limit and BNC-outage replies don't count as rejections.
  - The hold persists across restarts and raises one notification. It lifts when the stored password changes, on a manual retry, or after a successful slow probe (every 30 minutes).
  - Existing connections stay usable. An unreadable hold file is quarantined and ignored.
  - A burst of three consecutive connection faults now backs off for 5 s, instead of retrying with no delay.
- **Editing settings no longer remounts everything.**
  - Only connection, mount, TLS and pool-sizing changes (and credentials) remount a server.
  - Spread, cache, download, theme and other edits apply live.
  - Notification, search and IRC changes restart only their own component.
  - A reflection test fails if a new setting is added without a classification.

## UI

- The Overview cards and log tail refresh every 30 s again. Since v3.11.32 they had only refreshed after a successful SITE DISKFREE, which both servers refuse.
