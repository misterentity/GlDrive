## Changes and reproduction

A regression reproduced a settings conflict on an unchanged candidate with a rejected proposal and an unrelated unsaved runtime edit. The old code threw before recording the rejection. The revised transaction verifies the exact persisted baseline under its existing lock, recovers any prior journal, and can append the audit alone. It leaves the live edit and settings file intact and skips the service refresh. Applied changes and dry-run counter updates still require a settings commit. The conflict check compares typed JSON sections structurally and reports only top-level section names. The review cannot tell how many of the 19 historical runs had writeable proposals.

The first candidate suite also exposed a 50 ms regex timeout normalizing a parenthesized year in the library importer. The revised parser checks the six-character pattern directly, retaining the separators and existing source classification rules. An intermediate rebuild encountered a DLL still held by the preceding test host. Final validation uses a separate checkout.
