## Application fix

A CPSV operation could mark a connection as having an outstanding reply before checking a pre-cancelled token. The native reproduction sent no FTP command yet the caller discarded the connection. The candidate checks cancellation before setting the marker and preserves an existing marker when an earlier operation may still owe a reply. Quarantine diagnostics now record the operation, phase and cancellation state. A historical quarantine on the old version cannot be attributed retrospectively to this defect. See the [change notes](v3.20.26.md).

## Production observation and remaining risks

All 15 health samples passed from 15:50:22 through 16:00:55 UTC on November 20, a 10-minute 33-second observation of the installed Windows instance. Its process identity stayed stable. The retained-log check passed. All 207 application records were informational, including 70 FXP file completions and three completed races. The bounded audit found zero failed-operation signatures and zero matching Windows Application events. All samples reported the same six configuration warnings and four informational decisions seen before the release.

Destination write permissions and skiplists still govern which releases can transfer. A destination administrator must confirm intended permissions before the directory refusals can be resolved. Missing remote content, provider failures, DNS outages and data-channel timeouts can recur. The six announce-rule warnings need an operator-confirmed channel mapping. The historical no-activity stop and unattributed quarantine have insufficient evidence for a definitive cause.

Health verification covers this installation and observation window. Other installations and behavior during the application log retention gap remain unverified. Detailed local evidence is under `.release-tools/review-20261120/`.
