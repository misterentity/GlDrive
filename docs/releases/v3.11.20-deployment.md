## Changes

- **v3.11.19** (`d4487ff`): the search index and live search index a scene release directory
  without listing inside it (`FtpSearchService.IsReleaseDirectory`).
- **v3.11.20** (`9443ba0`): the release rule was too narrow. After the 3.11.19 deploy,
  superbnc still listed 632 release directories in 11 minutes: hyphen-only music names and
  game names with no digit. The new rule recognises 20,660 of 20,714 production release names
  and keeps all 20 real category folders as containers. See [v3.11.19](v3.11.19.md) and
  [v3.11.20](v3.11.20.md).

## Remaining risks

1. **Log level is Verbose.** An unattributed Settings save at 13:49:26 on 10-16, during the
   3.11.18 deployment, changed `logging.level` from Information (its value in every backup) to
   Verbose. The fix cut volume by about 83%, but Verbose still writes the full FTP and IRC
   protocol trace. The retention cap is 24 files of 10 MB, so history can still be shorter
   than the configured 3 days. It was left unchanged because it is a user setting.
   **Recommend switching back to Information in Settings.**
2. **superbnc `#supers`, `#supers-chat` and `#supers-spam` have been unjoined since 10:35 on
   10-16.** The site answers `Invited entity with nick entity0`, but its bot sends no IRC
   INVITE. The last successful invite was at 06:54, when the client was on the fallback nick
   `entity00`. This is on the site/bot side; the app's backoff and reconnect behave correctly.
   Worth checking the bot manually (for example `/whois SuperSport`).
3. SYN's FTP host has been down since 2026-08-13 (external).
4. 54 of 20,714 superbnc release directories are still listed during crawls (digit-only groups
   and two-token names). The cost is negligible.
5. Directories with release-style names are no longer searched inside. A pack whose own name
   is a scene name no longer has its nested releases indexed; the pack itself is.
6. One intermittent test (above). The suspected cause, not proven, is the ordering of
   cancellation callbacks between the deadline and traversal tokens. Re-run it if it fails in a
   future pipeline.
7. The release process depends on a worktree outside OneDrive. `CLAUDE.md`'s "Release" section
   does not mention this. Starting `powershell -File release.ps1` from Git Bash also fails with
   `Get-FileHash` not found (PowerShell 7 module path leak); start it from PowerShell.

Final disposition: **v3.11.20 published, installed and verified healthy in production.**
