# GL Drive v3.11.25

This release fixes FTP pool initialization accounting, duplicate-file source
selection, and updater exit status reporting.

- Reserve pool capacity while the first connection is opening. A concurrent
  borrow during a configuration remount can no longer erase that connection's
  count when its own wait is cancelled. Initialization failure, cancellation and
  disposal release their reservations and retain native connection safeguards.
  The mount also withholds its public pool until initialization is complete,
  preventing an external borrower from getting ahead of the initializer.
- Keep a remote duplicate refusal effective when a source file grows, while
  excluding the unverified destination copy from onward transfers and SFV
  inventory reads. A fresh full-size listing makes that copy eligible as a
  source; a stale listing cannot. Missing files still clear the duplicate hold.
- Report updater success as exit code 0 and rejected handoffs or failed installs
  as failure. Native forced termination remains in place because the updater's
  loaded runtime files may have been replaced during installation.

Validation and deployment evidence, observation limits, and remaining external
service failures are recorded in [the deployment report](https://github.com/misterentity/GlDrive/blob/master/docs/releases/v3.11.25-deployment.md).
The updater already installed on a machine performs its next update, so this
release's exit-status change takes effect when v3.11.25 later acts as updater.
