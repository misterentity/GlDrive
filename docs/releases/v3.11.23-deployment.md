# GL Drive v3.11.23 deployment and log review

Release date: October 20, 2026. Source commit:
`1075a95da7a43271f78b59da7a3150c5229892be`.

## Log review and root causes

The audit covered all 47 files in the application log directory: 16 rolling
application logs, 30 historical crash reports, and the heartbeat. The frozen
snapshot at **17:12:58 UTC** spans October 18 00:00:00.293 through October 20
10:12:56.061 local (UTC−07:00). It contains **237 warnings and zero Error/Fatal
records**. The current 3.11.22 run has **38 warnings and zero Error/Fatal records**.
Handled exceptions at Debug/Information were also examined. No GL Drive .NET
Runtime, Application Error, or Windows Error Reporting event occurred in the
current run through the event-log audit at 17:11:48 UTC.

Seven failed races exposed two connected defects:

1. Cancellation of a completed race's background borrow was converted into
   "account login cap reached." The login gate returns false for both timeout
   and cancellation, but the pool treated both as account pressure. Five such
   false backoffs occurred 14–298 ms after race completion; two episodes caused
   the seven failures. This could also consume the ghost-login recovery budget.
2. Source discovery treated a responsive peer's negative answers as proof of
   global absence. Every failed race had **7 clean negative probes and 16 failed
   source probes**, then received a **60-minute absence suppression**.

The pool now preserves caller cancellation before login-cap classification,
releases a permit when cancellation races its grant, avoids checking out idle
connections for already-cancelled work, and stops after deferred quarantine of
an interrupted health probe. Genuine gate timeouts still back off. Native
quarantine timing and teardown safeguards remain unchanged.

Discovery now requires a complete negative sweep for absence. Missing/disposed
pools count as unanswered candidates, diagnostic counts are accurate, and found
sources retain precedence. Inconclusive discovery uses the existing five-minute
suppression. It permits a later announcement to retry; it does not automatically
requeue historical failures.

Other current warnings were 18 SYN mount/remount failures, four log records for
two source RETR rejections, one successfully followed relocation, and one
optional metadata-provider failure. The relocated race completed at 01:03:01.980
local. The audit observed 1,240 successful FXP transfers and 29 completed races.
Fifty SFV cancellations were examined rather than counted as corrupted files.
One incomplete archive diagnostic was followed by the existing guard skipping
the unchanged, previously abandoned volume set.

The closing audit from 17:12:58 UTC to the new process start found **three
warnings and zero Error/Fatal records**. All three were PreDB requests exceeding
the configured 15-second timeout. Each recovered on its next attempt after
backoff, with 20 items returned. The interval also contained three handled
Debug-level FTP mount timeouts for the already unavailable site. The pending
download passed SFV verification, extraction completed at 17:22:48 UTC, and
the job completed at 17:22:49 UTC before installation. No new crash report or
relevant Windows crash event occurred; all 30 historical report hashes were
unchanged.

Historical reports include existing fixes for progress-bar namescopes, read-only
bindings, shell notifications/tooltips, and invalid folder-picker drives.
Thirteen July render-thread faults and one deferred-resource fault remain
unreproduced; this release does not claim to eliminate their original causes.

## Remaining risks and evidence

- SYN's remote FTP endpoint remains unavailable; its IRC connection is healthy.
- The optional keyless metadata host `api.imdbapi.dev` returns NXDOMAIN while the
  keyed OMDB host resolves. The provider's current web domain is parked and no
  supported replacement endpoint was established. Keyless metadata lookup remains
  unavailable; configured OMDB is attempted first. Changing metadata providers
  or acquiring a credential is separate work. Metadata filtering retains its
  existing fail-open behavior on lookup failure.
- Remotely moved/deleted files, account permissions, and incomplete archive
  contents cannot be repaired by these code changes.
- Historical WPF internal faults remain unproven. Native fixtures and a finite
  production observation do not replace an extended real-server transfer soak.
- Verbose protocol logging remains the user's setting and limits effective
  retention. No configuration was changed to hide warnings.
- The updater cleanup task deleted 1,338 backups but retained **336 `.old`
  files**, all under `mcp`, and returned **1**. That retained count is unchanged
  from before this deployment; 14 older MCP client processes remain running.
  Read-only mapped-file queries confirmed 252 of the retained files are mapped
  by ten live MCP processes. Four processes denied the query; the remaining
  84 files' ownership was not established. All 14 clients belong to existing
  Claude processes and were not terminated. Their next normal restart can
  release these runtimes. Current installed payload integrity and a newly
  launched MCP client both passed.
- The installer task reports **4294967295**, consistent with its existing
  `Program.Main` path killing its own process after the updater returns.
  Deployment success was established from the install log, new process/version,
  complete payload hashes and functional checks, not that task result.
- Inno Setup emitted its existing nonfatal warning about an administrative
  installer writing per-user HKCU settings. The per-user autostart behavior
  across different elevation identities was not tested in this release.
- Automatic approval review rejected recursive deletion of a generated
  temporary fixture as “blocked by policy.” Its process is stopped. Baseline
  and final synthetic fixture data were retained under
  `%TEMP%\gldrive-ftps-check-zs95x1ma` and
  `%TEMP%\gldrive-ftps-check-62fr13mu`; deletion was not retried.
- Automatic approval review also rejected deletion of the temporary signing-key
  copy as “blocked by policy.” It remains in the clean release worktree at
  `C:\Users\davem\codex-worktrees\gldrive-release-20261020\installer\keys\checksum-private.pem`.
  Its ACL allows only the owner and SYSTEM. The original key was unchanged;
  the temporary copy was not committed or published. Manual cleanup remains.
  The earlier `gldrive-release-20261019` worktree also still contains its
  previously documented temporary key copy; it was not modified by this work.
