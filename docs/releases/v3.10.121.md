# GlDrive v3.10.121

## Log review and root causes

Reviewed all retained daily application logs on September 16, 2026, through approximately 09:09 PT. The installed application was v3.10.120. Historical crash dumps predate this window (latest July 20), and there were no GlDrive Windows Application crash events 1000/1001/1026 in the preceding three days.

| Log date | Lines | Error | Fatal | Warning |
| --- | ---: | ---: | ---: | ---: |
| September 14 | 30,814 | 0 | 0 | 71 |
| September 15 | 36,101 | 0 | 0 | 78 |
| September 16, partial | 19,579 | 0 | 0 | 30 |

All 179 warnings were classified: 65 SYN remount timeouts, five initial SYN connection failures, 56 missing-T: download parks, 36 FXP failure headers/cause lines (22 STOR 425, eight RETR 425, four RETR 550 and two connection-reset lines), five notification LIST 425 failures, two followed source relocations, six incomplete-archive warnings, two prose-triggered race warnings already fixed by v3.10.118, one stale-heartbeat warning and one rejected duplicate launch. v3.10.120 already moved the whole-volume readiness gate onto all automatic extraction routes. Missing source volumes remain an external input problem.

Two additional defects were identified and fixed:

- **False unexpected-exit diagnosis after planned downtime.** At 03:30:06, Windows Update initiated a planned restart (System event 1074); GL Drive logged shutdown at 03:30:08. Startup at 06:45:05 treated the retained 11,699-second-old heartbeat as evidence of an unexpected session ending. Heartbeats survive clean exits, so age cannot establish a hang or crash. Startup now captures the previous running marker before replacing it, reports the evidence after Serilog initialization, and only offers an incomplete-shutdown notification when that marker was retained. Unknown/unreadable marker state is explicit. Neither heartbeat age nor the watchdog's historically named CRASH marker is presented as proof of a crash. Previously the marker diagnostics ran before logging initialization and could disappear.
- **Cancelled spread scans attempted fallback work.** During that same shutdown, cancellation of the main-pool scan fell through the general exception handler into the spread pool, producing a misleading login-cap failure and contention deferral. Both scan branches now propagate caller cancellation, and cancellation checks prevent fallback/result processing after a stop. Internal main-pool deadlines still permit fallback.

The duplicate process was a responsive, modal “already running” notice, not another active mount process. It had not spawned a watchdog or overwritten the primary's markers.

## Remaining risks and rollback

- SYN remains disconnected; a separate five-second TCP probe timed out. Restoring that endpoint requires network/server-side intervention.
- T: is absent from local filesystem drives and SMB mappings. The queued download is preserved; the intended mapping/replacement destination must be supplied before changing it.
- Remote 425 refusals, occasional connection resets, source relocations and incomplete RAR inputs cannot be repaired by client code alone. The existing recovery policies remain enabled.
- Older retained logs contain FiSH key fragments from versions before v3.10.119. Upgrading does not retract those logs; affected shared keys still require coordinated rotation. No unauthorized access was established.
- A retained running marker establishes an incomplete shutdown, not its cause. OS termination can leave it behind. Marker read failures are reported as unknown; heartbeat data remains best-effort.
- Native tests do not reproduce a remote BNC's CPSV stack. Short production observation does not replace a sustained soak.
- Automated desktop keyboard input could not focus the existing duplicate-instance notice. Rendered UI smoke passed; any additional installed UI checks are recorded separately below.
- Automatic approval review rejected temporary fixture-directory removal as “blocked by policy.” Its server was stopped; generated fixture data and the temporary certificate/key remain under the system temporary directory.
- Roll back with the v3.10.120 installer if needed. No persisted schema or credentials changed. That rollback restores the two defects described above.
