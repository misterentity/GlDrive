# GlDrive v3.11.3 — Arriving releases and FTP search

Downloads and site-to-site races now keep incomplete releases pending while the remaining files arrive. FTP search keeps busy or unavailable servers distinct from an empty result.

- Downloads recognize missing-volume placeholders and incomplete progress markers, refresh SFV manifests, and automatically rescan without consuming the transfer retry allowance. Valid local parts remain available for resume.
- Missing files are distinguished from checksum mismatches. Extraction and completion wait for the required files; queued rows show the waiting reason.
- Races inspect the files in existing release folders instead of assuming that the folder is complete. Waiting races return their concurrency slot and resume from a durable queue, allowing other releases to proceed.
- Active races resolve replacement connection pools after a server remount instead of retrying disposed pools.
- Cancelling or restarting a race preserves transferred parts for a later resume.
- Watched-folder extraction waits for managed downloads to finish their completion checks.
- Auto search returns cached matches without waiting for a busy connection, and falls back to live search when an old cache or SITE SEARCH has no usable matches. Queries match all words across scene-name punctuation.
- Search retains results from working servers, reports incomplete coverage, and prevents an older cancelled search from replacing the current results or status.
- Rejected standard FTP listings are reported as failures instead of being treated as empty directories by search, downloads, and race scans.

Includes the MCP settings panel released in v3.11.2.
