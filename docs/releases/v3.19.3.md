# GL Drive v3.19.3

This release corrects outage retry scheduling found while reviewing the v3.19.2 application logs. After Zephyr's FTP connection failed, deliberate login holds were repeatedly treated as fresh scan failures, producing 13,158 scan warnings and repeatedly starting races that could not transfer.

- Scans remember each site's login-admission deadline, defer empty pools, and continue using existing authenticated connections. A deliberate hold no longer triggers repeated empty-pool fallback or a warning flood. Actual failures after borrowing a connection remain visible.
- Active races waiting on a held, empty pool return their race slot. The queue retains their requests, delays unavailable starts and wakes for recovery. Pool initialization and reinitialization respect the same recorded holds.
- Regression coverage exercises admission denial, retry deadlines, usable connections, cancellation, durable queue retention and automatic recovery.

The application cannot restore an unavailable remote FTP endpoint. Zephyr and SYN were unavailable during the audit; their recorded health conditions and normal retry policy remain visible. See the [deployment report](https://github.com/misterentity/GlDrive/blob/master/docs/releases/v3.19.3-deployment.md) for validation, deployment evidence and remaining risks.
